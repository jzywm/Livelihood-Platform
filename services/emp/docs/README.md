# 用工服务（EMP · Employment）

> 微服务说明文档 · 依据《产品需求文档》（PRD v2.3）与《产品设计文档》（PDD v1.0（基线））编写
> 本文档用于明确该微服务的**功能与质量基线**，支持后续扩展开发。功能口径以 PDD §5.4 / §6.4.4 为准，需求口径以 PRD §5.4（C 组）与 §5.11（I 组）为准。

## 1. 服务概述

- **服务标识**：`emp`（用工服务）
- **服务定位**：用工关系、入职年龄核验与劳务信用双向互评，落实未成年人保护与劳资信用。
- **对应模块**：C2 防童工入职年龄核验（= 功能点 C-01）/ C-02 打卡记工时【§5.14】/ I2 劳务信用双向互评（I-02）；E3 招工求职【M2】。
- **里程碑**：M1 交付。
- **实现载体 / 技术栈**：Java 17 + Spring Boot 3.5（模块化单体）。
- **三端分布**：经营端（入职核验 / 打卡记工时 / 劳务互评）· 消费端（我的工时 / 一人一档联动）· 监管端（童工拦截与用工合规审计）。（发薪代付 / 工资流水 / 欠薪预警属 SETTLE 结算服务，本服务供考勤/用工校验数据。）
- **未成年人保护环节**：本服务承担「防童工入职年龄核验（C-01，<16 岁自动拦截并警示留痕）」；跨服务统一出口见 DASH（A-08 违规入场高频举报聚合）。
- **依赖服务 / 外部依赖**：ACC（实名信息复用）、SETTLE（发薪履约数据）、CRED（信用并入）。
- **核心状态机**：劳务信用互评（用工结束 / 发薪完成 → 双方互评 → 计入劳务信用分 → 并入 A-07 商户信用 / A-06 一人一档）。

## 2. 背景条件

- **需求背景（解决什么问题）**：未成年人进入娱乐场所（网吧最普遍）、劳资欠薪频发、从业人员信用缺失（PRD §2.1 问题 4）。EMP 落实「员工权益前置」：防童工是民生安全底线，劳务信用让守信者被看见、失信者被限制。
- **前置条件（本服务运行前提）**：
  - 拟入职人员已实名（复用 ACC 实名信息，不另建核验体系）；
  - 用工关系结束或发薪完成后方可互评。
- **平台红线约束（本服务需强落地）**：
  - 未成年人保护——年龄 <16 岁自动拦截并警示留痕（C-01）；
  - R-03 数据分级授权——履历仅本人 / 授权雇主可见；
  - R-15 防作弊——恶意差评走 D-03 申诉。
- **里程碑边界**：M1 交付防童工核验 + 劳务信用互评；招工求职（E3）为 M2 范围。

## 3. 主要功能

### 3.1 防童工入职年龄核验

入职登记时核验年龄，<16 岁自动拦截（3010）并警示留痕；年龄 ≥16 正常入职建档。实名未完成 3001 拦截，核验信息不符提示重新核验。

### 3.2 劳务信用双向互评

用工结束 / 发薪完成后双方互评（履约 / 态度 / 质量，可附证据），累积劳务信用分并联动全域信用。信用分构成：老板侧（发薪履约 40 + 纠纷 20 + 评价 20 + 资质 20）；工作者侧（出勤 40 + 纠纷 20 + 评价 20 + 实名 20），分别并入 A3 / A2。异常：恶意差评走 D-03 申诉；重复互评 3007 拦截。

## 4. 非功能性需求要求

### 4.1 全平台通用基线（所有服务共同遵守）

- **规模**：覆盖 ≈840 万；注册 ≥600 万、MAU ≥200 万、商户/机构 ≥10 万、DAU 峰值 ≈120 万。
- **性能**：核心读首屏 P95 ≤2s；核心写 P95 ≤3s；API P95 ≤500ms / P99 ≤1s。
- **可用性分级 SLO**：L1 ≥99.95% / L2 ≥99.9% / L3 ≥99.5%。
- **容灾**：同城双活 + 异地灾备，RPO ≤15min、RTO ≤30min（L1）。
- **安全**：等保三级 + OWASP ASVS L2；TLS 1.2+；密钥 KMS/HSM。
- **数据**：审计日志 ≥6 个月；存证只增不改。

### 4.2 本服务专项要求

- **可用性等级：L2（≥99.9%）**——用工 / 信用属 L2 覆盖对象；入职年龄核验强依赖 ACC 实名，实名不可用时按 R-02 暂停入职流程并明示。
- **红线不可降级**：年龄核验复用实名信息、不接受人工降级；<16 岁拦截为强制动作。
- **数据安全**：从业履历属敏感数据，加密存储、授权可见、脱敏输出；健康证等 L1 字段应用层 AES-256-GCM 加密。
- **防作弊**：互评防刷、恶意差评申诉闭环（R-15 / D-03）；失信者限制发布岗位 / 接单。
- **性能**：互评写入与信用分更新走异步化（MQ + 入账），避免同步阻塞发薪 / 互评主流程。
