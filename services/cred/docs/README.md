# 信用档案服务（CRED · Credit）

> 微服务说明文档 · 依据《产品需求文档》（PRD v2.0）与《产品设计文档》（PDD v1.12）编写
> 本文档用于明确该微服务的**功能与质量基线**，支持后续扩展开发。功能口径以 PDD §5.3 / §6.4.3 为准，需求口径以 PRD §5.2（A 组）为准。

## 1. 服务概述

- **服务标识**：`cred`（信用档案服务）
- **服务定位**：商户 / 人员 / 供应商**信用档案与信用分中枢**，含价格公示基础版与未成年人禁入承诺标注。
- **对应模块**：A1 一店一档 / A2 一人一档 / A3 信用分（A-01~A-08）；A-09 未成年人交易拦截（禁购标记，下单校验在 TRADE）。
- **里程碑**：M1 交付。
- **实现载体 / 技术栈**：Java 17 + Spring Boot 3.5（模块化单体）。
- **三端分布**：消费端（查档案 / 信用 / 价格）· 经营端（维护档案 / 价目表 / 承诺）· 监管端（全量档案核验 / 信用总览）。
- **未成年人保护环节**：本服务承担「未成年人禁入承诺标注（A-05）+ 未成年交易拦截标记（A-09）」；跨服务统一出口见 DASH（A-08 违规入场高频举报聚合）。
- **依赖服务 / 外部依赖**：ACC（实名）、TICKET（投诉归集）、TRACE（放心供应商联动）、AICORE（证照 OCR 预审）、OSS（证照存储）。
- **核心状态机**：价格公示（草稿 → 已公示 ⇄ 争议中）。

## 2. 背景条件

- **需求背景（解决什么问题）**：消费信任缺失（资质造假、图文不符、缺斤少两）与商户合规成本高（证照临期不自知、被职业差评讹诈）（PRD §2.1 问题 1/3）。「一店一档 / 一人一档」把好店好人的信用可视化，是平台信任底座。
- **前置条件（本服务运行前提）**：
  - 商户已实名（对公 / 法人）并持有营业执照 / 许可证；实名仅微信 / 支付宝回传（R-02）；
  - 从业人员已实名并持有健康证 / 技能证。
- **平台红线约束（本服务需强落地）**：
  - R-03 数据分级授权——档案脱敏公示，不泄露 L1/L2 敏感数据；
  - R-07 价格不因画像差异化——价目表仅展示、平台不代定价、同品同价不杀熟；
  - 未成年人保护——娱乐场所 / 网吧禁入承诺标注，举报数据流向 A4 预警。
- **里程碑边界**：M1 含价格公示基础版（商户自主维护价目表）与禁入承诺标注；维修报价单 / 后厨直播等完整版随 B2 在 P1/M2。

## 3. 主要功能

### 3.1 商户入驻与证照核验建档

商户注册 → 实名 → 上传证照 → 核验建档，支持 OCR 预审 + 人工核验，录入 ≤1 分钟；核验通过后档案可公开查询。

### 3.2 一店一档档案公开页

将证照 / 处罚 / 抽检 / 投诉率 / 好评率 / 信用分 / 价目表聚合于一页，脱敏公示、一屏可查。

### 3.3 商户档案维护与异常标记

商户自助维护档案，证照临期 / 年检 / 投诉激增自动标记并双向推送（同步监管端 A-08 预警）。

### 3.4 价格公示（基础版）

商户自主维护价目表，更新留痕、不代定价；价目与实收不符被投诉标记「价格争议」并关联 D2 投诉。

### 3.5 未成年人禁入承诺标注

为娱乐场所 / 网吧类档案标注「未成年人禁入承诺」，消费端脱敏可见，举报数据流向 A4 预警。

### 3.6 一人一档与从业履历核验

从业人员实名 → 健康证 / 技能证核验 → 一人一档，雇佣经历自动累积为履历（仅本人 / 授权雇主可见）。

### 3.7 信用分与红黑榜

商户 / 人员 / 供应商信用分计算与红黑榜脱敏公示，支撑分级监管（低分多查 / 高分少查）与放心供应商联动。

> **供应商信用分边界（2026-09-08 已决策）**：CRED 为信用分**唯一权威存储与公示**（`credit_score`/`redblack` 表）；供应商信用分的 T-05 公式（资质 30% + 履约 30% + 口碑 30% + 贡献 10%）由 TRACE 计算并经接口回写 CRED，其他服务（EMP/TRADE/TICKET/AICORE）仅上报评分事件、不直写信用分表。详见《微服务边界与职责基准》§3/§4-C02。

## 4. 非功能性需求要求

### 4.1 全平台通用基线（所有服务共同遵守）

- **规模**：覆盖 ≈840 万；注册 ≥600 万、MAU ≥200 万、商户/机构 ≥10 万、DAU 峰值 ≈120 万。
- **性能**：核心读首屏 P95 ≤2s；核心写 P95 ≤3s；API P95 ≤500ms / P99 ≤1s。
- **可用性分级 SLO**：L1 ≥99.95% / L2 ≥99.9% / L3 ≥99.5%。
- **容灾**：同城双活 + 异地灾备，RPO ≤15min、RTO ≤30min（L1）。
- **安全**：等保三级 + OWASP ASVS L2；TLS 1.2+；密钥 KMS/HSM。
- **数据**：审计日志 ≥6 个月；存证只增不改。

### 4.2 本服务专项要求

- **可用性等级：L2（≥99.9%）**——档案 / 信用为 L2 停机预算与容灾覆盖对象。
- **热读性能**：一店一档 / 红黑榜 / 网红店属热点档案，需多级缓存（本地 Caffeine + Redis），空值缓存防穿透、随机 TTL + 互斥重建防击穿、热点 key 分散 / 副本，降级出静态快照（PDD §8.1.3）。
- **数据脱敏**：档案公开页脱敏公示，L1/L2 敏感字段加密存储、脱敏输出，越权拦截（2002）/ 脱敏截断。
- **UX 基线**：商户入驻 / 上架录入 ≤1 分钟；消费端核心信息一屏看清、一步可查。
- **防作弊**：信用分防刷拦截（R-15）；扣分申诉复用 D-03 机制。
- **定时任务**：证照临期 / 年检每日扫描 → DASH / 通知双向推送；价目表更新即留痕。
