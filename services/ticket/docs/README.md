# 工单服务（TICKET · Ticket）

> 微服务说明文档 · 依据《产品需求文档》（PRD v2.0）与《产品设计文档》（PDD v1.1）编写
> 本文档用于明确该微服务的**功能与质量基线**，支持后续扩展开发。功能口径以 PDD §5.5 / §6.4.5 为准，需求口径以 PRD §5.5（D 组）与 §5.8（G 组）为准。

## 1. 服务概述

- **服务标识**：`ticket`（工单服务）
- **服务定位**：投诉 / 热线 / 申诉的**统一工单内核**，限时处理、升级市监、结果公示。
- **对应模块**：D2 投诉直达 / G1 群众热线诉求 / D3 恶意差评申诉（D-02 / G-01 / D-03）。
- **里程碑**：投诉 / 热线 M1、申诉 M2。
- **实现载体 / 技术栈**：Java 17 + Spring Boot 3.5（模块化单体）。
- **三端分布**：消费端（提交投诉 / 看进度）· 经营端（限时处理 / 申诉）· 监管端（工单升级 / 办结）。
- **依赖服务 / 外部依赖**：CRED（投诉计入商户信用）、MQ（超时升级 / 催办）、OSS（证据直传）。
- **核心状态机**：投诉直达（已提交 → 处理中 → 已解决 / 已升级 → 已办结公示，超时自动升级）。

## 2. 背景条件

- **需求背景（解决什么问题）**：维权不畅——投诉「打了没人管」、12345 不可对接、监管取证难、职业索赔讹诈（PRD §2.1 问题 2）。工单服务实现「投诉直达 + 结果公开（脱敏）」，并落地未成年人违规进入举报类别。
- **前置条件（本服务运行前提）**：
  - 用户已实名；证据可附（选填）；
  - 12345 不可接 → 自建工单 + 线下流转（P-04 双轨策略）。
- **平台红线约束（本服务需强落地）**：
  - R-04 证据存证——投诉证据时间戳 + 哈希存证、可出证；
  - R-03 数据分级授权——工单结果脱敏公示；
  - 未成年人保护——举报类别含「未成年人违规进入」，举报数据流向 A4 违规入场预警聚合。
- **里程碑边界**：投诉 / 热线 M1；恶意差评申诉与职业索赔识别 M2（AI 辅助 + 人工确认，C8）。

## 3. 主要功能

### 3.1 投诉直达（含「未成年人违规进入」举报）

消费者 ≤3 步提交投诉，全程进度可见、结果公示并计入商户信用。商家限时处理（48h），未解决自动升级市监、办结公示（脱敏）。

### 3.2 群众热线 / 诉求工单

群众提交诉求生成工单，平台分派部门限时办结（如 7 天）、进度可见、结果脱敏公示；12345 不可接走自建 + 线下流转；优秀建议 / 高频诉求转 G-02 建议论坛。

### 3.3 恶意差评申诉与职业索赔识别【M2】

商户凭平台留存证据申诉恶意差评，平台识别职业索赔后复核改判；识别结果仅辅助、人工确认后处置（C8）。

## 4. 非功能性需求要求

### 4.1 全平台通用基线（所有服务共同遵守）

- **规模**：覆盖 ≈840 万；注册 ≥600 万、MAU ≥200 万、商户/机构 ≥10 万、DAU 峰值 ≈120 万。
- **性能**：核心读首屏 P95 ≤2s；核心写 P95 ≤3s；API P95 ≤500ms / P99 ≤1s。
- **可用性分级 SLO**：L1 ≥99.95% / L2 ≥99.9% / L3 ≥99.5%。
- **容灾**：同城双活 + 异地灾备，RPO ≤15min、RTO ≤30min（L1）。
- **安全**：等保三级 + OWASP ASVS L2；TLS 1.2+；密钥 KMS/HSM。
- **数据**：审计日志 ≥6 个月；存证只增不改。

### 4.2 本服务专项要求

- **可用性等级：L1（≥99.95%）**——投诉直达属核心链路，是 L1 停机预算与容灾覆盖对象。
- **性能**：证据文件 OSS 直传（服务端签名，不占应用带宽）；图片异步审核；工单按月分表；超时升级 / 催办走定时 JOB + MQ。
- **UX 基线**：投诉提交 ≤3 步完成；进度全程可见（AC-M1.5）。
- **数据安全**：工单结果脱敏公示（R-03）；证据存证哈希链、可出证（R-04）。
- **可观测**：工单超时率作为业务级监控指标（PDD §8.5.3）。
