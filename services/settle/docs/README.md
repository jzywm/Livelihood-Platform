# 结算服务（SETTLE · Settlement）

> 微服务说明文档 · 依据《产品需求文档》（PRD v2.3）与《产品设计文档》（PDD v1.0（基线））编写
> 本文档用于明确该微服务的**功能与质量基线**，支持后续扩展开发。功能口径以 PDD §5.2 / §6.4.2 为准，需求口径以 PRD §5.11（I 组）为准。

## 1. 服务概述

- **服务标识**：`settle`（结算服务）
- **服务定位**：平台**所有资金结算的唯一执行层**，只走第三方持牌通道，平台不碰钱（记账与支付分离）。
- **对应模块**：I-03 工资保障代付 / I-04 商品购买结算分账 / I-05 零工劳务结算 / F-04 货运运费托管 / 平台结算账户（对接层）（= 规格书 I3/I4/I5/F4，C13 dash 编号口径）。
- **里程碑**：代付 M1、分账 / 零工 / 运费 M2；平台结算账户 M0。
- **实现载体 / 技术栈**：Java 17 + Spring Boot 3.5（模块化单体；M2 交易 / 结算按域**优先拆分独立部署**）。
- **三端分布**：经营端（代付发起 / 分账）· 消费端（工资流水）· 监管端（资金流水审计 / 欠薪预警）。
- **依赖服务 / 外部依赖**：ACC（实名 / 记账）、支付通道（微信商家转账 / 分账、支付宝 / 聚合）、JOB（对账 / 超时扫描）。
- **核心状态机**：工资代付（待校验 → 代付中 → 已到账 → 完成 / 预警 → 催办 → 已解决 / 仲裁）。

## 2. 背景条件

- **需求背景（解决什么问题）**：欠薪频发、预付卡跑路、货运运费拖欠、货款被卷（PRD §2.1 问题 4）。工资 / 货款 / 运费保障是民生安全底线，需「记账在平台、资金走持牌通道」的保障代付机制。
- **前置条件（本服务运行前提）**：
  - 老板已实名并绑定对公 / 法人付款账户；存在有效用工关系与考勤记录；
  - 分账产品资质已开通（M0 前置阻塞项，R-14）。
- **平台红线约束（本服务需强落地）**：
  - R-01 不沉淀资金、不做二清、不设资金池；记账与支付分离（AC-C1）；
  - R-04 证据存证——流水号 + 通道交易号 + 时间戳 + 哈希即证据链，支持出证。
- **里程碑边界**：代付 M1；商品分账 / 零工 / 运费 M2（设计先行）。

## 3. 主要功能

### 3.1 工资保障代付

老板经持牌通道向工作者代付工资，平台校验并记账留痕、不碰资金。携带幂等键提交；到账后更新老板发薪履约率并留痕存证。异常：通道失败切换备选通道 + 幂等重试；重复提交 3008 幂等返回；应发未发超时触发欠薪预警。

### 3.2 欠薪预警与证据出证

对「应发未发」自动预警，支持将流水 + 用工 / 考勤记录打包出证（evidenceId + hash + downloadUrl），供劳动仲裁 / 执法调取。

### 3.3 商品购买结算分账【M2】

交易订单验收通过后按比例分账（卖方货款 + 平台服务费，费率 0.5%~1% 公开），全程走持牌通道不沉淀（R-01）。

### 3.4 零工劳务结算【M2】

支持日结 / 周结 / 月结的零工灵活结算，复用 I-03 代付能力，到账计入劳务信用。

### 3.5 货运运费托管结算【M2】

货运运费经持牌通道托管，送达确认后放款入司机账户，杜绝拖欠；货损 / 迟到纠纷存证仲裁并计入双方信用。

## 4. 非功能性需求要求

### 4.1 全平台通用基线（所有服务共同遵守）

- **规模**：覆盖 ≈840 万；注册 ≥600 万、MAU ≥200 万、商户/机构 ≥10 万、DAU 峰值 ≈120 万。
- **性能**：核心读首屏 P95 ≤2s；核心写 P95 ≤3s；API P95 ≤500ms / P99 ≤1s。
- **可用性分级 SLO**：L1 ≥99.95% / L2 ≥99.9% / L3 ≥99.5%。
- **容灾**：同城双活 + 异地灾备，RPO ≤15min、RTO ≤30min（L1）。
- **安全**：等保三级 + OWASP ASVS L2；TLS 1.2+；密钥 KMS/HSM。
- **数据**：流水按月分表；审计日志 ≥6 个月；存证只增不改。

### 4.2 本服务专项要求

- **可用性等级：L1（≥99.95%）**——代付 / 分账为核心链路，是 L1 停机预算、容灾与灾备演练的覆盖对象。
- **资金一致性红线**：记账与支付分离；幂等键 + 超时状态机自动查单兜底；**无重复扣款 / 重复入账**（最终一致 + 对账补偿）；每日对账 JOB 补差。
- **通道韧性**：通道失败自动切换备选通道并幂等重试；全部通道不可用 → 暂停资金操作入口并公告（不碰钱红线不变）。
- **性能**：MQ 削峰 + 异步入账；流水按月分表（写放大治理）。
- **安全**：敏感操作（发薪 / 分账 / 申诉）强制 MFA；支付 / 工资密钥最高级隔离（微信 v3 API 证书，KMS 注入、禁写库、不入日志）。
- **可观测**：代付成功率 / 对账差异作为业务级监控指标（PDD §8.5.3）。
