## 1. 设计概述

### 1.1 设计目标与原则

1. **五词设计原则**（用户确认）:惠民 · 方便 · 安全 · 透明 · 直达 —— 每个模块/页面设计对照自检（§11 附录表）
2. **信任前置**:M1 只上溯源 + 信用（T2/T3 基础版）,交易撮合放 M2 —— 先攒数据与信任,再上交易（吸取美菜重资产教训）
3. **轻资产撮合**:不建仓储物流、不自营销售,只做信息撮合 + 担保交易 + 信用背书
4. **合规红线**（贯穿设计,不可妥协）:
   - 平台**不沉淀资金、不做二清**（资金全走第三方持牌通道）
   - 实名**仅微信/支付宝实名回传,不接受人工证件核验降级**
   - 农资/医美等强监管品类**只做信息撮合+溯源核验,不替代行政许可**
   - 大模型对话**脱敏前置、数据不出域、日志 ≤30 天脱敏留存**
5. **PC 端优先**:先 Web 应用,后续套壳 Windows 桌面;移动端后置
6. **存证能力**:工资/交易/投诉/溯源 时间戳 + 哈希存证,可出证供劳动仲裁/执法调取

## 2. 总体架构

### 2.1 架构风格与分层

- **B/S 前后端分离**:PC Web（浏览器）优先,后续套壳桌面（复用同一 Web 包）;三端共用后端 API
- **前端三端合一（2026-09-03 拍板,方案 F3）**:单一 React 应用（Monorepo 单仓）,消费端/经营端/监管端以「**角色 + 权限路由**」区分,内部按 feature 模块 + 公共组件库（ui/assistant/api-client/shared）组织;助手侧边栏为共享组件、三端复用;不拆多 App,避免三端重复建设与登录态割裂
- **单体起步、模块化拆分**:M1 规模（10~20 人团队）以**模块化单体**起步（一个应用 + 清晰模块边界）,预留按领域拆微服务的能力（M2 交易/结算独立部署）,避免过早微服务化
- **记账与支付分离**（合规核心）:平台账户系统只记账,资金流转全部由第三方持牌通道完成
- **异步化**:工单、预警、对账、通知走消息队列,削峰 + 可重试
- **双语言架构（Agent/AI 侧,2026-09-03 拍板）**:Java 模块化单体承载业务域（账户/信用/工单/溯源/交易/画像业务）;**ASSIST（J 助手）与 AICORE（模块 K AI 能力中心）为独立 Python 服务**,不经 Java 单体进程,经统一鉴权与内部接口对接（§6.2）;边界动机 = Agent/AI 链路是「高 IO 等待 + 外部 AI API + 异步任务」型负载,Python async 生态（FastAPI/LangChain/视觉-OCR 库）匹配度更高,且与 Java 业务域故障隔离（§8.2.4）

#### 前端模块划分（三端合一单 App,方案 F3）

> 单一 React 应用，三端以「角色 + 权限路由」区分；内部按「公共层 + 业务 feature 模块」组织，各 feature 独立开发、最后合并构建。

**Monorepo 结构（pnpm workspace）**：

| 目录 | 内容 | 复用性 |
|---|---|---|
| apps/web | 三端合一单应用（消费端/经营端/监管端按角色路由） | 唯一部署产物 |
| packages/ui | 公共组件库（AntD 封装：档案卡/信用分/表格/表单/看板/上传） | 全端复用 |
| packages/assistant | 助手侧边栏组件（J1~J6/J13,三端复用） | 三端复用 |
| packages/api-client | API 客户端 + TS 类型（由后端 OpenAPI 按模块生成） | 全端复用 |
| packages/shared | 常量/工具/鉴权/RBAC 路由守卫 | 全端复用 |

**业务 feature 模块（apps/web 内）**：档案查询（A1/A2/A3）· 投诉工单（D2/G1）· 溯源扫码（T3）· 账户钱包（I1）· 用工发薪（C2/I2/I3）· 选品交易（T1/T4,M2）· 监管看板（DASH/A4）· 助手（侧边栏组件挂载）。

### 4.1 核心实体清单

- **身份域**:用户（六方角色）、实名认证记录（微信/支付宝回传）、平台账户（记账簿）、钱包流水、收款绑定
- **档案域**:商户/门店、一店一档、**价目表（价格公示基础版:商户自主维护,更新留痕）**、**禁入承诺（未成年人禁入承诺标注）**、从业人员、一人一档、证照（上传+核验记录）、信用分（A3）、劳务信用（I2）、互评记录
- **用工域**:用工关系、考勤/工时、工资代付单、欠薪预警、证据包
- **工单域**:投诉工单（D2,**举报类别含「未成年人违规进入」**）、热线工单（G1）、限时处理、升级记录、公示记录
- **预警域（A4,设计先行）**:预警记录（资质临期/年检,监管端 + 商户端**双向推送**）、违规入场高频举报场所预警（举报聚合触发）
- **溯源域**:供应商、品类资质、商品（M2）、批次、溯源码、环节记录（①批号②检测③温控④终端）、断链标记
- **交易域（M2）**:购物车、B2C 订单、采购订单（T4）、担保托管单、验收记录、争议/仲裁、退款单、分账记录（服务费）
- **助手域**:会话（脱敏）、意图日志、跳转白名单、推荐候选快照、回答反馈
- **画像域（J7）**:画像档案（标签快照）、画像数据源授权记录（可撤回）、画像操作日志（查看/修改/关闭/删除审计）、行为事件（浏览/搜索/会话,脱敏）

### 4.4 存储策略

- MySQL 主库存业务实体;**流水类（钱包流水/代付/交易/分账）按月分表**
- Redis:会话（登录态）、助手会话上下文（30 分钟 TTL）、限流计数
- OSS:证照、检测报告、证据材料、溯源证明文件;存证只增不改
- 日志:应用日志 + 脱敏对话日志分离存储,对话日志 30 天自动清理

### 6.2 API 约定与错误码

**统一规范**：
- RESTful，URL 前缀 `/api/v1/`；统一响应 `{ code, message, data, traceId, timestamp }`，成功 `code=0`
- 鉴权：JWT（access 短时效 + refresh 轮换，Redis 吊销）+ RBAC（六方角色 + 扩展角色）；管理端二次鉴权 + 敏感操作（发薪/分账/申诉/执法/导出）MFA
- 分页：`{ list, total, page, pageSize }`；默认 `page=1, pageSize=20`（上限 100）
- 幂等：下单/代付/分账等资金接口强制幂等键（`Idempotency-Key` 头或业务幂等键），重复提交返回原结果
- 文档：OpenAPI 随代码生成；`agent-sdlc-standard` PR 门禁要求接口文档同步

**错误码约定（分段）**：

| 段 | 含义 | HTTP | 典型码 |
|---|---|---|---|
| 0 | 成功 | 200 | code=0 |
| 1xxx | 参数/校验 | 400 | 1001 参数缺失 · 1002 格式错误 · 1003 枚举/范围非法 |
| 2xxx | 鉴权/权限 | 401/403 | 2001 未登录/Token 失效 · 2002 无权限 · 2003 MFA 未通过 |
| 3xxx | 业务规则 | 422 | 3001 实名未完成 · 3002 实名不匹配 · 3003 证照核验不通过 · 3004 信用分不足 · 3005 商户未入驻 · 3006 对象不存在 · 3007 状态不允许该操作 · 3008 幂等键冲突 · 3009 资金对账不一致 · 3010 违规对象（未成年人） |
| 4xxx | 第三方/依赖 | 502 | 4001 实名接口失败 · 4002 支付通道失败/超时 · 4003 大模型/视觉 API 失败 · 4004 短信通道失败 |
| 5xxx | 系统 | 500 | 5000 内部错误 · 5001 数据库错误 · 5002 依赖超时/熔断 |

**双语言内部调用**（沿用 v0.8 口径）：Java 主站 ↔ Python ASSIST/AICORE 内部接口带统一鉴权头 + **traceId 透传**（§8.5）；Python 侧同步产出 OpenAPI（FastAPI 原生）；错误码/幂等/脱敏口径与主站一致；外部 AI 调用（DeepSeek/视觉云）一律由 Python 服务收敛，**前端不直连 Python 服务**（AI 入口经主站/网关鉴权后转发）。

### 8.1 性能设计

**8.1.1 预估模型**（采用专项 §5 量级输入,不另造口径）：峰值 DAU 120 万 × 在线率 1%~5% → 在线基线 1.2~6 万（规划 ≥10 万）;核心读按人均 1~2 req → 基线 ≈5 万 QPS（规划 ≥15 万）;核心写（投诉/发薪/交易/互评）基线 ≈2 万 TPS（规划 ≥5 万）。**规划峰值为 1.5~3x 冗余的选型量级,最终以设计评审压测修正（★AC-NFR-7）。**

**8.1.2 响应时间预算**（建议初值,评审确认,压测校准）：API 核心读 P95 ≤500ms 分解 ≈ 网关/应用 150ms + Redis ≤5ms + MySQL ≤100ms + 串行依赖余量;首屏 P95 ≤2s 分解 ≈ 页面静态资源 ≤500ms + 数据 API ≤800ms + 前端渲染余量。第三方强依赖（实名回填/支付回调/LLM/OCR）**不计入同步预算**：一律异步化 + 状态机 + 回调/轮询,页面先反馈「处理中」。(L1 链路 P95 目标优先级高于 L2/L3——瓶颈治理资源按 SLO 等级排布。)

**8.1.3 瓶颈分析与优化策略**（逐链路,对应概要设计模块）:

### 8.2 可用性设计

**8.2.1 分级 SLO 与停机预算**：见 §8.0（L1 ≥99.95% / L2 ≥99.9% / L3 ≥99.5%）。SLO 探测 = 每接口分组按月度可用性统计 + 错误预算告警（燃烧率,§8.5）。

**8.2.2 容灾方案（同城双活 + 异地灾备,两地三中心）**
- 目标模型（专项 §4.2）：生产中心 A（双活主）＋ 同城热备 B（可快速接管）＋ 异地灾备 C（冷备/异步复制）,**RPO ≤15min、RTO ≤30min（L1）**,★AC-NFR-5。
- **落地节奏**：M1 以「生产双实例 + MySQL 主从 + 同城备库 + 每日全量/实时 binlog 备份」起步;M2 升「同城双活 + 异地灾备」并完成真实切换演练（专项 §9,灾备 M2 验收）。
- **异地多活说明（如实标注）**：本期方案为「同城双活 + 异地灾备」,**异地多活（双活/三活）列为 M3 演进候选、本期不做**——需两机房同步写与冲突仲裁、成本显著更高;RPO≤15min/RTO≤30min 由同城双活 + 异地灾备即可达成,政务数据境内约束下异地冷备+演练更为稳妥。
- 前置条件（M2 落地前必须齐备）：无状态化（§8.3）、会话外置 Redis、分布式 ID（雪花/号段,避免 DB 自增跨机房冲突）、全链幂等、切流工具（DNS/LB/网关）。
- **演练**：半年 ≥1 次真实切换演练并留痕（专项 §4.2）;应急预案覆盖：数据泄露/DDoS/支付故障/RPO 失守/账号批量被盗/AI 误判（专项 §4.6）;每年 ≥1 次全链路演练。

**8.2.3 故障转移**：应用层——网关/LB 健康检查自动摘除故障实例;DB——MySQL 主从自动切换（半同步复制,从库可提升）;Redis——哨兵/Cluster 故障转移;MQ——镜像/副本队列;对象存储/存证——多云桶或同城跨 AZ 冗余 + 副本;切换优先级按 SLO 分级（L1 先保,允许 L3 短暂降级）。

**8.2.4 降级 / 熔断 / 舱壁（防雪崩）**
- 依赖降级清单（依赖 → 降级行为 → 恢复信号）:

| 依赖 | 降级行为 | 恢复 |
|---|---|---|
| 大模型/助手（ASSIST） | 回退 FAQ 规则库 + 人工入口（G1）,不纯 AI 硬答（§5.5） | LLM 健康检查恢复 |
| 视觉/OCR（AICORE K1/K2） | 任务进人工复核队列原样流转,AI 标记缺席不阻塞 | 云视觉 API 恢复 |
| 支付/代付通道 | 自动切换备选通道 + 幂等重试;全部不可用 → 暂停资金操作入口并公告（不碰钱红线不变） | 通道可用 |
| 短信通知 | 站内信/待发队列补偿 | 通道可用 |
| 推荐/画像（PROFILE） | 回退通用规则排序,不因降级做差异化定价（C7 不杀熟不变） | 画像服务恢复 |
| ES 检索（M2） | 回退 MySQL 近似检索 | ES 恢复 |
| 实名（ACC） | **不可降级**:按红线暂停相关流程并明示 | 第三方实名恢复 |

- 熔断/舱壁机制：统一超时（连接/读/写按依赖分级,含第三方）;线程池/信号量隔离——核心链路（代付/工单/实名回调）与 AI/看板/画像**资源隔离**,非核心故障不得拖垮核心（专项 §4.3）;熔断阈值建议初值【待评审】:连续错误或错误率/慢调用比超阈值熔断 + 半开探测;重试上限 + 指数退避（仅幂等接口）;队列积压监控 + 背压（超限拒绝而非拖垮）。

**8.2.5 数据可用**：每日全量 + binlog 增量备份;每月 ≥1 次恢复演练（★AC-NFR-8）;备份加密 + 异地留存（防勒索）;存证独立不可变存储（WORM/对象锁,只增不改）。

### 8.3 可扩展性设计

**8.3.1 水平扩展与无状态化**
- **无状态设计约束（逐服务执行）**：登录态/会话外置 Redis（HttpOnly 会话或 JWT 无状态 + Redis 可吊销）;助手会话上下文 Redis（30min TTL,已有）;文件/证照全量 OSS,本地零持久;定时任务单实例执行器或分布式锁（Redisson/SETNX）防重复扫描;分布式 ID 雪花/号段（流水/工单/交易全局唯一,为分库分表与多活预留）;幂等键（资金接口,§6.2）。
- 达成后**应用层加实例即扩**,水平扩展无状态数据迁移负担。

**8.3.2 有状态层扩展路线**（与 M1/M2 里程碑绑定）
- MySQL:主从读写分离（M1）→ 流水/工单/交易按月分表 + 冷热分离（M1~M2）→ 按域分库（M2 交易/结算独立库,§2.1 模块边界已预留）;每步配兼容迁移（expand-migrate-contract,§8.6）。
- Redis:哨兵（M1）→ Cluster 分片（M2,会话/缓存/限流多租户隔离）;RabbitMQ:镜像队列保障可用,分区/队列随量扩容;ES 集群 M2 引入（§3 已定可选）。
- **模块化单体 → 服务化**：M2 交易/结算按域拆分独立部署（§2.1/§3 已定边界）,拆分顺序按写吞吐与独立伸缩需求排（SETTLE/TRADE 优先）。

**8.3.3 弹性伸缩策略**
- M1（云主机 + Docker Compose）:实例级「监控触发人工扩容」半自动预案——容量预案 + 提前压测（监管集中检查/开学季/节假日,专项 §5.3）;
- M2（K8s）:HPA 自动弹性（CPU/内存/QPS 指标,最小/最大实例数护栏）+ 就绪探针平滑上下线;突发流量提前容量评估 + 临时扩容,压测达标才放量（专项 §5.3/§5.4）。

### 8.4 安全性设计（落地等保三级 + OWASP ASVS L2,详规见专项 §2/§3）

**8.4.1 认证与授权**
- 实名认证（I1）：**微信/支付宝 OAuth2 授权 + 实名信息回传**（授权码模式,服务端换 token;平台**不自建密码/证件核验体系**,红线不降级）。
- 平台登录态：自签发 **JWT**（access 短时效 + refresh 轮换,Redis 支持吊销/踢出;建议存 **HttpOnly + Secure + SameSite Cookie**,同时缓解 XSS 窃取与 CSRF——access/refresh 时效为【建议初值,评审确认】,如 access 30min + refresh 7d 滑动）;管理端（监管/运营）二次鉴权,敏感操作（发薪/分账/申诉/执法/数据导出）强制 MFA（专项 §3.1）。
- 授权模型：**RBAC**（六方角色 + 扩展角色 + 监管,§6.2）+ **ABAC 数据域**（本人/授权/脱敏公示,L1/L2/L3 分级 §4.3）;全接口 **IDOR/越权校验**（水平 + 垂直）。
- 边界说明：平台本期**不自建对外 OAuth2 IdP**（开放平台/第三方应用授权为 M3 候选,不属本期）;政务接口不可接 → 自建替代（规格书 §8.7,双轨）。

**8.4.2 数据加密**
- 传输:TLS 1.2+ 全链路（禁用 1.0/1.1）,管理面 VPN/专线（专项 §2.3）。
- 存储分层:L1 敏感字段（身份证/手机/工资流水/健康证 + 画像标签）**应用层 AES-256-GCM 加密**;MySQL **TDE** 库级兜底;OSS 服务端加密 + 备份加密;存证哈希链防篡改。
- 密钥:统一 **KMS/HSM**（§3.1 候选）,密钥与数据分离、禁写库（红线 §7.2）;轮换:对称 ≤1 年、非对称 ≤2 年、证书到期前 30 天告警（专项 §3.6）;支付/工资密钥最高级隔离（微信 v3 API 证书）。
- 展示/日志:脱敏输出（138****）、日志禁记明文密钥与敏感字段、对话脱敏前置（复用 J 脱敏组件,专项 §6）。

**8.4.3 防攻击（XSS/CSRF/SQL 注入）落地**

| 攻击面 | 概要架构层措施 |
|---|---|
| SQL 注入 | MyBatis-Plus **参数化查询**（禁字符串拼接/动态 SQL 拼装）;DB 账号最小权限（应用账号无 DDL）;SQL 审计 + 慢日志;WAF 规则兜底;SAST + 上线前渗透（专项 §3.8/§3.9） |
| XSS | React 默认转义 + 输出编码统一;CSP（script-src 白名单）;Cookie HttpOnly/Secure/SameSite;富文本（如有）白名单清洗;点击劫持防护（X-Frame-Options/frame-ancestors） |
| CSRF | SameSite=strict + 状态变更接口双重提交 Token;统一约定「敏感写请求携带 CSRF Token 或走非 Cookie 鉴权（Authorization header JWT）」;CORS 白名单;Referer 校验兜底 |
| 其他（专项 §3.3） | 上传白名单 + 杀毒 + 隔离存储;SSRF/路径穿越/命令注入防护;防重放（时间戳 + 签名/随机数,支付回调验签幂等 §6.1）;登录爆破限速/锁定/验证码;风控（同 IP/设备高频、价格异常,§7.3） |

- 边界防护:WAF + 抗 DDoS + IPS（§3.1 候选,M0 起）;HIDS/镜像扫描;SOC/SIEM 集中日志审计（专项 §2.4~§2.6）。
- 安全运营:告警 5min 响应/30min 定位/2h 处置;漏洞 SLA（严重 24h/高危 72h/中危 2 周/低危 1 月,高危未闭环不得发布）;渗透半年 ≥1 次（专项 §3.9）。

### 8.5 可观测性设计

**8.5.1 日志规范**
- 统一日志规范:**JSON 结构化 + 同 schema 双语言**——Java 主站用 SLF4J/Logback,Python 侧（ASSIST/AICORE）用 structlog/logging 输出同 schema;必含字段:time / level / app / service / module / **traceId / spanId** / uid（脱敏）/ bizType / opCode / code / message;错误码分段沿用 §6.2（1xxx/2xxx/3xxx/5xxx,双语言共用一套码表）。
- 级别规范:ERROR 必须携带可定位上下文（业务键/请求键）;禁止记录明文密钥/支付敏感信息。
- 分通道存储:**审计日志独立（WORM/哈希链,≥6 个月** ★AC-NFR-9）;**对话日志独立 ≤30 天自动清理**（红线）;应用日志分级 + 容量轮转;脱敏规则与 J 助手脱敏组件共用一套（正则 + 实体识别）。
- traceId 贯通:HTTP（X-Request-Id → traceId）与 **MQ header 透传**,跨线程池传递规范;第三方调用（支付回调/LLM/OCR）记录出入参摘要与耗时。

**8.5.2 链路追踪**
- 组件:**SkyWalking（§3.1 已选定）**;OTel+Jaeger 为未选备选。**双语言接入**:Java 主站用 SkyWalking agent;Python 侧（ASSIST/AICORE）用 SkyWalking Python agent 或 OTel 导出至同一后端,traceId 规范与 §6.2 透传一致;全链路采样策略【建议初值,评审确认】:错误与慢调用 **100% 采样** + 正常链路抽样（如 ≤10%,按量调优）。
- 覆盖范围:HTTP/DB/Redis/MQ/第三方;拓扑与慢调用分析供 §8.1 瓶颈治理闭环。

**8.5.3 监控与告警**
- 指标清单:
  - 系统/接口:QPS、P95/P99 时延、错误率、SLO 可用性、依赖健康度、MQ 积压、线程池/连接池水位、GC、慢 SQL、Redis 命中率;
  - 业务(模块级):助手**意图命中率/跳转成功率/推荐采纳率**（J12,已有口径）、工单超时率、代付成功率/对账差异、预警准确率（A4）、OCR 通过率（K2）、画像授权率（J7）。
- 组件:**Prometheus + Grafana + Alertmanager（§3.1 已选定,云托管为未选备选）**。
- 告警分级:**P0**（核心链路不可用/资损/数据泄露/安全事件——即时电话 + 短信 + 升级路由）;**P1**（接口错误率/时延劣化超阈值——5min 内响应）;**P2**（容量水位/积压/证书临期）;**P3**（运营类/低优）。SLO 告警用错误预算燃烧率（§8.2.1）;告警收敛（聚合/去重/静默窗口）防轰炸;值班 on-call 与升级路由（专项 §4.5）。阈值初值【评审确认,压测/试运行标定】。

### 8.6 兼容性设计

**8.6.1 版本兼容**
- API:RESTful 版本化（/api/v1…）;**向后兼容原则:只加不改**;语义变更必须升版本,旧版本废弃前提前通知（专项 §3.4:下线前通知）,废弃周期【建议:≥3 个月,评审确认】;OpenAPI 文档随代码同步（§6.2）;错误响应不破坏旧客户端（code 只增语义）。
- 前端/客户端:浏览器支持矩阵 = Chrome/Edge 当前两个大版本（PC Web 优先）;Electron 套壳锁定内置 Chromium 版本,自动更新通道校验签名（专项 §3.5）;移动端后置不阻塞桌面版（规格书 §8.2）。
- 数据/DB 变更:**expand-migrate-contract（扩展-迁移-收缩）**,字段可空新增、禁止破坏性 DDL 直上生产;迁移脚本评审门禁;双写/读写开关随灰度开关联动（§8.6.2）。

**8.6.2 灰度发布策略**（对齐专项 §4.4:灰度 + 金丝雀 + 自动回滚,回滚 ≤10min）
- 发布分层:① **功能开关**（配置中心/环境变量,按角色/商户域/监管域开关,新功能默认关）;② **网关/负载灰度**（header 灰度标签/cookie/IP/百分比权重分流,载体见 §3.1）;③ **金丝雀实例**（新版本实例先接 5%~10% 流量,与基线对比错误率/时延,指标劣化自动切回）;④ 蓝绿整体切换（无 DB 变更场景）。
- 放量节奏:小批验证 → 逐步放量（10%→30%→100%,每档观察期【建议 ≥30min,评审确认】）→ 全量;公示类变更（费率/规则）提前公告（§7.10 口径）。
- 回滚:应用回滚（镜像/历史版本,≤10min 目标）+ 数据回滚（依赖 §8.6.1 向后兼容,**不兼容变更禁止走灰度直发**）;灰度期 SLO 劣化阈值触发自动切回（与 §8.5.3 告警联动）。
- 演练:发布演练并入每季度全链路演练;发布窗口避开支付高峰（建议工作日晚间/周末白天）。
