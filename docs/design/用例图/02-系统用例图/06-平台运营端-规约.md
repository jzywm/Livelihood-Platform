# 系统用例规约 · 平台运营端（L2）

> 层：L2 系统用例 · 全字段规约 · 配套图 `06-平台运营端.puml`（UC-SYS-O01 ~ O11）

---

### UC-SYS-O01 公示平台费率
- **概述**：平台对外公示透明交易撮合服务费率与调整规则
- **主要参与者**：平台运营方；**次要参与者**：商户、供应商、司机
- **前置条件**：费率口径确定；**后置条件**：费率公示
- **触发条件**：对外公示
- **主成功场景**：1 公示费率（0.5%~1% 分品类）；2 公示计算方式与调整规则；3 随品类扩展更新
- **扩展流程**：2a 调整→提前告知商户
- **业务规则**：不做竞价广告收费、隐性扣费
- **优先级**：P0/M1；**追溯（include）**：P-01

### UC-SYS-O02 存证出证平台证据
- **概述**：对工资/投诉/溯源/交易关键记录时间戳+哈希存证并按需出证
- **主要参与者**：平台运营方；**次要参与者**：监管人员
- **前置条件**：存证能力贯穿；**后置条件**：证据可打包调取
- **触发条件**：仲裁/执法调取
- **主成功场景**：1 记录存证（只增不改）；2 打包出证；3 供仲裁/监管调取
- **扩展流程**：1a 记录缺失→提示
- **业务规则**：从设计期贯穿所有涉权功能
- **优先级**：贯穿 M1；**追溯（include）**：P-02

### UC-SYS-O03 划定试点并扩展行业
- **概述**：划定试点城市/行业并按 SOP 扩展
- **主要参与者**：平台运营方；**次要参与者**：政府
- **前置条件**：试点方案确定；**后置条件**：试点落地、行业扩展
- **触发条件**：运营启动
- **主成功场景**：1 划定试点（石家庄/餐饮+零售+家政）；2 按行业功能映射纳入；3 调研-问卷冻结后扩展
- **扩展流程**：2a 未冻结行业→不进入正式范围
- **业务规则**：走调研-问卷冻结流程
- **优先级**：P0/M0；**追溯（include）**：P-03

### UC-SYS-O04 替代政务对接并双轨切换
- **概述**：以自建能力替代不可对接的政务系统并双轨切换
- **主要参与者**：平台运营方；**次要参与者**：政府
- **前置条件**：政务接口不可接；**后置条件**：自建通道运行、可切换
- **触发条件**：能力建设
- **主成功场景**：1 自建证照核验/工单/结算通道；2 先自建录入；3 政务接口就绪后切换
- **扩展流程**：2a 第三方实名不可用→流程暂停
- **业务规则**：仅按可对接名单保留路径
- **优先级**：贯穿 M0；**追溯（include）**：P-04

### UC-SYS-O05 承诺平台定位与信任背书
- **概述**：对外交付信用背书+政府监督+全链溯源+免费推广+投诉直达承诺
- **主要参与者**：平台运营方；**次要参与者**：政府
- **前置条件**：定位三角确定；**后置条件**：承诺对外交付
- **触发条件**：对外承诺
- **主成功场景**：1 交付定位承诺；2 明确行为边界（强监管只撮合不替代许可）
- **扩展流程**：—
- **业务规则**：政府牵头运营；AI 不代执法
- **优先级**：贯穿定位级；**追溯（include）**：P-05

### UC-SYS-O06 导入存量商户并冷启动
- **概述**：低门槛入驻+存量数据导入，达成冷启动退出标准
- **主要参与者**：平台运营方；**次要参与者**：商户
- **前置条件**：试点范围已定；**后置条件**：商户≥200、行业≥3
- **触发条件**：冷启动
- **主成功场景**：1 低门槛入驻（≤1 分钟）；2 存量商户数据导入；3 政府发文+协会动员
- **扩展流程**：2a 数据缺失→人工补录
- **业务规则**：不做买量/地推承诺
- **优先级**：P0/M1；**追溯（include）**：P-06

### UC-SYS-O07 运营信用与交易风控
- **概述**：运营信用分（防刷单）、交易履约异常处置、助手治理
- **主要参与者**：平台运营方；**次要参与者**：监管人员
- **前置条件**：信用体系运转；**后置条件**：信用公信、风控生效
- **触发条件**：信用运营/异常交易
- **主成功场景**：1 运营全域信用分；2 异常交易（同 IP/设备高频、价格异常）自动拦截；3 助手治理与可观测
- **扩展流程**：2a 拦截→证据留存
- **业务规则**：防刷单防作弊是生命线
- **优先级**：P0/M1；**追溯（include）**：A-07、J-12、T-14

### UC-SYS-O08 统一 AI 网关并治理
- **概述**：统一模型路由、鉴权限流审计、后厨直播异常识别治理
- **主要参与者**：平台运营方；**次要参与者**：监管人员
- **前置条件**：AI 能力接入；**后置条件**：调用可控可审计
- **触发条件**：AI 调用
- **主成功场景**：1 统一路由（文本/视觉/OCR/预测）；2 鉴权限流审计；3 后厨直播异常标记进复核流
- **扩展流程**：3a 商户未授权→不分析
- **业务规则**：视觉云 API 不用于训练；处置人工确认
- **优先级**：P0/M1；**追溯（include）**：K-02、K-05

### UC-SYS-O09 提供实名账户与记账
- **概述**：分类型实名账户与钱包记账（纯记账簿）
- **主要参与者**：平台运营方；**次要参与者**：全角色
- **前置条件**：第三方实名可用；**后置条件**：账户+流水留痕
- **触发条件**：注册/资金操作
- **主成功场景**：1 分类型账户（个人/商户/供应商/结算通道）；2 钱包记账；3 每笔生成流水+哈希
- **扩展流程**：1a 第三方实名不可用→暂停
- **业务规则**：记账与支付分离；不沉淀资金
- **优先级**：P0/M1；**追溯（include）**：I-01

### UC-SYS-O10 提供助手通用能力
- **概述**：分角色使用指导、页面跳转、多轮上下文、兜底、内容安全
- **主要参与者**：平台运营方；**次要参与者**：全角色
- **前置条件**：助手接入；**后置条件**：通用能力可用
- **触发条件**：使用助手
- **主成功场景**：1 分角色 FAQ+步骤引导；2 白名单页面跳转（二次确认）；3 多轮上下文；4 兜底转人工
- **扩展流程**：3a 超时（30 分钟）→清空上下文
- **业务规则**：答案绑定平台流程不编造；脱敏日志≤30 天
- **优先级**：P0/M1；**追溯（include）**：J-01、J-02、J-04、J-05、J-06

### UC-SYS-O11 提供画像中心与四权
- **概述**：个人画像中心（五类数据源）与四权管理
- **主要参与者**：平台运营方；**次要参与者**：全角色
- **前置条件**：数据源授权；**后置条件**：画像可查可控
- **触发条件**：画像构建/用户行使四权
- **主成功场景**：1 五类数据源授权接入；2 标签脱敏加密；3 用户查看/修改/关闭/删除
- **扩展流程**：1a 未授权字段→不入画像；2a 未成年人→不建行为/购买画像
- **业务规则**：透明不杀熟；四权齐全
- **优先级**：P0/M1；**追溯（include）**：J-07、J-08
