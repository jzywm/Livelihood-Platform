## 1. 设计概述

### 1.1 设计目标与原则

1. **五词设计原则**（用户确认）:惠民 · 方便 · 安全 · 透明 · 直达 —— 每个模块/页面设计对照自检（§11 附录表）
2. **信任前置**:M1 只上溯源 + 信用（T2/T3 基础版）,交易撮合放 M2 —— 先攒数据与信任,再上交易（吸取美菜重资产教训）
3. **轻资产撮合**:不建仓储物流、不自营销售,只做信息撮合 + 担保交易 + 信用背书
4. **合规红线**（贯穿设计,不可妥协）:
   - 平台**不沉淀资金、不做二清**（资金全走第三方持牌通道）
   - 实名**仅微信/支付宝实名回传,不接受人工证件核验降级**
   - 农资/医美等强监管品类**只做信息撮合+溯源核验,不替代行政许可**
   - 大模型对话**脱敏前置、数据不出域、日志 ≤30 天脱敏留存**
5. **PC 端优先**:先 Web 应用,后续套壳 Windows 桌面;移动端后置
6. **存证能力**:工资/交易/投诉/溯源 时间戳 + 哈希存证,可出证供劳动仲裁/执法调取

## 2. 总体架构

### 2.1 架构风格与分层

- **B/S 前后端分离**:PC Web（浏览器）优先,后续套壳桌面（复用同一 Web 包）;三端共用后端 API
- **前端三端合一（2026-09-03 拍板,方案 F3）**:单一 React 应用（Monorepo 单仓）,消费端/经营端/监管端以「**角色 + 权限路由**」区分,内部按 feature 模块 + 公共组件库（ui/assistant/api-client/shared）组织;助手侧边栏为共享组件、三端复用;不拆多 App,避免三端重复建设与登录态割裂
- **单体起步、模块化拆分**:M1 规模（10~20 人团队）以**模块化单体**起步（一个应用 + 清晰模块边界）,预留按领域拆微服务的能力（M2 交易/结算独立部署）,避免过早微服务化
- **记账与支付分离**（合规核心）:平台账户系统只记账,资金流转全部由第三方持牌通道完成
- **异步化**:工单、预警、对账、通知走消息队列,削峰 + 可重试
- **双语言架构（Agent/AI 侧,2026-09-03 拍板）**:Java 模块化单体承载业务域（账户/信用/工单/溯源/交易/画像业务）;**ASSIST（J 助手）与 AICORE（模块 K AI 能力中心）为独立 Python 服务**,不经 Java 单体进程,经统一鉴权与内部接口对接（§6.2）;边界动机 = Agent/AI 链路是「高 IO 等待 + 外部 AI API + 异步任务」型负载,Python async 生态（FastAPI/LangChain/视觉-OCR 库）匹配度更高,且与 Java 业务域故障隔离（§8.2.4）

| L1 本人 | 身份证号、手机号、工资流水、健康证 | 存储加密;展示脱敏（138****） | 本人 + 授权（平台内） |
| L2 授权 | 履历、证照、用工/交易记录 | 本人授权后可见 | 授权方（老板↔工作者↔监管） |
| L3 脱敏公示 | 信用分、红黑榜、抽检、投诉结果、服务费率 | 脱敏公示 | 公众 |
| 对话数据 | 助手会话内容 | **脱敏前置后调 LLM;不沉淀原文;日志 ≤30 天脱敏留存** | 仅质量指标聚合 |
| 画像数据（J7） | 画像标签（年龄带/职业/学历带/品类偏好/价格敏感度） | **最小化收集 + 履历/行为入画像需授权（可撤回）+ 加密存储/脱敏输出 + 操作审计** | 本人可见（管理页四权）;服务端仅输出画像标签 |

### 4.4 存储策略

- MySQL 主库存业务实体;**流水类（钱包流水/代付/交易/分账）按月分表**
- Redis:会话（登录态）、助手会话上下文（30 分钟 TTL）、限流计数
- OSS:证照、检测报告、证据材料、溯源证明文件;存证只增不改
- 日志:应用日志 + 脱敏对话日志分离存储,对话日志 30 天自动清理

### 5.1 账户服务 ACC（I1 实名账户+钱包记账）

> **定位**：实名身份底座 + 纯记账簿，为全平台提供可信身份与资金流水证据。**模块**：I1;**里程碑**：M1;**三端分布**：消费端（实名/流水）· 经营端（实名/流水）· 监管端（资金流水审计）。

#### 5.1.1 功能详细说明

##### 5.1.1.1 实名注册与实名回传

- **功能描述**：用户通过微信/支付宝实名回传完成实名注册，获得平台账户与六方角色。
- **前置条件**：用户已进入注册页;持有可用微信/支付宝账号;已同意实名授权协议。
- **操作流程**：
  1. 用户点击「微信/支付宝一键实名」;
  2. 系统展示实名授权协议与第三方授权页;
  3. 用户输入（确认授权）并回传实名信息（姓名/身份证号）;
  4. 系统返回注册结果（accountId、realNameStatus=已实名）与角色。
- **后置状态**：账户创建成功、实名状态=已实名，可继续建档/入职/入驻等后续流程。
- **异常处理**：第三方实名不可用 → 按红线**暂停**注册/入职/入驻并明示，不接受人工证件核验降级（R-02）;实名信息不匹配 → 报 3002 提示重新核验;重复 open_id → 幂等返回原账户。

##### 5.1.1.2 钱包记账与流水查询

- **功能描述**：为每笔资金操作生成平台记账流水（含通道交易号/时间戳/存证哈希），支持本人分页查询。
- **前置条件**：账户已实名;已有资金操作发生或用户发起查询。
- **操作流程**：
  1. 用户点击「我的钱包/流水」;
  2. 系统展示流水列表（类型/金额/时间/通道交易号，脱敏）;
  3. 用户输入筛选条件（类型/起止日期/分页）;
  4. 系统返回分页流水（list、total）。
- **后置状态**：流水只增不改、长期留痕，可作为对账与出证依据（P-02）。
- **异常处理**：流水为空 → 返回空列表并提示;越权查询他人流水 → 2002 拦截（水平越权校验）;流水表按月分表，跨月查询走分表路由。

##### 5.1.1.3 收款账户绑定

- **功能描述**：将本人收款账户绑定到持牌支付通道，供代付/分账收款使用。
- **前置条件**：账户已实名;持有可绑定的收款账户。
- **操作流程**：
  1. 用户点击「绑定收款账户」;
  2. 系统展示绑定表单与通道说明;
  3. 用户输入通道类型与收款账号并确认;
  4. 系统返回绑定结果（bindingId）。
- **后置状态**：收款账户绑定成功，可用于后续代付/分账收款。
- **异常处理**：账号与实名不一致 → 3002 拒绝绑定;通道校验失败/超时 → 4002 提示重试;重复绑定同账号 → 幂等返回原绑定。

### 5.2 结算服务 SETTLE（I3 工资代付 / I4 分账 / I5 零工 / F4 运费）

> **定位**：所有资金结算的唯一执行层，只走第三方持牌通道、平台不碰钱。**模块**：I3/I4/I5/F4;**里程碑**：代付 M1、分账/零工/运费 M2;**三端分布**：经营端（代付发起/分账）· 消费端（工资流水）· 监管端（资金流水审计/欠薪预警）。

#### 5.2.1 功能详细说明

##### 5.2.1.1 工资保障代付

- **功能描述**：老板经持牌通道向工作者代付工资，平台校验并记账留痕、不碰资金。
- **前置条件**：老板已实名并绑定对公/法人付款账户;存在有效用工关系与考勤记录。
- **操作流程**：
  1. 用户（老板）点击「发起代付」并选择用工关系;
  2. 系统展示待付金额、考勤校验结果与代付协议;
  3. 用户输入代付金额/收款账户并确认（携带幂等键）;
  4. 系统调用持牌通道代付并返回代付单状态（payrollId、status）。
- **后置状态**：代付单进入「代付中」;到账后「已到账」，更新老板发薪履约率并留痕存证。
- **异常处理**：通道失败/超时 → 幂等重试或切换备选通道（4002）;重复提交 → 3008 幂等返回原结果;对账不一致 → 3009 + 每日对账 JOB 补差;应发未发超时 → 触发欠薪预警。

##### 5.2.1.2 欠薪预警与证据出证

- **功能描述**：对「应发未发」自动预警，并支持将流水+用工记录打包出证。
- **前置条件**：存在应发未发的代付单（超时扫描触发）;申请人有权限。
- **操作流程**：
  1. 用户（工作者/监察）点击「证据出证」并选择业务单;
  2. 系统展示可出证范围（流水/用工/考勤记录）与用途说明;
  3. 用户输入出证用途并确认;
  4. 系统返回证据包（evidenceId、hash、downloadUrl，含时间戳+哈希）。
- **后置状态**：证据包只增不改、可下载，供劳动仲裁/执法调取（P-02）。
- **异常处理**：对象不存在 → 3006;无权限 → 2002;欠薪预警推送失败 → MQ 重试 + 站内信兜底。

##### 5.2.1.3 商品购买结算分账【M2】

- **功能描述**：交易货款经持牌通道收款后按比例分账（卖方货款 + 平台服务费）。
- **前置条件**：交易订单已验收通过;分账产品资质已开通（M0）。
- **操作流程**：
  1. 系统在订单验收通过后触发分账;
  2. 系统展示分账明细（货款/服务费/费率，费率公开）;
  3. 用户（无需输入，自动分账）确认放款;
  4. 系统返回分账结果并落分账流水。
- **后置状态**：货款入卖方账户、服务费入平台（费率 0.5%~1% 公开），订单完成。
- **异常处理**：分账失败 → 幂等重试 + 每日对账;二清风险 → 全程走持牌通道不沉淀（R-01）;费率调整 → 调整前提前公示（P-01）。

##### 5.2.1.4 零工劳务结算【M2】

- **功能描述**：支持日结/周结/月结的零工灵活结算，复用 I-03 代付能力。
- **前置条件**：存在零工用工记录与考勤;已绑定收款账户。
- **操作流程**：
  1. 用户（老板）点击「零工结算」并选择结算周期;
  2. 系统展示应结金额与用工/考勤校验;
  3. 用户输入结算金额并确认;
  4. 系统代付并返回到账进度。
- **后置状态**：零工到账、计入劳务信用，工作者可查应结未结与发放进度。
- **异常处理**：结算周期无记录 → 提示无应结;通道失败 → 重试/换通道;越权 → 2002。

##### 5.2.1.5 货运运费托管结算【M2】

- **功能描述**：货运运费经持牌通道托管，送达确认后放款入司机账户。
- **前置条件**：货运订单已下单并冻结运费;司机/货主已实名。
- **操作流程**：
  1. 货主下单并冻结运费（第三方托管）;
  2. 系统展示托管状态与放款条件;
  3. 用户（货主）到货确认后触发放款;
  4. 系统放款入司机账户并返回结果。
- **后置状态**：运费入司机账户、留痕存证，杜绝拖欠。
- **异常处理**：货损/迟到纠纷 → 存证仲裁并计入双方信用;放款失败 → 重试 + 对账。

#### 5.2.2 核心流程与状态机（工资代付）

### 5.3 信用档案服务 CRED（A1 一店一档 / A2 一人一档 / A3 信用分）

> **定位**：商户/人员/供应商信用档案与信用分中枢，含价格公示与未成年人禁入承诺。**模块**：A1/A2/A3;**里程碑**：M1;**三端分布**：消费端（查档案/信用/价格）· 经营端（维护档案/价目表/承诺）· 监管端（全量档案核验/信用总览）。

#### 5.3.1 功能详细说明

##### 5.3.1.1 商户入驻与证照核验建档

- **功能描述**：商户注册→实名→上传证照→核验建档，支持 OCR 预审、录入 ≤1 分钟。
- **前置条件**：商户已实名（对公/法人）;持有营业执照/许可证;实名仅微信/支付宝回传。
- **操作流程**：
  1. 用户（商户）点击「入驻建档」;
  2. 系统展示证照上传页（扫码/拍照）;
  3. 用户输入（上传）营业执照/许可证并确认;
  4. 系统返回核验结果（merchantId、auditStatus，OCR 预审 + 人工核验）。
- **后置状态**：一店一档创建，核验通过后档案可公开查询。
- **异常处理**：证照核验不通过 → 3003 退回补传;实名未完成 → 3001 拦截;录入超时/失败 → 保存草稿可续传。

##### 5.3.1.2 一店一档档案公开页

- **功能描述**：将证照/处罚/抽检/投诉率/好评率/信用分/价目表聚合于一页，脱敏公示、一屏可查。
- **前置条件**：商户档案已建档;用户扫码或搜索进入。
- **操作流程**：
  1. 用户（消费者）点击「查档案」或扫码;
  2. 系统展示一店一档（核心信息一屏）;
  3. 用户输入（可选）筛选/搜索;
  4. 系统返回档案详情（archive、priceList、commitment，脱敏）。
- **后置状态**：档案可反复查阅，脱敏公示、不泄露 L1/L2 敏感数据。
- **异常处理**：对象不存在 → 3006;敏感字段越权 → 2002/脱敏截断;档案被隐藏 → 提示已下架。

##### 5.3.1.3 商户档案维护与异常标记

- **功能描述**：商户自助维护档案（更新证照/回应投诉），证照临期/年检/投诉激增自动标记并双向推送。
- **前置条件**：商户已入驻;有更新或异常事件发生。
- **操作流程**：
  1. 用户（商户）点击「档案维护」并选择更新项;
  2. 系统展示当前档案与异常标记;
  3. 用户输入（上传）新证照/回应内容;
  4. 系统返回更新结果并自动销警/留痕。
- **后置状态**：档案更新留痕;临期/异常标记随更新自动销警，同步监管端预警（A-08）。
- **异常处理**：证照过期未更新 → 升级预警 + 「资质异常」标注;更新越权 → 2002;OCR 预审失败 → 转人工核验。

##### 5.3.1.4 价格公示（基础版）

- **功能描述**：商户自主维护价目表并于档案「价格公示」区展示，更新留痕、不代定价。
- **前置条件**：商户已建档;需维护价目表。
- **操作流程**：
  1. 用户（商户）点击「维护价目表」;
  2. 系统展示价目表编辑页（扫码/拍照录入）;
  3. 用户输入价目并提交更新;
  4. 系统返回新版本号与公示状态（version、updatedAt）。
- **后置状态**：价目表「已公示」，更新历史可查、消费端一屏可见。
- **异常处理**：价目与实收不符被投诉 → 标记「价格争议」关联 D2 投诉;差异化定价 → 禁止（同品同价，不杀熟，R-07）。

##### 5.3.1.5 未成年人禁入承诺标注

- **功能描述**：为娱乐场所/网吧类档案标注「未成年人禁入承诺」，联动举报与预警。
- **前置条件**：商户属于娱乐场所/网吧类目;已建档。
- **操作流程**：
  1. 用户（商户）点击「禁入承诺标注」;
  2. 系统展示承诺内容与法律提示;
  3. 用户输入（勾选确认）承诺;
  4. 系统返回标注状态（status），档案展示该标注。
- **后置状态**：档案带「未成年人禁入承诺」标注，消费端脱敏可见;举报数据可流向 A4 预警。
- **异常处理**：非该类目商户 → 隐藏该入口;撤销承诺 → 留痕并记录原因。

##### 5.3.1.6 一人一档与从业履历核验

- **功能描述**：从业人员实名→健康证/技能证核验→一人一档，雇佣经历自动累积为履历（授权可见）。
- **前置条件**：从业人员已实名;持有健康证/技能证。
- **操作流程**：
  1. 用户（从业人员）点击「一人一档建档」;
  2. 系统展示证件上传页与授权说明;
  3. 用户输入（上传）健康证/技能证并授权;
  4. 系统返回建档结果（personId、auditStatus）。
- **后置状态**：一人一档创建，履历随雇佣关系自动累积，仅本人/授权雇主可见。
- **异常处理**：证照核验不通过 → 3003;未授权查看履历 → 2002;年龄 <16 联动 C-01 拦截。

##### 5.3.1.7 信用分与红黑榜

- **功能描述**：商户/人员/供应商信用分计算与红黑榜脱敏公示，支撑分级监管与放心供应商联动。
- **前置条件**：主体已建档;有评分数据源。
- **操作流程**：
  1. 用户点击「查信用分/红黑榜」;
  2. 系统展示信用分构成（维度拆解）与榜单;
  3. 用户输入筛选（类型/分数区间）;
  4. 系统返回分数（score、dims）与脱敏榜单。
- **后置状态**：信用分公示可查、可筛，低分多查/高分少查支撑分级监管。
- **异常处理**：扣分申诉 → 复用 D-03 申诉机制;刷分作弊 → 防刷拦截（R-15）;对象不存在 → 3006。

#### 5.3.2 核心流程与状态机（价格公示）

```
商户（经营端）自主维护价目表（扫码/拍照录入,≤1 分钟）→ 提交更新 → 留痕 + 轻量审核
→ 一店一档「价格公示」区展示（消费端一屏可见）→ 更新历史可查
异常分支:投诉/抽检发现价目与实收不符 → 标记「价格争议」→ 关联 D2 投诉
红线:价目表仅展示,不因画像差异化定价（同一商户同品同价,对齐 J7 不杀熟）
```

| 状态 | 说明 | 迁移 |
|---|---|---|
| 草稿 → 已公示 | 商户维护价目表 | 更新即重公示（留痕） |
| 争议中 | 价目与实收不符投诉 | → 商户申诉 / D2 处理 |

> 完整版（维修报价单、后厨直播）仍随 B2 在 P1/M2,本节为 M1 基础版。

### 5.4 用工服务 EMP（C2 防童工 / I2 劳务信用）

> **定位**：用工关系、入职年龄核验与劳务信用互评。**模块**：C2/I2;**里程碑**：M1;**三端分布**：经营端（入职核验/代付发起）· 消费端（工资流水/履历）· 监管端（欠薪预警）。

#### 5.4.1 功能详细说明

##### 5.4.1.1 防童工入职年龄核验

- **功能描述**：入职登记时核验年龄，<16 岁自动拦截并警示留痕。
- **前置条件**：存在用工关系登记;拟入职人员已实名。
- **操作流程**：
  1. 用户（雇主）点击「入职登记」并选择人员;
  2. 系统展示入职信息与年龄核验结果;
  3. 用户输入（确认）入职信息;
  4. 系统返回登记结果（employmentId、blocked 标记）。
- **后置状态**：年龄 ≥16 正常入职建档;<16 自动拦截，留痕并警示。
- **异常处理**：年龄 <16 → 3010 自动拦截（违规对象）;实名未完成 → 3001;核验信息不符 → 提示重新核验。

##### 5.4.1.2 劳务信用双向互评

- **功能描述**：用工结束/发薪完成后双方互评，累积劳务信用分并联动全域信用。
- **前置条件**：用工关系结束或发薪完成;双方已实名。
- **操作流程**：
  1. 用户（老板/工作者）点击「互评」;
  2. 系统展示评价维度（履约/态度/质量）与可附证据;
  3. 用户输入评分与评价内容（可附证据）;
  4. 系统返回互评结果（reviewId）并更新劳务信用分。
- **后置状态**：劳务信用分更新（老板侧:发薪履约40+纠纷20+评价20+资质20;工作者侧:出勤40+纠纷20+评价20+实名20），并入 A3/A2。
- **异常处理**：恶意差评 → 走 D-03 申诉;重复互评 → 3007 状态不允许;失信者限制发布岗位/接单。

#### 5.4.2 核心流程与状态机（劳务信用互评）

```
用工结束/发薪完成 → 双方互评（履约/态度/质量,可附证据）→ 计入劳务信用分
老板侧:发薪履约40 + 纠纷20 + 评价20 + 资质20
工作者侧:出勤40 + 纠纷20 + 评价20 + 实名20
→ 老板信用并入 A3,工作者信用并入 A2;恶意差评走 D3 申诉
```

### 5.5 工单服务 TICKET（D2 投诉 / G1 热线 / D3 申诉）

> **定位**：投诉/热线/申诉的统一工单内核，限时处理、升级市监、结果公示。**模块**：D2/G1/D3;**里程碑**：投诉/热线 M1、申诉 M2;**三端分布**：消费端（提交投诉/看进度）· 经营端（限时处理/申诉）· 监管端（工单升级/办结）。

#### 5.5.1 功能详细说明

##### 5.5.1.1 投诉直达（含「未成年人违规进入」举报）

- **功能描述**：消费者 ≤3 步提交投诉，全程进度可见、结果公示并计入商户信用。
- **前置条件**：用户已实名;已选商户;证据可附（选填）。
- **操作流程**：
  1. 用户点击「投诉」;
  2. 系统展示投诉表单（选商户→选类别【含未成年人违规进入】→附证据）;
  3. 用户输入投诉内容并提交;
  4. 系统返回工单号与状态（ticketId、status=已提交）。
- **后置状态**：工单进入「处理中」，商家限时处理（48h），未解决自动升级市监、办结公示（脱敏）。
- **异常处理**：参数缺失 → 1001;商户不存在 → 3006;超时未处理 → 自动升级;举报数据 → 流向 A4 违规入场预警聚合。

##### 5.5.1.2 群众热线/诉求工单

- **功能描述**：群众提交诉求生成工单，平台分派部门限时办结、结果公示。
- **前置条件**：用户已实名;选择部门/类别。
- **操作流程**：
  1. 用户点击「群众热线/诉求」;
  2. 系统展示诉求表单（部门/类别/内容/证据）;
  3. 用户输入诉求内容并提交;
  4. 系统返回工单号（ticketId）与受理状态。
- **后置状态**：工单智能分派对应部门，限时办结（如 7 天）、进度可见、结果脱敏公示。
- **异常处理**：12345 不可接 → 自建工单 + 线下流转（P-04）;超时办结 → 升级与考核;优秀建议/高频诉求 → 转 G-02 建议论坛。

##### 5.5.1.3 恶意差评申诉与职业索赔识别【M2】

- **功能描述**：商户凭留存证据申诉恶意差评，平台识别职业索赔后复核改判。
- **前置条件**：商户收到差评/扣分;有平台留存证据。
- **操作流程**：
  1. 用户（商户）点击「申诉」;
  2. 系统展示申诉表单与可引用证据;
  3. 用户输入申诉理由并附证据;
  4. 系统返回申诉受理状态（appealId），平台复核后改判/驳回。
- **后置状态**：申诉留痕、处置结果计入相关方信用，职业索赔识别（AI 辅助+人工确认）。
- **异常处理**：无证据申诉 → 提示补充;重复申诉 → 3007;识别结果仅辅助、人工确认后处置（C8）。

### 5.6 溯源服务 TRACE（T2 供应商资质 / T3 溯源二维码）

> **定位**：供应商入驻核验、供应商信用、批次溯源码与扫码验真。**模块**：T2/T3;**里程碑**：M1;**三端分布**：消费端（扫码溯源）· 经营端（批次上架/环节上报）· 监管端（断链预警）。

#### 5.6.1 功能详细说明

##### 5.6.1.1 供应商入驻与品类资质核验

- **功能描述**：供应商实名 + 按品类核验资质后开通上架，只做信息核验不替代行政许可。
- **前置条件**：供应商已实名;持有品类资质（农资:执照+经营/生产许可+登记批号;食材:执照+许可+检验报告）。
- **操作流程**：
  1. 用户（供应商）点击「供应商入驻」;
  2. 系统展示品类资质门槛与上传页;
  3. 用户输入（上传）资质文件并确认;
  4. 系统返回核验结果（supplierId、auditStatus）。
- **后置状态**：供应商建档、开通上架，同步建立信用档案（T-05）。
- **异常处理**：资质不达标 → 3003 退回;强监管品类 → 仅信息撮合+溯源核验、不替代行政许可（R-09）;实名未完成 → 3001。

##### 5.6.1.2 供应商信用档案与信用分

- **功能描述**：按资质合规30%+交易履约30%+质量口碑30%+正向贡献10% 计算供应商信用分。
- **前置条件**：供应商已建档;有评分数据源。
- **操作流程**：
  1. 用户点击「查供应商信用」;
  2. 系统展示信用分构成与红黑榜/放心供应商标识;
  3. 用户输入筛选（只看放心供应商/分数区间）;
  4. 系统返回信用分与榜单。
- **后置状态**：信用分动态更新，放心供应商（≥85 且无质量投诉）动态授予/撤销，与 A-07 全域信用贯通。
- **异常处理**：扣分申诉 → 复用 T-07/D-03;信用分 ≤40 → 黑榜降权/禁新单;刷分 → R-15 拦截。

##### 5.6.1.3 溯源批次码生成与环节上报

- **功能描述**：创建批次即生成唯一溯源码，按批次上报生产检测/流通温控/终端登记等环节。
- **前置条件**：供应商已入驻;批次信息齐全。
- **操作流程**：
  1. 用户（供应商）点击「创建批次」;
  2. 系统展示批次表单与环节模板;
  3. 用户输入批次信息并上报各环节数据;
  4. 系统返回批次号与溯源码（batchId、code）。
- **后置状态**：溯源码生成（一物一码/一批一码），各环节记录留痕存证。
- **异常处理**：环节缺失 → 显式标注「缺失/断链」;重复上报 → 按环节去重/幂等;异常（温度超限）→ 触发预警。

##### 5.6.1.4 扫码验真与全链透明展示

- **功能描述**：扫码按时间轴展示「批号→检测→温控→终端」全链，缺环显式标注。
- **前置条件**：批次已创建;用户持码扫码。
- **操作流程**：
  1. 用户扫码（溯源码）;
  2. 系统展示全链时间轴;
  3. 用户输入（无，自动识别码）;
  4. 系统返回链路（chain、brokenLinks），缺环标注「缺失/断链」。
- **后置状态**：扫码次数留痕（防伪旁证），全链透明可查。
- **异常处理**：溯源码无效 → 3006 提示;环节缺失 → 断链标注;重复流通/温度超限 → 预警。

### 5.7 助手服务 ASSIST（J 智能助手,Python 服务）

> **定位**：三端复用的智能助手侧边栏，脱敏→意图→动作，硬护栏强制。**模块**：J1~J6/J13;**里程碑**：M1;**实现载体**：独立 Python 服务（FastAPI + LangChain 编排，§3），经内部接口取数、不直连主站库（§6.2）。**三端分布**：消费端（深度：指导/跳转/推荐）· 经营端（基础问答）· 监管端（基础问答）。

#### 5.7.1 功能详细说明

##### 5.7.1.1 使用指导（分角色 FAQ + 步骤引导）

- **功能描述**：分角色知识库 + 步骤式引导，答案绑定平台流程与文档、不编造。
- **前置条件**：用户已登录;助手侧边栏常驻可见。
- **操作流程**：
  1. 用户点击助手并输入问题;
  2. 系统识别角色并展示匹配 FAQ/步骤引导;
  3. 用户输入追问（可选）;
  4. 系统返回答案（绑定平台流程，标注「以页面为准」）。
- **后置状态**：用户获得可执行引导，可一键跳转对应页面。
- **异常处理**：无法识别 → 回退 FAQ 关键词 → 人工入口（G1）;事实类回答绑定文档、不自由发挥。

##### 5.7.1.2 页面跳转（意图导航）

- **功能描述**：自然语言 → 平台内部页面直达，仅白名单路由、跳转前二次确认。
- **前置条件**：用户已登录;意图可映射到白名单页面。
- **操作流程**：
  1. 用户输入「我要投诉/查信用」等意图;
  2. 系统展示目标页面卡片与二次确认;
  3. 用户输入（确认跳转）;
  4. 系统返回目标路由（route、needConfirm）。
- **后置状态**：跳转到白名单内页面，不对外链。
- **异常处理**：意图不在白名单 → 不跳转并提示;越权页面 → 2002 拦截;误跳 → 二次确认防误跳。

##### 5.7.1.3 对话内商品推荐（透明理由）

- **功能描述**：按规则排序推荐商品并输出透明理由，非竞价、不杀熟。
- **前置条件**：用户已登录;候选 = 在售 + 信用分 ≥ 阈值 + 溯源完整。
- **操作流程**：
  1. 用户输入「帮我推荐…」;
  2. 系统展示候选（信用40%+溯源30%+价格20%+好评10%）与理由模板;
  3. 用户输入（可选）过滤条件（只看放心供应商/预算）;
  4. 系统返回候选列表与理由（candidates、reasons）。
- **后置状态**：用户获得带理由的推荐，可一键跳商品详情。
- **异常处理**：候选不足 → 如实提示;强监管品类 → 只推荐不替代行政许可;排序非竞价、无付费置顶。

##### 5.7.1.4 澄清式导购

- **功能描述**：模糊意图经模板化追问后输出 ≤5 个带理由对比，不臆断需求。
- **前置条件**：用户表达「帮我选/不知道买什么」等模糊意图。
- **操作流程**：
  1. 用户输入模糊选购意图;
  2. 系统展示模板化追问（用途/预算/给谁用，可跳过）;
  3. 用户输入（回答或跳过）;
  4. 系统返回 ≤5 个带理由对比（信用/溯源/价格/好评）。
- **后置状态**：可一键跳选品页/详情或继续多轮。
- **异常处理**：无法识别 → J-05 人工兜底;候选不足 → 如实提示;不臆断用户需求。

##### 5.7.1.5 会话上下文与人工兜底

- **功能描述**：会话内指代理解，30 分钟超时清空;无法识别走 FAQ→人工入口。
- **前置条件**：用户处于会话中。
- **操作流程**：
  1. 用户输入多轮指代问题;
  2. 系统结合会话上下文理解并应答;
  3. 用户输入（继续追问）;
  4. 系统返回答案或（无法识别时）转人工入口。
- **后置状态**：会话 30 分钟超时自动清空、不留跨会话记忆;回答可评价。
- **异常处理**：识别不了 → FAQ 关键词 → 人工入口（G1），不纯 AI 硬答;反馈数据脱敏用于迭代、不训练第三方。

##### 5.7.1.6 内容安全与幻觉管控

- **功能描述**：输出过内容安全过滤、防幻觉，事实类绑定平台数据、标注「以页面为准」。
- **前置条件**：助手输出任何回答前。
- **操作流程**：
  1. 系统对助手输出做内容安全过滤与事实校验;
  2. 系统展示（过滤后）回答并标注「平台助手生成，请以页面信息为准」;
  3. 用户输入（无，接收回答）;
  4. 系统返回合规回答。
- **后置状态**：未成年人场景额外敏感词与年龄限制;对话脱敏、不出域、日志 ≤30 天。
- **异常处理**：涉政/色情/暴力 → 拦截并提示;幻觉/编造 → 模板化输出+绑定文档;限流防滥用（J-12）。

### 5.8 商品服务 PROD（T1 选品广场,【M2】）

#### 5.8.1 功能详细说明

##### 5.8.1.1 商品上架审核与批次关联

- **功能描述**：商品关联资质/批号/检测报告上架，平台校验后审核，资质临期/投诉激增强制下架。

##### 5.8.1.3 商品透明详情页与供应商主页

### 5.9 交易服务 TRADE（T4 担保撮合 + B2C,【M2】）

> **定位**：担保交易、货款托管、验收退款、仲裁与互评。**模块**：T4/B2C;**里程碑**：M2（设计先行）;**三端分布**：消费端（担保下单/退款）· 经营端（采购/收款）· 监管端（交易合规监控/资金审计）。

#### 5.9.1 功能详细说明

##### 5.9.1.1 担保交易与货款托管

- **功能描述**：下单后货款托管于持牌机构，平台仅收服务费、不碰货款（不二清）。
- **前置条件**：采购方已实名;商品在售;货款可冻结。
- **操作流程**：
  1. 用户（采购方）点击「担保下单」;
  2. 系统展示订单与托管协议（费率 0.5%~1% 公开）;
  3. 用户输入数量并确认（幂等键）;
  4. 系统返回订单与托管状态（orderId、escrowStatus）。
- **后置状态**：货款托管于持牌机构，订单进入发货环节。
- **异常处理**：重复下单 → 3008 幂等;通道失败 → 4002 重试;平台不沉淀货款（R-01）。

##### 5.9.1.2 到货验收与拒收退款

- **功能描述**：收货后 48h 验收期，支持确认/部分/全额拒收，验收通过放款、拒收退款。
- **前置条件**：订单已发货/在途;进入验收期。
- **操作流程**：
  1. 用户（采购方）点击「到货验收」;
  2. 系统展示验收选项（确认/部分拒收/全额拒收）;
  3. 用户输入验收结果并附证据;
  4. 系统返回验收状态并触发放款/退款。
- **后置状态**：验收通过→放款+互评;拒收→退款中→完成;超期自动确认。
- **异常处理**：验收超期 → 自动确认并提示;货不对板 → 拒收+证据+退款;生鲜/农资验收期可差异化配置。

##### 5.9.1.3 争议仲裁与结果公示

- **功能描述**：验收/货款争议进入存证仲裁，平台给出结论并脱敏公示。
- **前置条件**：存在验收分歧或争议;双方提交证据。
- **操作流程**：
  1. 用户点击「发起争议」;
  2. 系统展示争议表单与证据要求;
  3. 用户输入争议主张并附证据;
  4. 系统返回争议单（disputeId），仲裁后公示结果。
- **后置状态**：仲裁完成（放款/退款），结果脱敏公示、计入双方信用。
- **异常处理**：证据不足 → 提示补充;仲裁结果 → 计入双方信用;公示脱敏（R-03）。

##### 5.9.1.4 交易互评与信用联动

- **功能描述**：交易完成双方互评，更新供应商/商户信用分。
- **前置条件**：订单已完成/验收通过。
- **操作流程**：
  1. 用户（买卖双方）点击「交易互评」;
  2. 系统展示评价维度与证据入口;
  3. 用户输入评分与评价;
  4. 系统返回互评结果并更新信用分。
- **后置状态**：信用分联动更新（T-05/A-07），恶意差评走 D-03。
- **异常处理**：恶意差评 → D-03 申诉;重复互评 → 3007;防刷单 → R-15 拦截。

##### 5.9.1.5 履约异常处置与防刷单风控

- **功能描述**：超时未发货自动催发/可取消退款，验收超期自动确认，异常交易风控拦截。
- **前置条件**：订单存在履约异常或触发风控规则。
- **操作流程**：
  1. 系统定时扫描履约状态并触发处置;
  2. 系统展示异常提示（催发/可取消/风控拦截）;
  3. 用户输入（确认取消/继续等待）;
  4. 系统返回处置结果。
- **后置状态**：超时自动催发或退款，异常交易（同 IP/设备高频、价格异常）拦截留痕。
- **异常处理**：刷单/价格异常 → 拦截并留证（R-15）;验收超期 → 自动确认;催发无响应 → 可取消退款。

#### 5.10.1 功能详细说明

##### 5.10.1.1 费率/抽成公开公示页

- **功能描述**：对外公示服务费率（0.5%~1% 分品类）与货运抽成口径、调整规则，调整前告知。
- **前置条件**：用户访问公示页（消费/经营/监管三端）。

  1. 用户点击「费率/抽成公示」;
  2. 系统展示费率表（分品类）与调整规则;
  3. 用户输入（可选）品类筛选;
  4. 系统返回对应费率与规则（rate、rules）。
- **后置状态**：费率公开可查，调整前提前告知商户（P-01）。
- **异常处理**：品类未开放 → 提示未开放;费率调整 → 调整前公示（R-13）;不做竞价广告/隐性扣费。

##### 5.10.1.2 监管预警与分级监管【M1 基础 / M2 完整】

- **功能描述**：高频投诉/资质临期/异常经营自动预警推送，按「画像风险+信用」双维度分级监管。
- **前置条件**：存在预警触发（扫描/举报聚合）;监管人员登录看板。
- **操作流程**：
  1. 系统定时扫描并生成预警;
  2. 系统展示预警看板与分级监管列表;
  3. 用户（监管）输入筛选（类型/等级/分数区间）;
  4. 系统返回预警列表与分级建议（低分多查/高分少查）。
- **后置状态**：预警只推送线索、不自动执法;商户更新资质自动销警;处置留痕。
- **异常处理**：资质过期未更新 → 升级预警+「资质异常」标注;举报聚合 → 人工复核后推送、不自动定责;预警准确率 → §8.5 指标监控。


| 预警类型 | 触发 | 推送对象 |
|---|---|---|
| 资质临期 | 证照有效期 ≤30 天 | 监管端 + 商户端 |
| 资质过期 | 已过期未更新 | 监管端（升级）+ 商户端 |
| 违规入场高频举报 | 同场所未成年人举报聚合达阈值 | 监管端 |

> 设计要点:复用 CRED 证照有效期数据 + TICKET 举报数据;通知走 MQ（§6.3）,商户端提醒落「方便/惠民」两词（回应经营端「合规成本高」痛点）。

### 5.11 画像服务 PROFILE（J7 个人画像 + 商铺画像）

> **定位**：个人画像构建、画像四权管理、个性化推荐与商铺画像（选择性监管）。**模块**：J7;**里程碑**：M1 基础 / M2 完整;**实现载体**：业务留 Java（§2.4 注），算法子服务后置 Python。**三端分布**：消费端（画像四权/个性化）· 经营端（基础）· 监管端（画像合规审计/选择性监管）。

#### 5.11.1 功能详细说明

##### 5.11.1.1 个人画像构建与数据授权

- **功能描述**：聚合实名/履历/行为/评论/购买/主动完善六类数据源构建画像，履历与行为入画像需授权可撤回。
- **前置条件**：用户已实名;数据源按授权策略采集（履历需本人授权）。
- **操作流程**：
  1. 系统按数据源采集（授权校验）;
  2. 系统展示画像数据来源与授权状态;
  3. 用户输入（授予/撤回授权）;
  4. 系统返回标签计算结果（脱敏、加密、来源可查）。
- **后置状态**：画像生成（脱敏标签），未授权字段不入画像;未成年人不建行为/购买画像。
- **异常处理**：未授权 → 该字段不入画像;撤回授权 → 停止采集并清理;脱敏/加密/审计（R-07/C7）。

##### 5.11.1.2 画像管理页（用户四权）

- **功能描述**：查看/修改/关闭个性化/删除画像四权齐全，操作全审计。
- **前置条件**：用户已实名;访问画像管理页。
- **操作流程**：
  1. 用户点击「我的画像」;
  2. 系统展示画像标签 + 来源 + 授权状态;
  3. 用户输入（查看/修改/关闭/删除）;
  4. 系统返回操作结果（status）。
- **后置状态**：关闭个性化→推荐回退通用规则、停止行为采集;删除→衍生数据 30 天清理、不影响基本功能。
- **异常处理**：删除后衍生数据 30 天内清理;操作留痕审计;价格不因画像差异化（不杀熟）。

##### 5.11.1.3 个性化推荐增强

- **功能描述**：在规则排序上叠加画像权重（职业加权/价格敏感/适龄过滤），理由标注画像依据、价格不变。
- **前置条件**：画像已授权;有推荐场景（商品/信息/引导）。
- **操作流程**：
  1. 系统基于画像计算推荐权重;
  2. 系统展示推荐结果 + 画像依据说明;
  3. 用户输入（关闭个性化等四权操作）;
  4. 系统返回推荐（叠加不替代、价格与画像无关）。
- **后置状态**：个性化商品/信息/引导按画像排序，理由透明可解释、可纠错。
- **异常处理**：关闭个性化 → 回退通用规则（J-03）;价格差异化 → 禁止（R-07）;未成年人不建画像。

##### 5.11.1.4 商铺画像与选择性监管【M2】

- **功能描述**：聚合商铺信息/购买者评价/卫生/信用/风险五类特征构建商铺画像，供推荐排序与「画像风险+信用」分级监管。
- **前置条件**：商铺已建档;聚合 A/B/K 既有数据（不新增采集）。
- **操作流程**：
  1. 系统聚合商铺五类特征生成商铺画像;
  2. 系统展示商铺画像（脱敏、来源可查）;
  3. 用户（监管）输入分级监管筛选;
  4. 系统返回分级建议（高信用低风险少查、低信用高风险多查）。
- **后置状态**：商铺画像=特征集合，信用分=其派生的可公示评分，不另立第二套评分;预警只推送线索、不自动执法。
- **异常处理**：商铺申诉画像特征 → 复用 A-07/D-03;画像用于监管不替代人工执法（C8）;经营者个人信息脱敏（R-03）。

### 5.12 AI 能力中心 AICORE（模块 K,Python 服务）

> **定位**：AI 网关底座 + 视觉合规审核 + 证照 OCR + 图像问答 + 风险预测。**模块**：K1~K6;**里程碑**：网关+OCR M1、视觉审核/图像问答 M2、预测 M3;**实现载体**：独立 Python 服务（§3），AI 只标记不决策（C8）。**三端分布**：经营端（K2 证照 OCR）· 监管端（K1 视觉审核/K4 预警）· 消费端（K3 图像问答）。

#### 5.12.1 功能详细说明

##### 5.12.1.1 AI 网关与治理底座

- **功能描述**：统一模型路由（文本/视觉云/OCR/自建预测通道）+ 鉴权限流路由审计 + 任务队列 + 置信度分级 + 全链路审计。
- **前置条件**：平台已接入模型服务（DeepSeek/视觉云，密钥经 KMS）;调用方经统一鉴权。
- **操作流程**：
  1. 业务侧发起 AI 调用;
  2. 系统按路由策略分发到对应模型通道并限流;
  3. 用户输入（业务参数/图像，脱敏后）;
  4. 系统返回模型结果 + 置信度 + 审计记录。
- **后置状态**：AI 调用全链路可审计、限流可控、结果置信度分级。
- **异常处理**：模型/视觉 API 失败 → 4003 + 降级（FAQ/人工复核队列）;限流 → 令牌桶按账号限流;视觉云签数据合规协议（不用于训练）。

##### 5.12.1.2 证照 OCR 自动核验

- **功能描述**：证照上传后自动提取字段、比对有效期/类目，减少人工核验量。
- **前置条件**：商户/监管上传证照图像;经 K-02 网关接入。
- **操作流程**：
  1. 用户上传证照图像;
  2. 系统 OCR 提取字段并比对有效期/类目;
  3. 用户输入（确认/纠错）;
  4. 系统返回核验结果（fields、matchResult）。
- **后置状态**：核验结果可追溯，经营端预审 + 监管端双端。
- **异常处理**：OCR 识别失败 → 转人工核验;图像模糊 → 提示重传;结果仅预审、人工核验兜底。

##### 5.12.1.3 视觉合规审核工作台【M2】

- **功能描述**：上传/巡检图像经脱敏+云视觉分析，疑似标记+置信度分级，人工复核留痕。
- **前置条件**：监管人员上传原材料/证照/抽检图像;图像脱敏前置。
- **操作流程**：
  1. 用户（监管）上传巡检图;
  2. 系统脱敏（去人脸/车牌）后云视觉分析;
  3. 系统返回疑似标记 + 置信度（高≥0.9/中 0.7~0.9/低<0.7）;
  4. 用户输入（人工确认/一键核查单/归档）复核结论。
- **后置状态**：结论写入 A-02 档案与信用分;AI 只标记不决策、复核留痕。
- **异常处理**：高置信 → 人工确认;中 → 复核队列;低 → 归档;复核结果只用于平台调优、不回流第三方。

##### 5.12.1.4 图像问答【M2】

- **功能描述**：拍照提问（包装合规/食材新鲜度）由视觉模型辅助回答，仅辅助判断。
- **前置条件**：用户上传图像并提问;受 J 组对话合规约束。
- **操作流程**：
  1. 用户拍照并提问;
  2. 系统脱敏后调视觉模型;
  3. 用户输入（追问，可选）;
  4. 系统返回答案 + 置信度。
- **后置状态**：用户获得辅助判断，不作执法/鉴定结论。
- **异常处理**：无法判断 → 提示仅辅助、转人工/投诉入口;图像脱敏前置;不作鉴定结论（C8）。

##### 5.12.1.5 风险预测预警【M3】

- **功能描述**：基于信用/交易/抽检/投诉数据预测风险商户，联动 A-08 预警。
- **前置条件**：有足量平台数据;预测通道=平台自建风险模型、数据不出域。
- **操作流程**：
  1. 系统基于平台数据计算风险分;
  2. 系统展示风险商户与预警依据;
  3. 用户（监管）输入（筛选/处置确认）;
  4. 系统返回风险结果（riskScore、factors）。
- **后置状态**：预警触发人工处置（AI 不决策），联动分级监管。
- **异常处理**：AI 输出风险建议、人工决策执行;数据不出域;预警准确率监控（§8.5）。

##### 5.12.1.6 后厨直播异常识别【M2/M3】

- **功能描述**：联动后厨直播做画面级异常标记（未穿工装/卫生/明火离人），需商户授权。
- **前置条件**：商户已授权接入后厨直播;有直播画面流。
- **操作流程**：
  1. 系统对直播画面帧做异常识别;
  2. 系统标记异常并进入复核流;
  3. 用户（监管）输入（复核确认/驳回）;
  4. 系统返回处置结果。
- **后置状态**：标记进复核流、处置人工确认、不自动处罚。
- **异常处理**：商户未授权 → 不采集;识别误报 → 人工驳回;处置不自动处罚（C8）。

### 5.13 民生互动服务 CIVIC（G2 论坛 / H 民生监督 / E 社区,【M2~M3】）

> **定位**：群众建议论坛、民生项目公开与进度、优质小店免费推广与行业圈层论坛。**模块**：G2/H/E;**里程碑**：M2~M3（占位，仅边界）;**三端分布**：消费端（看进度/提意见/看推荐榜单）· 经营端（免费上榜）· 监管端（建设方回应）。

#### 5.13.1 功能详细说明

##### 5.13.1.1 群众建议论坛【M2】

- **功能描述**：群众按分类发帖建议（实名/匿名可选），平台审核分派、限时答复并公示采纳情况。
- **前置条件**：用户已实名;建议内容合规。
- **操作流程**：
  1. 用户点击「提建议」并选择分类;
  2. 系统展示建议表单（实名/匿名可选）;
  3. 用户输入建议内容并提交;
  4. 系统返回受理结果（suggestionId），分派部门后限时答复。
- **后置状态**：采纳/部分采纳/不采纳+理由公示;优秀建议可获积分/荣誉。
- **异常处理**：内容违规 → 敏感词+人工复核拦截;匿名建议 → 脱敏处理;与画像边界：不收集无关信息。

##### 5.13.1.2 民生项目公开与进度【M3】

- **功能描述**：政府发布民生项目（计划/资金/工期/责任部门）并实时同步进度，群众可查、可提意见。

- **操作流程**：
  1. 用户点击「民生项目」;
  2. 系统展示项目列表与进度（图文/视频/数据）;
  3. 用户输入（筛选/提意见）;
  4. 系统返回项目详情与意见入口。
- **后置状态**：项目进度公开可监督;建设方限时回应并公示。
- **异常处理**：项目无进展 → 提示待更新;群众意见 → 建设方限时回应（H-02）;内容治理防谣言。

##### 5.13.1.3 优质小店免费推广【M3】

- **功能描述**：优质小店免费上榜、群众点评、信用加权推荐（非竞价、不收费）。
- **前置条件**：商户信用达标;上榜审核通过。
- **操作流程**：
  1. 用户（消费者）点击「优质小店榜」;
  2. 系统展示信用加权榜单与点评;
  3. 用户输入（点评/筛选）;
  4. 系统返回榜单与点评结果。
- **后置状态**：上榜=信用换流量，形成「信用→流量→守法」正循环，平台不靠推广收费。
- **异常处理**：刷榜 → 信用加权+防刷拦截;差评 → 走 D-03 申诉;排名非竞价。

##### 5.13.1.4 行业圈层论坛【M3】

- **功能描述**：按行业/地域分层的行业圈层论坛，敏感词+人工复核治理。
- **前置条件**：用户已实名;发帖内容合规。
- **操作流程**：
  1. 用户进入行业圈层;
  2. 系统展示分层论坛帖子;
  3. 用户输入（发帖/回复）;
  4. 系统返回发帖结果（postId）。
- **后置状态**：行业交流互助、内容治理留痕。
- **异常处理**：敏感词/违规 → 拦截+人工复核;与画像边界：不用于画像训练;未成年人内容 → 年龄限制。

### 5.14 新增功能设计（v1.2 · 26 项评审整改，功能点 P-07/A-09/B-04/C-02/D-04/E-04/T-23/I-06/J-15）

> 本小节集中承载 26 项整改新增的 9 个功能点（六段模板），按归属服务落位；对应页面见 IA v1.3 与线框图 `apps/docs/线框图/`。

#### 5.14.1 强实名增强 I-06（ACC）

- **功能描述**：在微信/支付宝回传基础上，新增 NFC 读身份证芯片 + 人脸活体比对，作高风险场景（供应商入驻/大额交易）强实名增强；基础回传路径不变（R-02）。
- **前置条件**：已完成基础实名回传；持有 NFC 读卡能力（移动端/线下设备）+ 公安授权读卡模块/SAM。
- **操作流程**：1. 用户进入强实名增强页;2. 系统展示 NFC 读证引导;3. 用户 NFC 贴证读取芯片信息 + 人脸活体;4. 系统返回增强实名结果。
- **后置状态**：实名等级=强实名，可进行高风险场景操作。
- **异常处理**：NFC 读卡失败 → 降级基础实名并提示;生物特征属敏感个人信息 → 最小化+加密存储（R-03/R-07），人脸模板不出域;授权缺失 → 提示线下设备办理。

#### 5.14.2 未成年人交易拦截 A-09（TRADE/CRED）

- **功能描述**：商品/店铺打「禁未成年」标记（联动 A-05 禁入承诺），购买链路下单时校验买家实名年龄，<18 岁拦截下单。
- **前置条件**：商品/店铺已标注「禁未成年」；买家已实名（含年龄字段）。
- **操作流程**：1. 买家点击下单;2. 系统校验实名年龄;3. 若 <18 → 拦截并提示「本商品限 18+」;4. 系统返回拦截结果。
- **后置状态**：拦截留痕，违规商家计入信用分（A-07）。
- **异常处理**：未实名 → 引导先实名;年龄数据缺失 → 视为未成年拦截（从严）;商家漏标 → 信用扣分 + 预警。

#### 5.14.3 店铺直播 B-04（TRACE）

- **功能描述**：商户发起店铺/后厨直播（明厨亮灶 + 实况），消费者观看；内容实时合规，监管端可抽查（K-05 画面识别）；直播带货（营销直播）属 P2 评估。
- **前置条件**：商户已入驻;直播设备就绪;直播内容合规授权。
- **操作流程**：1. 商户点击「开始直播」;2. 系统推流并生成直播间;3. 消费者进入观看/互动/举报;4. 系统返回直播状态。
- **后置状态**：直播留痕，异常画面标记进复核流（人工确认不自动处罚）。
- **异常处理**：违规内容 → 实时过滤 + 监管抽查;未授权 → 拒绝开播;断流 → 自动回放/结束提示。

#### 5.14.4 打卡记工时 C-02（EMP）

- **功能描述**：职工上班/下班打卡，工时自动累计，作为工资代付（I-03）考勤校验依据，联动一人一档（A-06）。
- **前置条件**：职工已建立用工关系（M-08）。
- **操作流程**：1. 职工点击「上班/下班打卡」;2. 系统记录打卡时间;3. 系统累计工时;4. 系统返回打卡结果与工时。
- **后置状态**：工时留痕，供 M-10 工资代付校验。
- **异常处理**：重复打卡 → 幂等提示;漏打卡 → 补卡申请（留痕）;代付时工时缺失 → 提示补录。

#### 5.14.5 退货/退款 D-04（TRADE）

- **功能描述**：验收通过后买家可申请退货，状态机：申请→审核→寄回/上门取→退款（分账反向），争议复用 T-15 仲裁。
- **前置条件**：订单已验收通过且在退货时效内。
- **操作流程**：1. 买家发起退货申请（原因+证据）;2. 商家审核;3. 买家寄回/上门取;4. 系统退款（分账反向）并返回结果。
- **后置状态**：退货完成，双方信用联动。
- **异常处理**：商家驳回 → 可申诉/争议仲裁（T-15）;超时未处理 → 自动通过;退款失败 → 分账反向重试。

#### 5.14.6 商户动态 E-04（CIVIC）

- **功能描述**：商户发布图文/短视频动态（上新/优惠/营业状态/实拍），内容审核（敏感词+人工复核）后展示，非竞价排序。
- **前置条件**：商户已入驻;内容合规。
- **操作流程**：1. 商户编辑动态（图文/视频）;2. 系统内容审核;3. 审核通过后展示在店铺主页/首页动态流;4. 系统返回发布结果。
- **后置状态**：动态留痕，消费者可见。
- **异常处理**：敏感词/违规 → 拦截+人工复核;不做付费置顶（非竞价）;恶意刷动态 → 防刷拦截。

#### 5.14.7 上门服务 T-23（TRADE）

- **功能描述**：消费者浏览上门服务（家政/维修等）→ 预约 → 服务方接单 → 上门服务 → 双方扫码核验（复用溯源/信用链路）。
- **前置条件**：服务方已入驻建档（复用 T-01 门槛）;消费者已实名。
- **操作流程**：1. 消费者预约上门服务;2. 服务方接单;3. 上门服务;4. 双方扫码核验并返回结果。
- **后置状态**：服务完成，服务方建立信用档案（复用 T-05 思路）。
- **异常处理**：超时未接单 → 取消/重新匹配;服务争议 → 投诉直达（D-02）;扫码核验失败 → 补录留痕。

#### 5.14.8 消费券 P-07（DASH）

- **功能描述**：政府/平台发券（惠民）→ 消费者领取 → 「我的消费券」展示券码 → 到店商家扫券码核销 → 结算抵扣；券为优惠凭证、平台不沉淀资金（R-01）。
- **前置条件**：发券经政府授权;消费者已实名。
- **操作流程**：1. 消费者领取消费券;2. 系统生成券码;3. 到店出示券码，商家扫码核销;4. 结算抵扣并返回结果。
- **后置状态**：券状态=已用，核销留痕可审计。
- **异常处理**：券过期 → 提示失效;重复核销 → 幂等拦截;结算抵扣异常 → 对账补差。

#### 5.14.9 助手操作悬浮卡 + 一键代做 J-15（ASSIST）

- **功能描述**：助手给方案时同步弹「跟着做」浮动步骤卡（随页面滚动常驻）；白名单安全操作支持「一键代做」——跳转并高亮目标按钮（复用 J-02 白名单+二次确认）。
- **前置条件**：助手已识别用户意图并输出方案。
- **操作流程**：1. 助手输出方案 + 悬浮步骤卡;2. 用户按步骤卡逐步操作;3. 或点击「一键代做」;4. 系统跳转并高亮目标按钮。
- **后置状态**：用户完成操作，步骤卡标记完成/收起。
- **异常处理**：非白名单操作 → 不提供一键代做，仅步骤卡;越权 → RBAC 拦截（2002）;标注「以页面为准」。

### 6.2 API 约定与错误码

**统一规范**：
- RESTful，URL 前缀 `/api/v1/`；统一响应 `{ code, message, data, traceId, timestamp }`，成功 `code=0`
- 鉴权：JWT（access 短时效 + refresh 轮换，Redis 吊销）+ RBAC（六方角色 + 扩展角色）；管理端二次鉴权 + 敏感操作（发薪/分账/申诉/执法/导出）MFA
- 分页：`{ list, total, page, pageSize }`；默认 `page=1, pageSize=20`（上限 100）
- 幂等：下单/代付/分账等资金接口强制幂等键（`Idempotency-Key` 头或业务幂等键），重复提交返回原结果
- 文档：OpenAPI 随代码生成；`agent-sdlc-standard` PR 门禁要求接口文档同步

**错误码约定（分段）**：

| 段 | 含义 | HTTP | 典型码 |
|---|---|---|---|
| 0 | 成功 | 200 | code=0 |
| 1xxx | 参数/校验 | 400 | 1001 参数缺失 · 1002 格式错误 · 1003 枚举/范围非法 |
| 2xxx | 鉴权/权限 | 401/403 | 2001 未登录/Token 失效 · 2002 无权限 · 2003 MFA 未通过 |
| 3xxx | 业务规则 | 422 | 3001 实名未完成 · 3002 实名不匹配 · 3003 证照核验不通过 · 3004 信用分不足 · 3005 商户未入驻 · 3006 对象不存在 · 3007 状态不允许该操作 · 3008 幂等键冲突 · 3009 资金对账不一致 · 3010 违规对象（未成年人） |
| 4xxx | 第三方/依赖 | 502 | 4001 实名接口失败 · 4002 支付通道失败/超时 · 4003 大模型/视觉 API 失败 · 4004 短信通道失败 |
| 5xxx | 系统 | 500 | 5000 内部错误 · 5001 数据库错误 · 5002 依赖超时/熔断 |

**双语言内部调用**（沿用 v0.8 口径）：Java 主站 ↔ Python ASSIST/AICORE 内部接口带统一鉴权头 + **traceId 透传**（§8.5）；Python 侧同步产出 OpenAPI（FastAPI 原生）；错误码/幂等/脱敏口径与主站一致；外部 AI 调用（DeepSeek/视觉云）一律由 Python 服务收敛，**前端不直连 Python 服务**（AI 入口经主站/网关鉴权后转发）。

### 8.1 性能设计

**8.1.1 预估模型**（采用专项 §5 量级输入,不另造口径）：峰值 DAU 120 万 × 在线率 1%~5% → 在线基线 1.2~6 万（规划 ≥10 万）;核心读按人均 1~2 req → 基线 ≈5 万 QPS（规划 ≥15 万）;核心写（投诉/发薪/交易/互评）基线 ≈2 万 TPS（规划 ≥5 万）。**规划峰值为 1.5~3x 冗余的选型量级,最终以设计评审压测修正（★AC-NFR-7）。**

**8.1.2 响应时间预算**（建议初值,评审确认,压测校准）：API 核心读 P95 ≤500ms 分解 ≈ 网关/应用 150ms + Redis ≤5ms + MySQL ≤100ms + 串行依赖余量;首屏 P95 ≤2s 分解 ≈ 页面静态资源 ≤500ms + 数据 API ≤800ms + 前端渲染余量。第三方强依赖（实名回填/支付回调/LLM/OCR）**不计入同步预算**：一律异步化 + 状态机 + 回调/轮询,页面先反馈「处理中」。(L1 链路 P95 目标优先级高于 L2/L3——瓶颈治理资源按 SLO 等级排布。)

### 8.2 可用性设计

**8.2.1 分级 SLO 与停机预算**：见 §8.0（L1 ≥99.95% / L2 ≥99.9% / L3 ≥99.5%）。SLO 探测 = 每接口分组按月度可用性统计 + 错误预算告警（燃烧率,§8.5）。

**8.2.2 容灾方案（同城双活 + 异地灾备,两地三中心）**
- 目标模型（专项 §4.2）：生产中心 A（双活主）＋ 同城热备 B（可快速接管）＋ 异地灾备 C（冷备/异步复制）,**RPO ≤15min、RTO ≤30min（L1）**,★AC-NFR-5。
- **落地节奏**：M1 以「生产双实例 + MySQL 主从 + 同城备库 + 每日全量/实时 binlog 备份」起步;M2 升「同城双活 + 异地灾备」并完成真实切换演练（专项 §9,灾备 M2 验收）。
- **异地多活说明（如实标注）**：本期方案为「同城双活 + 异地灾备」,**异地多活（双活/三活）列为 M3 演进候选、本期不做**——需两机房同步写与冲突仲裁、成本显著更高;RPO≤15min/RTO≤30min 由同城双活 + 异地灾备即可达成,政务数据境内约束下异地冷备+演练更为稳妥。
- 前置条件（M2 落地前必须齐备）：无状态化（§8.3）、会话外置 Redis、分布式 ID（雪花/号段,避免 DB 自增跨机房冲突）、全链幂等、切流工具（DNS/LB/网关）。
- **演练**：半年 ≥1 次真实切换演练并留痕（专项 §4.2）;应急预案覆盖：数据泄露/DDoS/支付故障/RPO 失守/账号批量被盗/AI 误判（专项 §4.6）;每年 ≥1 次全链路演练。

**8.2.3 故障转移**：应用层——网关/LB 健康检查自动摘除故障实例;DB——MySQL 主从自动切换（半同步复制,从库可提升）;Redis——哨兵/Cluster 故障转移;MQ——镜像/副本队列;对象存储/存证——多云桶或同城跨 AZ 冗余 + 副本;切换优先级按 SLO 分级（L1 先保,允许 L3 短暂降级）。

**8.2.4 降级 / 熔断 / 舱壁（防雪崩）**
- 依赖降级清单（依赖 → 降级行为 → 恢复信号）:

| 依赖 | 降级行为 | 恢复 |
|---|---|---|
| 大模型/助手（ASSIST） | 回退 FAQ 规则库 + 人工入口（G1）,不纯 AI 硬答（§5.7） | LLM 健康检查恢复 |
| 视觉/OCR（AICORE K1/K2） | 任务进人工复核队列原样流转,AI 标记缺席不阻塞 | 云视觉 API 恢复 |
| 支付/代付通道 | 自动切换备选通道 + 幂等重试;全部不可用 → 暂停资金操作入口并公告（不碰钱红线不变） | 通道可用 |
| 短信通知 | 站内信/待发队列补偿 | 通道可用 |
| 推荐/画像（PROFILE） | 回退通用规则排序,不因降级做差异化定价（C7 不杀熟不变） | 画像服务恢复 |
| ES 检索（M2） | 回退 MySQL 近似检索 | ES 恢复 |
| 实名（ACC） | **不可降级**:按红线暂停相关流程并明示 | 第三方实名恢复 |

- 熔断/舱壁机制：统一超时（连接/读/写按依赖分级,含第三方）;线程池/信号量隔离——核心链路（代付/工单/实名回调）与 AI/看板/画像**资源隔离**,非核心故障不得拖垮核心（专项 §4.3）;熔断阈值建议初值【待评审】:连续错误或错误率/慢调用比超阈值熔断 + 半开探测;重试上限 + 指数退避（仅幂等接口）;队列积压监控 + 背压（超限拒绝而非拖垮）。

**8.2.5 数据可用**：每日全量 + binlog 增量备份;每月 ≥1 次恢复演练（★AC-NFR-8）;备份加密 + 异地留存（防勒索）;存证独立不可变存储（WORM/对象锁,只增不改）。

### 8.3 可扩展性设计

**8.3.1 水平扩展与无状态化**
- **无状态设计约束（逐服务执行）**：登录态/会话外置 Redis（HttpOnly 会话或 JWT 无状态 + Redis 可吊销）;助手会话上下文 Redis（30min TTL,已有）;文件/证照全量 OSS,本地零持久;定时任务单实例执行器或分布式锁（Redisson/SETNX）防重复扫描;分布式 ID 雪花/号段（流水/工单/交易全局唯一,为分库分表与多活预留;时钟回拨三档预案——L1 退避→L2 自动切号段兜底→L3 拒绝发号,统一组件 infra-idgen 全写库服务复用,见《高并发架构演进设计》§2.3）;幂等键（资金接口,§6.2）。
- 达成后**应用层加实例即扩**,水平扩展无状态数据迁移负担。

**8.3.2 有状态层扩展路线**（与 M1/M2 里程碑绑定）
- MySQL:主从读写分离（M1）→ 流水/工单/交易按月分表 + 冷热分离（M1~M2）→ 按域分库（M2 交易/结算独立库,§2.1 模块边界已预留）;每步配兼容迁移（expand-migrate-contract,§8.6）。
- Redis:哨兵（M1）→ Cluster 分片（M2,会话/缓存/限流多租户隔离）;RabbitMQ:镜像队列保障可用,分区/队列随量扩容;ES 集群 M2 引入（§3 已定可选）。
- **模块化单体 → 服务化**：M2 交易/结算按域拆分独立部署（§2.1/§3 已定边界）,拆分顺序按写吞吐与独立伸缩需求排（SETTLE/TRADE 优先）。

**8.3.3 弹性伸缩策略**
- M1（云主机 + Docker Compose）:实例级「监控触发人工扩容」半自动预案——容量预案 + 提前压测（监管集中检查/开学季/节假日,专项 §5.3）;
- M2（K8s）:HPA 自动弹性（CPU/内存/QPS 指标,最小/最大实例数护栏）+ 就绪探针平滑上下线;突发流量提前容量评估 + 临时扩容,压测达标才放量（专项 §5.3/§5.4）。

### 8.4 安全性设计（落地等保三级 + OWASP ASVS L2,详规见专项 §2/§3）

**8.4.1 认证与授权**
- 实名认证（I1）：**微信/支付宝 OAuth2 授权 + 实名信息回传**（授权码模式,服务端换 token;平台**不自建密码/证件核验体系**,红线不降级）。
- 平台登录态：自签发 **JWT**（access 短时效 + refresh 轮换,Redis 支持吊销/踢出;建议存 **HttpOnly + Secure + SameSite Cookie**,同时缓解 XSS 窃取与 CSRF——access/refresh 时效为【建议初值,评审确认】,如 access 30min + refresh 7d 滑动）;管理端（监管/运营）二次鉴权,敏感操作（发薪/分账/申诉/执法/数据导出）强制 MFA（专项 §3.1）。
- 授权模型：**RBAC**（六方角色 + 扩展角色 + 监管,§6.2）+ **ABAC 数据域**（本人/授权/脱敏公示,L1/L2/L3 分级 §4.3）;全接口 **IDOR/越权校验**（水平 + 垂直）。
- 边界说明：平台本期**不自建对外 OAuth2 IdP**（开放平台/第三方应用授权为 M3 候选,不属本期）;政务接口不可接 → 自建替代（规格书 §8.7,双轨）。

**8.4.2 数据加密**
- 传输:TLS 1.2+ 全链路（禁用 1.0/1.1）,管理面 VPN/专线（专项 §2.3）。
- 存储分层:L1 敏感字段（身份证/手机/工资流水/健康证 + 画像标签）**应用层 AES-256-GCM 加密**;MySQL **TDE** 库级兜底;OSS 服务端加密 + 备份加密;存证哈希链防篡改。
- 密钥:统一 **KMS/HSM**（§3.1 候选）,密钥与数据分离、禁写库（红线 §7.2）;轮换:对称 ≤1 年、非对称 ≤2 年、证书到期前 30 天告警（专项 §3.6）;支付/工资密钥最高级隔离（微信 v3 API 证书）。
- 展示/日志:脱敏输出（138****）、日志禁记明文密钥与敏感字段、对话脱敏前置（复用 J 脱敏组件,专项 §6）。

**8.4.3 防攻击（XSS/CSRF/SQL 注入）落地**

| 攻击面 | 概要架构层措施 |
|---|---|
| SQL 注入 | MyBatis-Plus **参数化查询**（禁字符串拼接/动态 SQL 拼装）;DB 账号最小权限（应用账号无 DDL）;SQL 审计 + 慢日志;WAF 规则兜底;SAST + 上线前渗透（专项 §3.8/§3.9） |
| XSS | React 默认转义 + 输出编码统一;CSP（script-src 白名单）;Cookie HttpOnly/Secure/SameSite;富文本（如有）白名单清洗;点击劫持防护（X-Frame-Options/frame-ancestors） |
| CSRF | SameSite=strict + 状态变更接口双重提交 Token;统一约定「敏感写请求携带 CSRF Token 或走非 Cookie 鉴权（Authorization header JWT）」;CORS 白名单;Referer 校验兜底 |
| 其他（专项 §3.3） | 上传白名单 + 杀毒 + 隔离存储;SSRF/路径穿越/命令注入防护;防重放（时间戳 + 签名/随机数,支付回调验签幂等 §6.1）;登录爆破限速/锁定/验证码;风控（同 IP/设备高频、价格异常,§7.3） |

- 边界防护:WAF + 抗 DDoS + IPS（§3.1 候选,M0 起）;HIDS/镜像扫描;SOC/SIEM 集中日志审计（专项 §2.4~§2.6）。
- 安全运营:告警 5min 响应/30min 定位/2h 处置;漏洞 SLA（严重 24h/高危 72h/中危 2 周/低危 1 月,高危未闭环不得发布）;渗透半年 ≥1 次（专项 §3.9）。

### 8.5 可观测性设计

**8.5.1 日志规范**
- 统一日志规范:**JSON 结构化 + 同 schema 双语言**——Java 主站用 SLF4J/Logback,Python 侧（ASSIST/AICORE）用 structlog/logging 输出同 schema;必含字段:time / level / app / service / module / **traceId / spanId** / uid（脱敏）/ bizType / opCode / code / message;错误码分段沿用 §6.2（1xxx/2xxx/3xxx/5xxx,双语言共用一套码表）。
- 级别规范:ERROR 必须携带可定位上下文（业务键/请求键）;禁止记录明文密钥/支付敏感信息。
- 分通道存储:**审计日志独立（WORM/哈希链,≥6 个月** ★AC-NFR-9）;**对话日志独立 ≤30 天自动清理**（红线）;应用日志分级 + 容量轮转;脱敏规则与 J 助手脱敏组件共用一套（正则 + 实体识别）。
- traceId 贯通:HTTP（X-Request-Id → traceId）与 **MQ header 透传**,跨线程池传递规范;第三方调用（支付回调/LLM/OCR）记录出入参摘要与耗时。

**8.5.2 链路追踪**
- 组件:**SkyWalking（§3.1 已选定）**;OTel+Jaeger 为未选备选。**双语言接入**:Java 主站用 SkyWalking agent;Python 侧（ASSIST/AICORE）用 SkyWalking Python agent 或 OTel 导出至同一后端,traceId 规范与 §6.2 透传一致;全链路采样策略【建议初值,评审确认】:错误与慢调用 **100% 采样** + 正常链路抽样（如 ≤10%,按量调优）。
- 覆盖范围:HTTP/DB/Redis/MQ/第三方;拓扑与慢调用分析供 §8.1 瓶颈治理闭环。

**8.5.3 监控与告警**
- 指标清单:
  - 系统/接口:QPS、P95/P99 时延、错误率、SLO 可用性、依赖健康度、MQ 积压、线程池/连接池水位、GC、慢 SQL、Redis 命中率;
  - 业务(模块级):助手**意图命中率/跳转成功率/推荐采纳率**（J12,已有口径）、工单超时率、代付成功率/对账差异、预警准确率（A4）、OCR 通过率（K2）、画像授权率（J7）。
- 组件:**Prometheus + Grafana + Alertmanager（§3.1 已选定,云托管为未选备选）**。
- 告警分级:**P0**（核心链路不可用/资损/数据泄露/安全事件——即时电话 + 短信 + 升级路由）;**P1**（接口错误率/时延劣化超阈值——5min 内响应）;**P2**（容量水位/积压/证书临期）;**P3**（运营类/低优）。SLO 告警用错误预算燃烧率（§8.2.1）;告警收敛（聚合/去重/静默窗口）防轰炸;值班 on-call 与升级路由（专项 §4.5）。阈值初值【评审确认,压测/试运行标定】。

### 8.6 兼容性设计

**8.6.1 版本兼容**
- API:RESTful 版本化（/api/v1…）;**向后兼容原则:只加不改**;语义变更必须升版本,旧版本废弃前提前通知（专项 §3.4:下线前通知）,废弃周期【建议:≥3 个月,评审确认】;OpenAPI 文档随代码同步（§6.2）;错误响应不破坏旧客户端（code 只增语义）。
- 前端/客户端:浏览器支持矩阵 = Chrome/Edge 当前两个大版本（PC Web 优先）;Electron 套壳锁定内置 Chromium 版本,自动更新通道校验签名（专项 §3.5）;移动端后置不阻塞桌面版（规格书 §8.2）。
- 数据/DB 变更:**expand-migrate-contract（扩展-迁移-收缩）**,字段可空新增、禁止破坏性 DDL 直上生产;迁移脚本评审门禁;双写/读写开关随灰度开关联动（§8.6.2）。

**8.6.2 灰度发布策略**（对齐专项 §4.4:灰度 + 金丝雀 + 自动回滚,回滚 ≤10min）
- 发布分层:① **功能开关**（配置中心/环境变量,按角色/商户域/监管域开关,新功能默认关）;② **网关/负载灰度**（header 灰度标签/cookie/IP/百分比权重分流,载体见 §3.1）;③ **金丝雀实例**（新版本实例先接 5%~10% 流量,与基线对比错误率/时延,指标劣化自动切回）;④ 蓝绿整体切换（无 DB 变更场景）。
- 放量节奏:小批验证 → 逐步放量（10%→30%→100%,每档观察期【建议 ≥30min,评审确认】）→ 全量;公示类变更（费率/规则）提前公告（§7.10 口径）。
- 回滚:应用回滚（镜像/历史版本,≤10min 目标）+ 数据回滚（依赖 §8.6.1 向后兼容,**不兼容变更禁止走灰度直发**）;灰度期 SLO 劣化阈值触发自动切回（与 §8.5.3 告警联动）。
- 演练:发布演练并入每季度全链路演练;发布窗口避开支付高峰（建议工作日晚间/周末白天）。
