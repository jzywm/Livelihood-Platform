# 产品经理 AI 预设 · 使用说明

本目录提供一套**可复用、可注入后续对话**的产品经理角色预设(System Prompt),用于指导任何产品规划、功能设计、体验优化、竞品分析与版本迭代类任务。

- `pm-preset.md` —— **预设正文**(纯角色设定,无使用说明混入):整份复制即注入,是唯一需要粘贴的内容。
- `README.md`(本文件)—— 使用说明:何时用、怎么注入、怎么配具体任务,读一遍即可,不必发给 AI。

## 一、它内置了什么(核心原则)

1. **痛点全覆盖是决策起点**:按用户角色、生命周期阶段、性质强度三个维度系统识别所有痛点,每条痛点带「角色+场景+描述+频率/严重度」;此后每个产品决策必须回链到痛点,无痛点支撑的功能会被主动质疑。
2. **易用性优先,优先用 AI 降低门槛**:以步骤数、学习成本、出错率衡量便捷性;方案按「自然语言交互 → AI 自动执行 → 智能推荐 → 个性化适配 → 传统 UI 优化」的次序思考,并警惕「为 AI 而 AI」。
3. **竞品分析与差异化优势**:主动做多维竞品竞争点分析;差异化须满足「用户可感知、相对难复制、与自身资源一致、可翻译成定位语与取舍准则」四条标准;不编造竞品事实。
4. **通用默认**:不限定行业;信息不足时先给 ≤5 个关键澄清问题,或按标注假设推进;输出结构化(先结论后依据)。

## 二、怎么注入(三种常见方式)

**方式 1 · 作为系统提示词注入(推荐,效果最稳定)**
把 `pm-preset.md` 的完整内容粘贴到模型的「System Prompt / 角色设定 / 预设」输入框中,然后正常对话。

**方式 2 · 作为对话首条消息注入(无系统框时)**
直接把 `pm-preset.md` 全文粘贴为你的第一条消息,并附一句:「请先确认你已理解以上角色与三条原则,然后等待我给出任务。」

**方式 3 · 做成常驻规则文件/技能(在本环境长期复用)**
把预设内容保存为规则或技能文件(例如本环境工作区根目录的记忆规则、或 `.dsh/skills/` 下的技能包),使每次会话自动加载,无需重复粘贴。

## 三、注入后如何下达任务(任务句式)

用 `pm-preset.md` 末尾的「任务启动句式」模板,一行说清四要素:

> 按产品经理预设工作:产品为【产品名称/一句话描述】,目标用户为【角色/人群】,当前阶段为【立项规划 / 功能优化 / 体验诊断 / 竞品分析 / 版本迭代】,本次要解决【具体目标或问题】。

示例:

- 「按产品经理预设工作:产品为**面向小团队的任务管理 Web 工具**,目标用户为**团队负责人与普通成员**,当前阶段为**功能优化**,本次要解决**提升新成员上手速度**。」
- 「按产品经理预设工作:产品为**订阅制在线文档**,目标用户为**知识工作者**,当前阶段为**竞品分析**,本次要解决**规划下季度差异化版本**。」

## 四、可选的追加约束(临时子句)

预设默认「通用场景」。如需临时收紧,可在任务句后追加子句,预设会自动服从(因为其工作规范要求以你的上下文为准):

- 限定行业/领域:「仅考虑【教育 / 金融 / 本地生活 / 医疗……】场景」
- 限定资源:「方案需适配【3 人小团队 / 6 个月 / 冷启动无数据】的约束」
- 限定输出:「只输出痛点清单 / 输出竞品对比表并给出差异化定位语 / 用优先级 P0-P2 排序」
- 限定用户群:「以【非技术背景用户 / 老年用户 / 海外用户】为重点」

## 五、各条原则失效时的判断信号(供你抽查预设是否真正生效)

- 它一上来就谈方案/加功能,而不是先给痛点清单 → 原则一未生效;
- 它给的功能建议没写「如何降低门槛、省去什么操作」 → 原则二未生效;
- 它谈竞品只列差异没给「定位语 + 取舍准则」 → 原则三未生效。

出现上述情况时,回贴预设原文并要求「重新按预设执行」即可纠正。

## 六、定制建议

- **想更精简**:只保留三部分原则正文并合并「通用工作方式」的前两条,即可得到轻量版。
- **想更正式**:可把原则一、二、三的输出扩展为固定模板(痛点清单表 / AI 易用性改造表 / 竞品对比矩阵 / 差异化定位陈述),形成方法论工作流版。
- **想限定某行业**:在「# 角色」段补一句「本预设长期用于【行业】场景」即可。
