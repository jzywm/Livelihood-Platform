### 裁定（用户 2026-09-20 选定 (a)，控制者已记录）

- **M1 不使用 `MANUAL_REVIEW`**：`4003` 与 `5002` 都是 **`status = FAILED`** + **`error_code = 对应码`**；
- **"已转人工"是 `4003` 这个码自带的语义**（`er.md:329` 逐字「4003 通道失败**已转人工**」），
  **不是**一个状态迁移；
- **"人工复核队列" = 运维按 `error_code` 的查询视图**（`WHERE status='FAILED' AND error_code='4003'`），
  M1 不新建队列表、不新增状态；
- **`MANUAL_REVIEW` 作为第四态保留在枚举与状态机里，M1 无触发者**，留给 M2；
  **如实登记为"M1 不使用"**，**MUST NOT** 在实现里给它编一个触发点。

**依据（为什么 (a) 与已定档文档完全自洽）**：`error_code` **两处**都被定义为「**FAILED** 业务码」，
`design.md:210` 也写「置 `FAILED` 并转人工复核队列」；选 (b)/(c) 都要反过来改这三处口径，
把一个"文档写明的失败态"改写成状态迁移——**那属于改文档迁就一种解释**，而不是按文档实现。

### 对本任务判据的影响（**因为这一定，§3 的第 2 条更简单了**）

- "分别计数" **不需要跨两个 status 聚合**：`WHERE status='FAILED' GROUP BY error_code` 即可；
- §3 第 1 条的"两码不混用"要**同时断言 `status='FAILED'`**（而不是断言 `MANUAL_REVIEW`）；
- **MUST NOT** 出现任何把任务置成 `MANUAL_REVIEW` 的新代码路径。

## 3. 判据形态（已按 §2 的裁定 (a) 收窄）

1. **两码不混用**：构造两条失败任务，一条以 `4003`（通道失败）结束、一条以 `5002`（依赖超时）结束；
   断言**两条行上的 `error_code` 各自正确且互不串**。
   **MUST NOT** 只断言"有 `error_code`"——那对"两个都写同一个码"的实现是绿的；
2. **分别计数**：对 `FAILED` 行 **`GROUP BY error_code`** 得到 `{4003: 1, 5002: 1}`
   —— **这就是"分别计数"的可验收形态**，**不需要等第 11 组**（`design.md:98` 的 Prometheus 指标属
   第 11 组"可观测性与健康检查"；指标只是**暴露方式**，事实源的分组能力现在就能验）。
   **并登记**：接指标时是把它做成 counter，本任务只保证事实源可分；
3. **降级不阻塞核心业务**：在"通道不可用"（mock 通道注入故障，或 `4003` 持续返回）期间，
   **新任务仍能受理**：`POST /aicore/ocr` 返回 `202` + `taskId`。
   `er.md:176` 要求「**原样流转**、AI 标记缺席**不阻塞**」⇒ 判据要断言**受理链路**不受影响，
   而不是只断言"失败任务变成了 FAILED"；
4. **`5002` 的路径要真的走"依赖超时"而不是复用通道失败**：`DependencyTimeoutError`（`5002`）
   与 `ChannelFailureError`（`4003`）在 `_handle_failure` 里取的都是异常自带的码
   （`Task 4.7` 已实现：`error_code` **取异常自带的 `AiCoreError.code`，MUST NOT 由执行器猜**）。
   判据要**分别触发两条异常路径**，不能让一条路径冒充另一条。

**判别力自证（MUST）**：把"两码分别落库"改成"都写死 `4003`"（内存变异 / 局部复制控制流），
第 1、2 条**必须变红**。只测"失败被记下来了"的判据对它是绿的。

5. **【机械判据·新增，因 §2 的裁定 (a)】没有任何代码路径会把任务置成 `MANUAL_REVIEW`**。
   `state.py` 里**定义**该常量、`ALLOWED_TRANSITIONS` **包含**它，都是合法的（它是 M2 的预留态）；
   要拦的是**把它当成写回目标**——即 AST 扫描 `src/`，断言 `MANUAL_REVIEW` **不出现在**
   `update_status` / `mark_failed` / `mark_succeeded` / `requeue` 之类**写回调用**的实参里。
   **为什么要机械化**：这是一条"**将来才可能被违反**"的约定——M2 接视觉审核时，
   最自然的动作就是顺手把 `4003` 接到 `MANUAL_REVIEW` 上，而那会**推翻本裁定**且没人会注意到。
