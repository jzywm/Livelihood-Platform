## 2. 核心设计（逐条对应权威源）

| 决策 | 依据 | 落地 |
|---|---|---|
| 6 种前缀 `task_`/`cor_`/`rev_`/`marker_`/`kan_`/`qa_` | `er.md` §5.4 L239–L245 | `ID_PREFIXES` 字典，**前缀自带下划线** |
| `merchant` **不发号** | `er.md` §5.4 L244「源服务生成，只读引用，不重新发号」 | `new_id("merchant")` 抛 `ValueError`，消息里点名该条款 |
| 总长 **≤32**，超限即抛错（非静默截断） | spec §5.8、`er.md` §5.4（所有 ID 列 `varchar(32)`） | hex 段长度 = `32 − len(前缀)`；生成后自校验，不符抛 `ValueError` |
| **不用雪花 / 无 workerId / 无时钟回拨** | `er.md` §5.4 L247 + spec §2.3 | 只用 `uuid4().hex`；用例有防回归断言 |
| 长度账只算一次 | —— | `_UUID_HEX_LENGTHS` 由 `MAX_ID_LENGTH` 与前缀现算，函数体里**无** `[:27]` 这类字面量 |

**为什么截断 UUID 安全（写进模块 docstring，不是权宜之计）**：UUID4 有 122 位随机性，
保留 100~116 位后按生日界，碰撞概率远低于同月分片表容量上限（`er.md` §5.2：>2000 万行才再分），
且唯一性**最终由数据库主键约束兜底**。两害相权：截断的风险是"概率极低的主键冲突"，
超长的风险是**每一行都写不进去**。

### 3.3 核心负向证据（"超限即抛"真的是活的）
```
monkeypatch.setattr(idgen, "MAX_ID_LENGTH", 10)
idgen.new_id("marker")  ->  ValueError（消息含「长度」）
```
没有这条，"超限即抛错"就只是文档里的一句话——而它正是 spec §5.8 点名的「最容易写错」处。

### 3.4 用例写错并修正的一处（登记）
防回归断言初版直接对**整份源码**做子串检查，结果在模块 docstring 里命中了 `workerId`
——而那段 docstring 恰恰是在**说明禁用理由**（`不会命中` 本该是文档的特权）。
**修法**：用 `tokenize` 剥掉注释与字符串字面量，**只对代码骨架发问**；
并加反向自检（剥离后必须仍能看到 `uuid4`，否则说明剥过头、断言变成空断言）。
**教训**：这类"防回归子串检查"必须区分"代码"与"文档"，否则要么误报、要么被绕过。
