## 2. 【控制者裁定】区间重叠：两档同时包含 `0.9` 与 `0.7`

**同一组数值被写成「高 ≥0.9、中 0.7~0.9、低 <0.7」，于是 `0.9` 与 `0.7` 各被两档同时包含。**
该口径出现在**三处**：`spec.md:58`、`er.md:63`（enum 描述）、`er.md:301`（§5.7，已标"✅ 已定档"）。

**裁定（照此实现，MUST NOT 自己另选一个）**：

```
HIGH   = c >= 0.9
MEDIUM = 0.7 <= c < 0.9
LOW    = c < 0.7
```
⇒ `0.9 → HIGH`、`0.899 → MEDIUM`、`0.7 → MEDIUM`。

**理由**：`er.md:63` 的 `HIGH≥0.9` 是**显式边界**，`MEDIUM0.7~0.9` 是**区间描述**；显式边界优先，
余下区间自然取半开。反过来（`0.9 → MEDIUM`）要改 `HIGH≥0.9` 才能自洽 ⇒ 那是**改文档迁就猜法**。

**执行要求**：三分**必须是一个纯函数**（不许散落成多处 `if`），"阈值可配"只影响**两个阈值**、
**不影响边界归属规则**。函数放 `service/task/`（业务语义），**不得 import 任何 provider 具体实现**
（契约 2；本函数只需要 `float`，不需要 provider 类型）。

## 3. 【裁定 + 一处"文档少写"】`confidence is None` 怎么办

`provider/results.py` 的模块 docstring **逐字要求**：`confidence` 用 `float | None` 是为了
**区分「没有置信度」与「置信度为 0」**；用 `0.0` 兼任两者会让"通道没给置信度"被判成 `LOW` 并转人工
——**"那是造假数据，不是兜底"**。

但**没有任何一份文档说"没有置信度"时该返回什么**（三处分级口径都只写有值的情形）
⇒ 这是典型的**"文档少写"**（本项目的教训："文档缺陷多数出在**少写**而非写错"）。

**裁定（照此实现）**：
- `confidence is None` ⇒ **不判级**（分级字段返回"无"，**MUST NOT** 返回 `LOW`）；
- 且 **`needs_manual_review = 1`** —— 依据 `er.md:40`「置信度**不足**转人工核验**兜底**」的**目的**：
  通道没给置信度 ⇒ AI 无法自证可靠 ⇒ 走兜底。
- **`MUST` 在 docstring 里写清这两件事的区别**：
  「把 `None` 当 `0.0` ⇒ 伪造出一个 `LOW`」**与**「`None` ⇒ 不判级 + 兜底」**语义不同**，
  前者造假数据、后者是保守兜底。
- ⚠ **若你读到的任何文档与本裁定冲突，停下报告**，MUST NOT 自行改文档迁就实现。

## 5. 判据形态

1. **边界三分**：`0.899 / 0.9 / 0.7` 各一条 **+ 各档内一个值**（如 `0.95 / 0.8 / 0.1`）——
   只测三个边界会让"把整段都判成 MEDIUM"的实现蒙混过关；
2. **`None` 的处置**：不判级 + `needs_manual_review=1`，且**断言它没有变成 `LOW`**；
3. **阈值可配**：改 `confidence_high` 后**边界随之移动**（同一份输入改配置后分级改变）；
   **判据要断言"移动"这件事本身**，不是只断言"读到了配置"；
4. **留痕**：**改阈值之前**提交的任务，其 `model_meta.thresholds` 快照**仍是旧值**
   ——这才是 `spec.md:128` 要的"当次快照"；**只断言"字段存在"不算留痕**；
5. **负向**：置信度 `MUST NOT` 被用作跳过人工确认的依据（`spec.md:58` 末句 + `:65-67` 场景）
   ——即"高置信度 **不** 等于免人工"，若实现里有任何"HIGH 就跳过复核"的分支，判据要能抓住它。

**判别力自证（MUST）**：把三分改成 `>=`/`>` 互换（或把边界写成闭区间），
第 1 条里**至少一条必须变红**；把"当次快照"改成"读当前配置"，第 4 条**必须变红**。
