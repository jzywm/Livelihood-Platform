# 需求收集 SOP 手册

> 版本：v1.0 · 2026-09-01
> 适用范围：本平台（民生综合服务平台）**所有新行业/新模块的需求收集**
> 配套：`模板/` 目录下 5 个可复用模板
> 来源：方案乙（手册+模板工具箱），并沉淀 11 行业实战经验

---

## 1. 目的

让每个新行业（如养老、私教、搬家……）的需求收集**标准化、可复制、不遗漏**：
- 一次走完 5 个阶段，产出完整档案
- 每份档案可直接并入《需求规格说明书》
- 避免问卷过长、你查项堆积、重复调研等已知坑

## 2. 流程总览（5 阶段）

```
阶段0 行业识别     → 确认行业边界与细分（模板①）
阶段1 桌面调研     → 痛点初判 + 公开数据佐证（模板①）
阶段2 用户访谈     → 角色化问题（模板②③，二选一）
阶段3 归档确认     → 回答归档 + 补充你查项（模板④）
阶段4 并入规格书   → 行业映射 + 优先级 + 更新总览（模板⑤）
```

**每一阶段的产出物** = 下一阶段的输入，最后全部汇入 `需求规格说明书-初稿.md` 与 `README.md`。

## 3. 各阶段详解

### 阶段0：行业识别
- **步骤**：确认行业名 → 列出细分（如教育培训 = K12/素质/职业/托育）→ 判断主管单位（市监/卫健委/教育局/人社…）
- **产出**：行业范围一句话 + 细分清单 + 主管单位
- **检查**：是否与已有 11 行业重叠？是否有明确民生痛点假设？

### 阶段1：桌面调研（≤1 轮检索）
- **步骤**：
  1. 写「痛点初判」：按角色列出（消费者/商户/员工/监管者，+特殊角色如司机、家长）
  2. 检索验证：每类痛点找 1-2 条公开实证（新闻/政策/案例），**只保留有据可查的**
  3. 查本地现状：试点城市（石家庄）该行业有无既有平台/数据源（如托育平台、黑白名单）→ **优先对接而非重造**
- **产出**：痛点初判 + 实证链接 + 本地数据源清单
- **检查**：每个痛点都有链接佐证？本地有无可对接系统？

### 阶段2：用户访谈（两模式二选一）
- **模式 A 问卷**（行业多、问题杂时）：用模板③，**≤15 题**，每题给选项+「你查/后定」逃生口
- **模式 B 对话访谈**（行业单一、需深挖时）：用模板②，按角色逐个问
- **关键原则**：
  - 问题必须**角色化**（问「老板最痛什么」而非「行业有什么问题」）
  - 每题附「你查/后定」选项，避免阻塞
  - **一次问清**，不反复打扰用户（教训：餐饮 6 问拖了 4 轮）

### 阶段3：归档确认
- 用户回答 → 写入 `归档文件`（模板④）
- 用户标注「你查」的 → 补桌面调研，**并注明是调研推断而非用户确认**
- 标注「后定」的 → 列入开放问题清单，不阻塞

### 阶段4：并入规格书
- 行业映射表新增一行（模板⑤）
- 功能点标注复用模块（如「复用 C1 专户结算」）或新增模块
- 更新 `README.md` 行业清单与进度
- **检查**：规格书版本号递增？README 进度同步？

## 4. 质量检查清单（收尾前逐项打勾）

- [ ] 行业档案文件编号规范（`NN-行业名.md`）
- [ ] 痛点均按角色分组，且至少有 1 条实证链接
- [ ] 本地（石家庄）有无既有系统已排查，能对接的不重造
- [ ] 用户「你查/后定」项有明确状态标记
- [ ] 行业映射行已加入规格书，模块编号正确（A/B/C/D/E/F/G/H/T）
- [ ] 优先级建议明确（P0/P1/P2），复用模块已标注
- [ ] README 行业清单、进度、对接清单已同步
- [ ] 版本号递增，变更摘要写入规格书头部

## 5. 已知坑与对策（实战沉淀）

| 坑 | 对策 |
|---|---|
| 问卷太长 → 用户疲劳 | 问卷 ≤15 题，选项化，给「你查/后定」逃生口 |
| 你查项堆积 → 档案不完整 | 归档时立即补调研，标注「调研推断」 |
| 重复调研（如本地系统未排查） | 阶段1 必查「本地既有系统」，优先对接 |
| 角色混问 → 答案不聚焦 | 问题严格按角色分组，一题一问 |
| 规格书版本混乱 | 每次并入后递增版本号，头部写变更摘要 |
| 功能点重复设计 | 先查模块清单，标注「复用 XX 模块」 |
