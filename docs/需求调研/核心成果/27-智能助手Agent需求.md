# 模块 J · 智能使用助手 Agent 需求（对话式平台助手）

> 状态：v1.1（2026-09-01 · v1.0 + 画像接入 J7）
> 定位：平台内置「使用助手 Agent」，帮助用户**会用、找得快、选得好** —— 使用指导 + 页面跳转 + 商品推荐 + **画像个性化**
> 归属：《需求规格说明书》**模块 J**（J1~J6 + J7 画像），优先级 **P0**，随 **M1 MVP**（PC Web）上线
> 依赖：I1 实名账户（登录态/个性化）、A3/T2 信用数据（推荐排序）、T1/T3 商品与溯源数据（推荐候选）、**J7 画像中心（`28`，个性化增强）**

---

## 1. 一句话需求

> 用户在平台任意页面可唤起对话式助手「**民生小助手**」（PC Web 侧边栏常驻，移动端后置），用自然语言完成三件事：**① 问怎么用（步骤引导）② 说要去哪（直接跳转）③ 说想买啥（透明推荐）**，全程数据脱敏、不出域、回答可解释。

## 2. 能力清单（J1~J6）

| 编号 | 能力 | 说明 | 关键约束 |
|---|---|---|---|
| J1 | **使用指导（FAQ + 步骤引导）** | 分角色知识库：消费者（怎么投诉/怎么看信用/怎么溯源）、老板（怎么入驻/怎么申诉/怎么发起工资代付）、供应商（怎么上架/怎么拿放心供应商标识）、从业人员（怎么实名/怎么查工资）、监管（怎么看待办预警） | 答案绑定平台流程与文档（`规格书` §4），不自由发挥；步骤式引导（第 1 步…第 N 步） |
| J2 | **页面跳转（意图导航）** | 自然语言 → 平台内部路由，如「我要投诉」→ D2 投诉页、「这家店信用咋样」→ A1 档案页、「我要发工资」→ I3 代付页 | **白名单路由表**（§5）；跳转前二次确认，防误跳；只跳平台内部页，不对外链 |
| J3 | **商品推荐** | 选品广场/溯源商品推荐：信用分 + 溯源完整度 + 价格 + 评价综合排序，**输出推荐理由（透明）**；支持「只看放心供应商」过滤 | 排序规则平台定，**不做竞价排名**；农资/医美等强监管品类只做信息推荐，不替代行政许可（红线同 T 模块） |
| J4 | **多轮上下文** | 会话内指代理解（如「这个」= 上轮推荐/上轮提及的商品），上下文随会话结束清理 | 会话超时（建议 30 分钟）自动清空，不留跨会话记忆 |
| J5 | **兜底与反馈** | 意图无法识别 → 回退 FAQ 关键词匹配 → 仍不行给人工入口（群众热线 G1 / 客服工单）；用户可对回答点「有用/没用」 | 反馈数据脱敏后用于知识库迭代（不用于训练第三方模型） |
| J6 | **内容安全与合规** | 输出内容安全过滤（涉政/色情/暴力/未成年人不当引导）；不编造事实，事实类回答绑定平台数据 | 与 §6 对话数据合规一致 |
| J7 | **画像个性化（接入画像中心，详见 `28`）** | 商品/信息推荐叠加画像权重（职业相关品类、价格敏感度、年龄适龄过滤）；个性化信息推荐（职业/年龄相关招工、培训、政策）；个性化使用引导（按角色与熟悉度） | 推荐理由标注画像依据；**价格不因画像差异化（不杀熟）**；用户可关闭/删除画像（四权）；未成年人不建行为/购买画像 |

## 3. 关键流程（对话 → 动作）

```
用户输入
  → 意图分类（四类：导航 / 推荐 / 使用问答 / 无法识别）
  → 导航：查白名单路由表 → 二次确认 → 跳转页面
  → 推荐：查候选商品（信用≥阈值 + 溯源完整 + 在售）→ 规则排序 → 生成推荐理由 → 展示
  → 问答：查分角色知识库 → 步骤引导回答
  → 无法识别：FAQ 关键词回退 → 人工入口兜底
全程：输入先脱敏（姓名/手机号/身份证/地址等）→ 调合规云 API → 输出过内容安全过滤 → 记录脱敏日志
```

## 4. 推荐逻辑（透明化，非黑盒）

- **候选集**：在售 + 供应商信用分 ≥ 阈值（建议 ≥ 80，对齐 T2 放心供应商门槛思路）+ 溯源信息完整
- **排序权重（建议初值，上线前评审确认）**：供应商信用分 40% + 溯源完整度 30% + 价格竞争力 20% + 消费者好评率 10%
- **画像增强（J7，叠加不替代）**：在规则排序基础上按画像微调 —— 职业相关品类加权、价格敏感度调整、年龄带适龄过滤；推荐理由标注画像依据；**画像不影响价格（不杀熟）**
- **推荐理由模板化**：如「该供应商信用分 92、溯源链路完整（农资批号→检测→温控→终端）、近 30 天好评率 98%，价格低于同品类均值 5%；根据你的职业（餐饮）为你优先展示食材类目」
- **不做**：竞价排名、付费置顶、虚假销量、基于画像的价格差异化

### 4.1 场景补充：澄清式导购（「不知道选哪个商品」，J3 扩展）

> 痛点依据:`25` 消费端 #8(用户新增 2026-09)——可选对象多、信息分散,用户说不出具体商品名、不知道选哪个;对应经营端选品痛点见 `20` §T1-补。

- **功能目标**:当用户表达"帮我选 / 不知道买什么 / 拿不定主意"等模糊意图时,由对话助手**追问澄清**（用途 / 预算 / 给谁用 / 在意的维度）→ 按回答**收敛候选**（信用分 ≥ 阈值 + 溯源完整 + 在售，规则同 §4）→ 输出**透明对比推荐**（候选 ≤ 5 个：信用、溯源、价格、好评各给理由与差距）→ 可一键跳选品页/商品详情（复用 J2 跳转）或继续多轮追问（J4）。
- **能力边界（继承 §4 / §6 既有口径，不新增收费与画像红线）**：
  1. 澄清问题**模板化、可跳过**：用户不答也给出按通用规则排序的候选，不臆断用户需求；
  2. **排序仍为规则排序（建议初值待评审）**，**不做竞价排名、付费置顶、虚假销量**；画像仅按 J7 授权叠加（职业/价格敏感/适龄），**价格不因画像差异化（不杀熟）**，用户关闭个性化后回退通用收敛；
  3. 推荐理由**模板化透明输出**，事实绑定平台数据，回答标注「平台助手生成，请以页面信息为准」（幻觉管控 J6）；
  4. 候选不足/无满足条件时**如实提示**（同 §10「暂无满足条件的商品」），不强行凑数；意图无法识别走 J5（FAQ → 人工入口）；
  5. 强监管品类（农资/医美等）只做信息推荐与核验提示，**不替代行政许可**；
  6. 对话数据合规继承 §6：脱敏前置、数据不出域、默认不沉淀、脱敏日志 ≤ 30 天；未成年人相关品类输出内容安全与年龄限制（J6）。
- **分期（归属明确，随 J3）**：M1 基础版 = 澄清话术 + FAQ 兜底 + 通用规则推荐（推荐为辅）；M2 增强 = 画像加权收敛、候选对比组件、与 T1 选品广场/B2C 下单链路打通。
- **验收提示（草案）**：输入「帮我选适合小饭店用的食用油」等模糊语句，助手能在 2 轮追问内给出 ≤5 个带理由候选并可跳转选品页；不出现竞价/付费置顶痕迹与无来源陈述。

## 6. 对话数据合规（红线，评审确认口径）

1. **脱敏前置**：调用云 API 前，对话内容去除姓名、手机号、身份证号、地址、银行账号等个人信息（正则 + 实体识别双层脱敏）
2. **数据不出域**：选用国内持牌大模型服务商（如通义/文心/智谱等，**已定 DeepSeek**），签署数据合规协议，明确数据不出域、不用于模型训练
3. **日志留存**：默认**不沉淀原始对话**；质量迭代仅留脱敏日志，留存 ≤ 30 天，到期自动删除
4. **内容安全**：输出过内容安全过滤；未成年人场景（娱乐/网吧等行业内容）额外敏感词与年龄限制
5. **可解释**：推荐给出理由，跳转给出确认，回答标注「平台助手生成，请以页面信息为准」（幻觉管控）

## 7. 非功能要求

- 端形态：PC Web 侧边栏常驻组件（三端基础覆盖：消费端深度优先，经营/监管端基础问答入口）；移动端后置
- 响应：对话首响 ≤ 3s（目标值，设计阶段确认）
- 可用性：对话服务随主站（≥99.5% 月度目标）；API 网关**限流防滥用**（按账号/频次），M1 试点期按量控制成本
- 可观测：脱敏日志 + 意图命中率 / 跳转成功率 / 推荐采纳率指标看板（监管端可见）

## 9. 与五词设计原则自检

| 理念词 | 落点 |
|---|---|
| 惠民 | 免费提供，降低学习成本，人人会用 |

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| API 成本不可控（按量计费） | M1 试点限流 + 用量看板 + 缓存高频 FAQ（规则库兜底，减少 API 调用） |
| 幻觉（编造流程/数据） | 事实类回答绑定平台数据与文档，模板化输出，标注「以页面为准」 |
| 合规（对话数据） | 脱敏前置 + 数据不出域协议 + 日志 30 天脱敏留存（§6） |
| 推荐数据基础薄弱（M1 期数据少） | M1 以「使用指导 + 跳转」为主、推荐为辅；推荐候选不足时明确提示「暂无满足条件的商品」 |
| 服务商审核/实名依赖 | 与支付通道同批推进（M0），双服务商备选 |
