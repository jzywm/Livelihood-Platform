## 二、🔴 高优先级缺口

### A1. 费率公开 ——「惠民」落点缺显性条目

- **依据**:`26` §2.5 惠民落点 = 免费推广(E2)/ 民生服务(G/H)/ **费率公开**;`25` 经营端重点「**费率公开是商户信任底线**」;规格书 §7.3 货运参照引用满帮教训「公开抽成」。
- **规格书现状**:仅 T4 一句「服务费率 = 成交额比例 0.5%~1% 分品类(已确认)」(L202);F 模块无「抽成公开」条目;§8 非功能无费率公示承诺。
- **建议**:在 §8 非功能(或 T4/I4/F 模块)补一条「费率与抽成对商户公开,公示口径与调整规则透明」;F 模块补「运费抽成公开」。
- **处置建议**:🔴 建议随下轮变更流程升版,或设计阶段作为平台承诺落实(影响面小)。
- **v1.6 落地**:✅ §8.1 新增「费率与抽成公开承诺」;T4 补「费率对商户公开公示(口径与调整规则透明)」;F 模块新增 **F5 费率/抽成公开**;验收 AC-M1.10。

### A2. 「录入 ≤1 分钟」量化指标未进规格书

- **依据**:`11-P0用户故事.md` L112「录入门槛 ≤1 分钟」;`25` L41「录入门槛 ≤1 分钟、扫码/拍照录入」;五词「方便」落点 = 操作轻量、一步完成。
- **规格书现状**:§8 非功能仅定性五词自检(L332),无该量化指标;验收 AC-M1.1 仅「试点商户 ≥200 家」。
- **建议**:§8.1/8.5 补充商户入驻/上架录入量化指标(≤1 分钟,PC Web 优先),挂到 AC-M1.1 验收。
- **处置建议**:🔴 低成本高价值,建议设计阶段细化时一并纳入(需规格书补一句量化描述)。
- **v1.6 落地**:✅ §8.1「一屏看清、一步可查」UX 基线 + §8.5 量化 UX 指标(录入 ≤1 分钟);AC-M1.1 增「入驻/上架录入 ≤1 分钟」。

### B1. 消费端痛点 7「娱乐场所未成年人进入」无对应功能(易混淆)

- **依据**:`25` 消费端痛点 7「娱乐场所未成年人进入(网吧最普遍,用户确认)」;规格书 §5 行业映射娱乐行业 = A1 A4 D2(L245)。
- **规格书现状**:**C2 防童工 = 防雇佣童工(经营端入职年龄核验),不是"未成年人进入网吧/娱乐场所"的消费端管控**;规格书无针对后者的功能(入场年龄核验 / A4 预警场景 / 举报类别)。
- **建议**:明确是否纳入:① 作为 A4 监管预警场景(网吧/娱乐场所未成年人违规入场预警),或 ② C 模块扩展「场所年龄管控」,或 ③ 显式声明 M1 不做(在 §6.2「M1 明确不做」清单中注明),避免评审被质疑"痛点写了但没落点"。
- **处置建议**:🔴 需用户拍板(纳入范围),建议作为下轮评审待确认项。
- **v1.6 落地**:✅ 用户拍板 = **轻量纳入**(2026-09-01):A1 一店一档标注「未成年人禁入承诺」+ D2 举报类别「未成年人违规进入」+ A4 预警场景「违规入场高频举报场所」;M1 即交付(AC-M1.9)。

## 三、🟡 中优先级

### A3. 价格公示随 B2 在 P1,M1 对"价格不透明"零回应

- **依据**:价格不透明/乱收费是**用户确认**的消费端痛点(规格书 §5:零售缺斤少两、住宿图文不符、美容效果不符、维修乱收费、婚庆隐形消费);`25` 消费端重点「透明可视化是核心价值」。
- **规格书现状**:价格公示挂在 B2「服务过程透明:后厨直播、维修报价单、价格公示」(L162),B2 在 P1;M1 明确不做 B2。
- **建议**:评审确认是否在 M1 提供「价格/报价公示基础版」(如 A1 一店一档内展示公示价、维修报价单模板),否则 M1 对"价格透明"无直接交付物。
- **处置建议**:🟡 需用户拍板,建议作为下轮评审待确认项。
- **v1.6 落地**:✅ 用户拍板 = **M1 价格公示基础版**(2026-09-01):A1 一店一档内展示商户自主维护价目表;维修报价单/后厨直播仍随 B2 在 P1;验收 AC-M1.8。

### B2. 经营端痛点 4「合规成本高、流程繁琐」无商户侧回应

- **依据**:`25` 经营端痛点 4「办证、年检、录入台账;中小商户无技术团队、数字化能力弱」。
- **规格书现状**:A4「资质临期」只推监管端(L158);K2 OCR 是平台侧降人工;商户端无「证照临期提醒 / 合规自查 / 年检提醒」。
- **建议**:A4 预警数据对称推送给商户端(商户自己看到资质临期、年检提醒),成本低、直接回应痛点 4,也落「方便/惠民」两词。
- **处置建议**:🟡 建议设计阶段细化(可并入 A4 预警或 I 账户中心),需规格书补一句商户端推送。
- **v1.6 落地**:✅ A4 监管预警改为**双向推送**:资质临期/年检提醒同步推送商户端(§4 模块 A)。

### B3. 监管端痛点 4「小摊小贩/三小难覆盖」未显式处理

- **依据**:`25` 监管端痛点 4「流动性经营、取证后执行难」;石家庄"三小"(小餐饮/小作坊/小摊贩)整治是本地重点。
- **规格书现状**:试点行业只有固定商户(餐饮/零售/家政),未提摊贩/流动经营者登记;§6.2「M1 明确不做」清单也未声明。
- **建议**:可能是有意裁剪(M1 聚焦 3 行业),但应在 §6.2 明确不做清单中**显式声明"三小/摊贩不在本期"**,或在 P2/P3 预留「流动经营者登记」扩展位,防止范围边界被挑战。
- **处置建议**:🟡 需用户确认(裁剪声明 or 预留扩展),建议作为下轮评审待确认项。
- **v1.6 落地**:✅ 用户拍板 = **裁剪声明 + 预留扩展位**(2026-09-01):§6.2「M1 明确不做」加「三小/摊贩登记」,P2(P3)预留「流动经营者登记」扩展位;规格书 §10.3 遗留执行项登记。

### C1. 缺「模块 ↔ 三端」映射矩阵

- **依据**:`25` 按端组织痛点(消费端/经营端/监管端);规格书按模块 A~K 组织,但无「哪个模块在哪个端呈现什么」的映射。
- **规格书现状**:§8.2 仅一句「三端形态:消费端(Web/后续移动)、经营端(Web)、监管端(Web 看板)」(L337)。
- **建议**:附录加一张三端 × 模块矩阵(如:消费端 = A1(脱敏)/A2(授权)/A3/B2/B3/D2/E2/J/K3…;经营端 = A1/A2/A3/C/D3/E2/E3/F/T/I/J/K2;监管端 = A4/B3/D2/G/H/K1/K4…),设计阶段页面规划直接需要。
- **处置建议**:🟡 建议设计阶段产出(不必须改规格书,可在设计文档给出;若冻结需要则走变更)。
- **v1.6 落地**:✅ 规格书**附录 C 新增三端 × 模块映射矩阵**(A~K 全模块 × 消费/经营/监管端),设计阶段页面规划直接输入。

### C2. 「一屏看清、一步可查」UX 要求未显式化

- **依据**:`25` 消费端重点「信息要'一屏看清、一步可查',不能藏在多级菜单里」;`25` 经营端重点「录入门槛 ≤1 分钟」。
- **规格书现状**:§8.1 仅「五词贯穿所有功能设计……对照自检」(L332),无显式 UX 条目。
- **建议**:§8.1 或 AC-M1.5 显式化(如「消费端核心信息一屏可查、投诉 ≤3 步完成;商户录入 ≤1 分钟」)。
- **处置建议**:🟡 与 A2 合并处理,设计阶段纳入。
- **v1.6 落地**:✅ §8.1「一屏看清、一步可查」UX 基线显式化;AC-M1.5 增「消费端核心信息一屏可查、投诉 ≤3 步完成」。
