## 0. 阅读说明（先读这段）

### 0.1 本文与 J7「平台内个人画像」的区别

| | 本文（用户画像 / Persona） | J7 平台内个人画像（`28`） |
|---|---|---|
| 是什么 | **设计用**典型用户描述（虚构人物卡） | **系统功能**：真实用户标签数据模型 |
| 用途 | 指导产品设计、评审、对齐 | 支撑个性化推荐 / 引导（M1 基础版） |
| 用户 | 不一定是平台注册用户 | 平台实名用户 |

两者不冲突：本文描述「为谁设计」，J7 描述「系统如何认识真实用户」。J7 的合规红线（不杀熟、未成年人不建画像、用户四权）与本文人物画像的「目标用户特征」无冲突——本文人物均假设为成年人或由成年监护人代操作的场景。

### 0.2 证据 / 推断标注

- **[证据]** = 已由调研/问卷/公开案例确认的事实（标注来源文档）
- **[推断]** = 基于调研合理外推的典型化细节（年龄、家庭、心理），**未经真实用户访谈验证，待用研确认**（见 §5 待验证清单）

### 0.3 人物为虚构合成

以下人物均为「画像角色」，由调研材料合成，不代表任何真实个人。年龄、城市、职业背景为合理推断，用于帮助团队共情。

#### P1 「买菜掌勺的宝妈」—— 全家饮食与日常消费的决策者

**一句话画像**：35 岁石家庄宝妈，管着一家老小的吃穿用度，最怕「看不见的脏」和「说不清的坑」，买东西认「看得见的证明」。

**基本档案（[推断]** 合成细节）
| 项 | 内容 |
|---|---|
| 姓名/年龄 | 王女士，35 岁 |
| 城市/家庭 | 石家庄市区，二孩家庭（大宝 8 岁，小宝 3 岁） |
| 职业/收入 | 全职/半职妈妈，家庭月消费大头在吃饭、孩子、家政 |
| 数字能力 | 中上：会用微信/抖音/点评，会扫码付钱，不擅长复杂表单 |
| 典型场景 | 早市/菜场买菜、周末带孩子下馆子、给小宝请钟点工、给大宝报班 |

**核心目标**
- 给孩子和家人吃到**干净、安全**的东西，不被「预制菜冒充现做」糊弄
- 花钱明白：不缺斤少两、不乱收费
- 遇到问题**有个地方能投诉、且真有人管**

**痛点（证据）**
| # | 痛点 | 依据 |
|---|---|---|
| 1 | 后厨看不见、食材来路不明：地沟油/过期食材/预制菜冒充现做，只能「赌运气」 | [证据] `01-餐饮.md`、`25` 消费端#1 |
| 2 | 零售缺斤少两是本地更常见的事 | [证据] `12-用户问卷.md` Q13（用户确认） |
| 3 | 家政/育儿服务怕履历造假、人不靠谱 | [证据] `12-用户问卷.md` Q27：请保姆最怕履历造假；`06-家政.md` |
| 4 | 给孩子报的班（早教/兴趣班）怕机构跑路、退费难 | [证据] `16-教育培训需求调研.md`：预收费跑路高发（推断关联到其场景） |
| 5 | 投诉无门、差评无用、打了 12345 没人管 | [证据] `25` 消费端#5（9/9 行业共性） |

**行为模式**
| 环节 | 现状行为 [证据+推断] |
|---|---|
| 选店 | 先看点评/小红书/妈妈群口碑 → 看得见证照卫生的店加分（[推断] 其信息渠道）；本地真实案例会让她「绕道走」（如面馆腐烂西红柿停业整顿 [证据] 调研README） |
| 消费中 | 买菜习惯自己复秤；点外卖会挑「感觉正规」的店，但后厨到底干不干净看不见（[证据] 后厨不可见） |
| 遇坑后 | 先差评/群里吐槽 → 或打 12345 → 多数不了了之，「算了，下次不去」[推断]；极少走到工商流程 |
| 工具习惯 | 微信小程序/扫码是舒适区；打字长表单、上传一堆材料会觉得麻烦 |

**平台机会点与设计启示**
- **查询型需求**：A1 一店一档「一屏看清证照/处罚/抽检/投诉率」+ T3 溯源扫码 → 满足「看得见的证明」
- **投诉型需求**：D2「傻瓜式投诉」（选商户 → 选类别 → 传证据 → 看进度）+ G1 直达政府进度可见 → 回应「投诉有回音」
- **推荐型需求**：J3 商品推荐给「信用分+溯源完整度」的透明理由；J7 画像提供个性化（注意：价格不因画像差异，避免杀熟 [证据] `28`）
- **设计要点**：查/诉/扫主路径一步到位，别藏多级菜单（`25` 消费端重点关注）；录入证据要「拍照即传」，操作 ≤1 分钟心智

#### P2 「退休在家的张大爷/张阿姨」—— 银发消费者：最易被坑、最不会维权的一群人

**一句话画像**：68 岁退休老人，常去早市、社区店和理疗/足疗店，容易信熟人推销，吃亏了也说不清楚、投诉不动。

**基本档案（[推断]）**
| 项 | 内容 |
|---|---|
| 姓名/年龄 | 张大爷，68 岁（或张阿姨 65 岁），退休 |
| 城市/生活 | 石家庄老城区，日常早市买菜、社区理疗/足疗/美容体验、去小饭馆 |
| 数字能力 | 弱：会用手机打电话、微信语音/视频，看不懂复杂界面，不敢乱点，怕被骗钱 |
| 典型场景 | 早市买菜复秤无门、被「免费体验」拉进店办卡充值、足疗卫生担心 |

**核心目标**
- 不被骗：不买无效保健品、不办「跑路卡」、不被乱收费
- 简单：有人能替我把「这店靠不靠谱」查清楚（自己查不动）
- 安心：出了问题有人管，而不是「算了算了」

**痛点（证据）**
| # | 痛点 | 依据 |
|---|---|---|
| 1 | 预付卡/充值跑路重灾区：美容健身、零售等（石家庄实证：玥庭养生SPA 充值 5000 失联、永琪美容闭店） | [证据] `07-美容美发健身.md`、调研README 石家庄案例 |
| 2 | 缺斤少两、乱收费难察觉：复秤不便、看不懂价目 | [证据] `25` 消费端#2；Q13 缺斤少两（零售） |
| 3 | 足疗按摩卫生更让人担心（娱乐行业问卷确认） | [证据] `12-用户问卷.md` Q34 |
| 4 | 被坑后不会投诉：流程复杂、不会上传证据、怕麻烦/怕被报复 | [推断] 基于 `25` 消费端#5 投诉无门共性 + 数字能力弱 [推断] |
| 5 | 对「证照/处罚/抽检」等公示看不懂、不知道去哪看 | [推断] 数字能力弱 + `25`「信息一屏看清」要求的反面 |

**行为模式**
- 信息渠道：熟人推荐、社区/广场舞圈子、电视报纸 > 线上口碑 [推断]
- 决策特征：重人情信任，「熟人开的店」不太设防；易被「免费体验+情感销售」打动 [推断]
- 被坑后：常自认倒霉；子女代投诉是主要路径 [推断]
- 工具习惯：需要**大字、语音、一键直达**；个人操作投诉类功能吃力，倾向「家人代办 / 电话热线」

**平台机会点与设计启示**
- **查档前置**：A1 一店一档应对银发高频场景（理疗/足疗/菜店）可查证照与黑榜 → 子女先查、老人放心
- **风险提示**：D1 预付卡风险提示（M2）对办卡场景直接预警
- **代办/家人模式**：画像提示「银发用户常由子女代办」→ 设计考虑家人授权代办、热线兜底（G1 电话工单）
- **傻瓜式投诉**：D2 需极简步骤；文字可以少，图标/语音引导要多；公示结果要「看得懂的大白话」

**核心目标**
- 外卖/堂食不踩雷：出问题快速赔付/处理

| # | 痛点 | 依据 |

| 3 | 办卡跑路有案例，退费难 | [证据] Q30 + 石家庄实证案例 |

- 选店路径：外卖/点评榜单 → 看差评与图片 → 下单 [推断]

- T1 选品广场（M2+）对其延伸价值：装修/维修材料透明比价
- 画像注意：年轻用户对「政府背书平台」初期可能有「会不会很政务、很难用」的预设 → 产品观感需轻、快、像消费产品（[推断] 设计启示）

### 2.4 监管端

#### P9 「市监所的小周」—— 基层监管人员：看得见、管得动、取证易、有预警

**一句话画像**：33 岁区市监所执法人员，管一片辖区的餐饮+零售，人手少、活多、取证难，做梦都想要「数据帮我看店、证据帮我执法」。

**基本档案（[推断]）**
| 项 | 内容 |
|---|---|

**行为模式**
- 巡查：按计划抽查、接投诉到店检查；记录靠拍照+纸质/Excel [推断]

- 用系统：政务内网系统多而旧，数据录入重复 [推断]

**平台机会点与设计启示**
- A4 监管预警（高频投诉/资质临期/异常经营/欠薪/溯源断链自动推送 + 分级监管：低分多查、高分少查）→ 他的核心价值（`25` 监管端）

- K1 视觉合规审核（M2）+ K4 风险预测（M3）→ AI 初筛人工复核（合规红线：AI 只辅助，执法人工确认 [证据] 规格书 C8）
- 设计要点：监管端是「看板 + 工单 + 证据包」产品形态；警惕重复录入（与现有系统协同而非替代）；对接不可接 → 数据靠商户申报+平台巡检+群众举报双轨积累（`21` 风险4）
- **双视角需求**（§5 #6 落地·代理定稿）：**一线执法员（网格员）** 侧重「单店证据包 + 现场可查 + 录入轻 + 预警到人」——A1 档案调取、B/T 存证出证、D2 工单办理；**科室领导** 侧重「片区/行业态势看板 + 办结率考核 + 分级监管分配 + 上级检查材料」——A4 预警汇总、G3 限时办结、B3 抽检公示与红黑榜
- **一线录入意愿**（§5 #6 落地）：愿意日常录入，但必须**从轻**——拍照 + 字段选择替代填表，与现有系统协同而非重复录入；数据来源「商户申报 + 平台巡检 + 群众举报」双轨（与 `21` 风险4 一致）

## 3. 跨角色洞察：行为模式共性（对设计最有价值的部分）

### 3.1 数字化能力分层 → 决定交互复杂度

| 分层 | 代表 | 能力 | 设计对策 |

### 3.2 三类「被坑路径」的共性缺口（9/9 行业投诉共性）

- 消费端共性路径：**选店靠口碑盲猜 → 消费中无凭据 → 被坑后投诉无门 → 不了了之** → 平台用「查档（A1）→ 留痕（B/T）→ 投诉直达（D2）→ 结果公示」闭环补上每一环
- 经营端共性路径：**怕多花钱 → 怕被讹 → 怕麻烦** → 平台用「免费+信用加权（E2）→ 申诉+证据留存（D3）→ 轻量入驻（K2/≤1min）」逐项破防
- 监管端共性路径：**看不见 → 查不实 → 管不动** → 平台用「档案+溯源（A1/B）→ 存证出证 → 预警分级监管（A4）+ 工单考核（G3）」承接

### 3.3 ⚠️ 端形态冲突点（移动后置 vs 行为惯性，建议设计期拍板）

- 用户已确认 **PC Web 优先（先 Web 后套壳桌面），移动端后置**（`21` §2.3、`25` v1.1）
- 但 P1/P2/P3/P6 的核心行为——**现场扫码溯源（T3）、拍照传证据投诉（D2）、零工找活（E3/I5）、司机接单看位置（F）**——天然发生在手机上
- 设计提示：M1 建议明确「PC Web 为主体 + 手机浏览器响应式兜底 / 扫码跳转落地页」的折中方案，否则「傻瓜式投诉」与「PC 优先」会打架（[推断-设计启示]，需用户拍板）
- 本地配送（M2）同理：下单「GPS 定位 + 地图选点」与配送跟踪「骑手实时位置」天然发生在手机端；PC Web 优先下需以「网页端地图选点 + 手机定位兜底」折中（[推断]，随 M2 设计期拍板）

## 5. 待用研验证清单（本画像的「推断项」集中区）

> 以下内容为画像构建中的**推断**，建议在用户研究/可用性测试阶段按优先级验证，验证后回填本文。

1. **消费者画像分层是否成立**：宝妈/银发/年轻白领三类划分、各自占比与场景（尤其石家庄本地家庭结构）
   ✅ 已落地：新增 P10「学生」画像卡（消费端第四类），消费端痛点同步扩展（培训贷、兼职/暑期工、校园三小、预付卡等）→ 见 §1 总览、§2.1 P10
2. **银发用户的代办/家人模式**：是否普遍由子女代办？是否接受授权代办设计
   可以
3. **商户入驻动机排序**：免费推广 vs 不被讹 vs 录入省事，哪个是入驻第一驱动力（冷启动 200 家关键）
   免费推广
4. **从业人员（家政/零工）对平台信任度**：会不会怕「平台把自己管起来」而抵触实名/打卡
   会
5. **货运司机对 F 模块的接受度**：位置实时可见是否被接受（隐私与「被监控」顾虑）
   可以被接受
6. **监管端使用场景**：一线执法员 vs 科室领导，看板需求差异；是否愿意日常录入巡检数据（数据来源双轨）
   ✅ 已落地（代理定稿）：一线执法员=单店证据包+现场可查+录入轻+预警到人；科室领导=态势看板+办结考核+分级监管+上级检查材料；数据双轨=商户申报+平台巡检+群众举报，一线录入从轻 → 见 §2.4 P9
7. **端形态冲突**（§3.3）：移动后置下消费端扫码/拍照投诉的兜底方案
   可以
8. **未成年人边界**：消费端是否需要「家庭模式/儿童账号」还是仅做禁入与举报（注意 J7 红线不建未成年画像）
   仅做禁入和举报
9. **本地配送（L 组）推断项**：骑手画像是否与货运司机 P8 同质（是否单独成卡）、配送费计价与配送范围口径、消费者「点外卖/即时达」习惯是否真接入平台、骑手端上线时点——均待 M2 设计期用研验证（本次仅速览，不单独成卡）
