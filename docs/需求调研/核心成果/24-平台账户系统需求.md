# 平台账户系统需求 · 实名账户 + 钱包记账 + 劳务信用

> 目的：新增平台核心账户体系 —— 解决**求职工作者 ↔ 老板之间的劳务信用问题**，工资与商品购买均在平台账户体系内进行
> 状态：v1.1 · 已通过 2026-09-01 需求评审（已冻结，并入规格书 v1.7）
> 用户决策（2026-09-01）：① 石监码/银行专户/12345 **均不可对接**；② **先做 PC 端**（先 Web 后套壳桌面）；③ 建设平台账户系统（方案1 轻量合规：资金走第三方持牌通道，平台不沉淀资金）

---

## 1. 定位与核心诉求

### 1.1 要解决的问题
1. **劳务信用缺失**：求职者怕老板欠薪、老板怕员工拿了预支/货款跑路、双方互不信任
2. **工资无保障**：欠薪事后追讨难（石监码/银行专户/劳动监察对接均不可行，需自建机制）
3. **交易无凭证**：工资与商品购买没有平台留痕，纠纷无证据

### 1.2 平台账户体系（一句话）
> 每个实名用户拥有**平台账户**（记账式钱包），工资发放、商品购买、劳务结算都在账户内留痕；**资金实际结算走第三方持牌支付通道**（微信支付/支付宝/聚合支付），平台只记账不碰钱，规避二清合规风险。

### 1.3 核心原则（合规红线）
- **平台不沉淀资金**：不设资金池、不做代收代付的"二清"，资金流转必须由持牌机构完成
- **记账与支付分离**：平台账户 = 账本 + 信用记录；真实资金 = 第三方通道（微信商家转账到零钱 / 支付宝转账 / 聚合支付）
- **强实名**：所有账户实名认证（**已确认 2026-09-01：仅走微信/支付宝实名信息回传，不接受人工证件核验降级**；身份证+人脸由第三方通道完成）
- **工资优先**：工资发放优先级高于货款结算（延续"先发工资后结货款"原则）

## 2. 账户体系结构

### 2.1 账户类型

| 账户类型 | 使用者 | 说明 |
|---|---|---|
| **个人账户（工作者/消费者）** | 求职工作者、消费者 | 实名 + 身份认证；绑定本人微信/支付宝收款；工资入账、消费支出、劳务互评 |
| **商户账户（老板）** | 商户（雇主/卖方） | 实名 + 营业执照；绑定对公/法人收款；发工资、收货款、采购支出 |
| **供应商账户** | 供应商（T 模块） | 实名 + 资质核验；收货款、供货结算（联动 T2 信用） |
| **平台结算账户** | 平台运营方 | 对接第三方支付商户号（微信商户号 + 支付宝商户号或聚合支付），仅作为**过账通道**，不沉淀资金 |

### 2.2 账户资金流（关键设计）

> ⚠️ **合规红线澄清**：平台账户「钱包」是**纯记账簿（账本）**，不是资金钱包——平台**不保管、不沉淀任何真实资金**。真实资金始终在持牌机构（微信/支付宝/银行）账户内，代付/分账由持牌机构直接从**付款方绑定账户**划转，平台仅记录流水。

```
工资发放（工作者 ↔ 老板）：
  老板发起发薪 → 平台校验用工/考勤记录 → 持牌机构从老板绑定账户(对公/法人)代付 → 工作者收款(平台记账 +X)
  平台角色：记账 + 信用记录；真实资金在持牌机构账户内划转，平台不碰钱

商品购买（消费者/商户 ↔ 商户/供应商）：
  买方下单付款 → 第三方通道收款(资金在持牌机构账户) → 验收通过 → 分账(货款→卖方、服务费→平台)
  平台角色：下单/验收/确认后触发分账；平台仅收服务费分润
```

### 2.3 记账流水（平台账本）
每条资金操作生成**平台流水**：流水号、类型（工资/货款/退款/服务费）、双方账户、金额、关联订单/用工、第三方通道交易号、时间戳、存证哈希
→ 流水即证据：劳务纠纷、交易纠纷以平台流水为凭证（出证能力）

## 3. 功能需求

### 3.1 实名认证与账户开通
- 作为**用户（工作者/老板/供应商/消费者）**，我想实名注册开通平台账户，以便参与工资结算与交易
- 实名方式（**已确认 2026-09-01：仅微信/支付宝实名信息回传，不接受人工证件核验降级**）；若第三方实名不可用，则该流程暂停（影响入职/注册）
- 绑定收款方式：微信收款（推荐）/ 支付宝 / 银行卡（代发通道决定）

### 3.2 劳务信用（工作者 ↔ 老板 双向互评）
- 作为**工作者**，我想看到老板的**用工信用**（历史发薪履约率、是否欠薪、评价），以便决定是否入职
- 作为**老板**，我想看到工作者的**履约信用**（出勤/质量/有无纠纷），以便放心用工
- 作为**平台监管**，我想基于劳务信用分对失信老板/工作者预警（低分限制发布岗位/接单）

**劳务信用分构成（已确认 2026-09-01）**
- 老板侧：发薪履约率 40% + 纠纷率 20% + 用工评价 20% + 资质合规 20%
- 工作者侧：出勤履约 40% + 纠纷率 20% + 雇主评价 20% + 实名可信 20%
- 联动：老板信用分并入 A3 全域信用；工作者信用并入 A2 一人一档

### 3.3 工资保障（自建机制，替代银行专户）
- 作为**工作者**，我想工资按时足额到账，平台记录发放，欠薪有证据可追
- 作为**老板**，我想规范发薪记录，信用加分，避免纠纷
- 作为**平台监管**，我想看到欠薪预警（应发未发）并协助追讨

**落地模式（银行专户不可接后的替代方案）**
> 背景：原方案对比过「模式甲：银行工资专户托管（资金池，门槛高，银行不可接）」与「模式乙：打卡+举报直达（事后补救）」。银行不可接后，采用升级版 **模式丙（已确认）**：
- **模式丙（已确认）**：**平台代付留痕 + 欠薪预警 + 证据出证** —— 工资由持牌机构从老板绑定账户代付（微信商家转账到零钱），平台全量留痕；应发未发自动预警，欠薪证据（流水+用工记录）一键打包供劳动仲裁/监察使用
- 说明：原 C1 银行专户托管不可行（银行专户不可对接），升级为"代付留痕+证据链"模式；"先发工资后结货款"在分账模式下由结算顺序保证

### 3.4 商品购买（平台内交易）
- 作为**买方**，我想在平台下单付款，货款分账给卖方，平台留痕可查
- 作为**卖方**，我想货款有保障、按时到账（联动 T4 担保交易）
- 支付方式：微信支付 / 支付宝（第三方通道收款），平台触发分账

### 3.5 劳务结算（灵活用工，已确认 2026-09-01：日结/周结/月结都支持）
- 作为**老板**，我想按日结/周结/月结给临时工结算（零工场景，三种频率均支持）
- 作为**工作者**，我想随时查看应结未结金额与发放进度
- 结算触发：老板发起 → 平台校验（用工记录/考勤）→ 第三方代付 → 双方确认 → 计入劳务信用

## 4. 关键流程

### 4.1 工资发放全流程
1. 老板在平台发起发薪（选员工/金额/周期）→ 平台校验用工/考勤记录（**钱包仅记账，不设资金余额**）
2. 平台调用持牌机构代付（微信商家转账/支付宝转账）→ 资金**从老板绑定的对公/法人账户**划转至工作者 → 实时/批量
3. 工作者收款确认 → 平台生成流水 → 更新双方劳务信用（老板发薪履约率 +）
4. 应发未发（超时）→ 欠薪预警 → 平台协助（证据打包/催办/仲裁协助）

### 4.2 商品购买全流程（T4 联动）
1. 买方下单 → 第三方通道收款（货款托管于持牌机构）
2. 卖方发货 → 买方验收（T4 流程）
3. 验收通过 → 平台触发**分账**：货款→卖方、服务费→平台（持牌机构执行）
4. 交易完成 → 流水留痕 → 更新 T2 供应商信用

### 4.3 劳务互评流程
1. 用工关系结束/发薪完成 → 双方互评（履约/态度/质量，可附证据）
2. 评价计入劳务信用分 → 红黑榜联动（A3）
3. 恶意差评申诉（复用 D3 机制）

## 5. 非功能需求

- **合规**：平台不沉淀资金、不做二清；资金全部由持牌机构结算；服务费收取合规（需持牌或与持牌机构分润）
- **安全**：支付/工资数据加密；防刷单防作弊（同 IP/设备高频异常拦截）；代付风控（金额/频率异常人工复核）
- **实名**：全员实名（**仅微信/支付宝实名信息回传，已确认不接受人工证件核验降级**）
- **存证**：每条流水时间戳+哈希存证，可出证供劳动仲裁/执法调取
- **PC 端优先**：先 Web 应用（浏览器访问），后续套壳 Windows 桌面程序；移动端后置
- **对接**：微信支付商户号 / 支付宝商户号 / 聚合支付服务商（持牌），需营业执照+对公账户申请
- **可扩展**：未来若获得银行/政务通道，账户体系可平滑切换（记账层不变，通道层替换）

## 6. 第三方支付通道可行性评估（2026-09-01）

### 6.1 评估结论
| 通道 | 用途 | 申请条件 | 可行性 |
|---|---|---|---|
| 微信支付「商家转账到零钱」 | 工资/劳务代发 | 企业商户号 + 营业执照 + 对公账户；需开通经营资质 | ✅ 高（官方产品，见[文档](https://pay.wechatpay.cn/doc/v3/merchant/4012064660)） |
| 支付宝转账/分账 | 货款代收付/分账 | 企业商户号 + 营业执照；分账产品需资质审核 | ✅ 高 |
| 聚合支付服务商（持牌） | 微信+支付宝统一接入 | 营业执照 + 行业资质；服务商代进件 | ✅ 中高（备选，降低微信/支付宝直签门槛） |
| 银行聚合支付/代发 | 对公代发工资 | 对公账户 + 银行合作 | ⚠️ 低（**当前不可用：银行通道不可接**，仅作未来可扩展项保留） |

### 6.2 二清合规红线（必须遵守）
- 平台**不得**：先收款入平台账户再分给商户/个人（= 二清，违法）
- 平台**应**：用持牌机构分账产品（微信分账/支付宝分账/银行存管+分账），资金在持牌机构账户内按规则划转（参考[分账系统规避二清](https://www.eshutong.com/archives/24140.html)、[银行存管结合](https://www.eshutong.com/archives/13274.html)）
- 平台服务费：通过分账比例收取（**已确认 2026-09-01：按成交额比例 0.5%~1% 分品类**），不碰商户货款
