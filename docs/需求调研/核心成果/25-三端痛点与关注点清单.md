## 一、消费端(消费者 / 群众)

### 痛点
1. **食品安全与卫生不可见**:地沟油、过期食材、预制菜冒充现做、后厨看不见(01-餐饮;石家庄面馆腐烂西红柿案例)→ 消费者只能"赌运气"。
2. **价格不透明、被乱收费**:缺斤少两(用户确认,零售)、维修乱收费(用户确认)、订房图文不符(用户确认)、婚庆隐形消费(用户确认)——价格欺诈跨行业普遍。
3. **预付卡/充值跑路、退费难**:美容健身、零售、餐饮、住宿 4 大行业共性;石家庄「玥庭养生SPA充值5000失联」「永琪美容闭店」为本地实证。
4. **资质/履历造假导致服务不可信**:家政履历造假(用户确认)、黑中介套路(用户确认"都有")、医美材料百亿灰色流通——"人"和"货"都可能造假。
5. **投诉无门、处理慢、无反馈**:**9/9 全行业共性痛点**,差评无用、12345 打了没人管。
6. **效果不符、虚假宣传**:健身/美容效果不符(用户确认)、刷单好评、1688 类平台假货骗局(选品采购场景)。
7. **特定人群风险**:娱乐场所未成年人进入(网吧最普遍,用户确认)、足疗卫生、医美材料无注册证。
8. **不知道想要选择哪一个商品(选择困难、决策成本高)**(用户新增痛点 2026-09):同品类/同场景可选对象多,但证照、信用、价格、评价、溯源等信息分散,消费者缺少「按自己的用途/预算/给谁用把候选收敛到可信小范围、再逐项对比」的工具 → 凭感觉或熟人推荐下单,选错风险高;数字能力弱人群(如银发)更甚(`31` 画像[推断]:看不懂公示、不知去哪看)。→ 平台能力落点:J3 商品推荐(透明理由)+ **澄清式导购(`27` §4.1)** 收敛候选 + J7 画像辅助收敛与个性化;选购链路随 B2C 延伸(规格书 §2.2/`20` T1)。

### 项目重点关注(消费端)
- **D2 投诉直达 + 进度可见是全平台最大共性需求,必须做好**:一键提交、证据上传、商家限时处理 → 升级市监 → 结果脱敏公示,全程进度可视化——这是消费端留存和信任的基石。
- **透明可视化是核心价值**:一店一档(A1)把证照/处罚/抽检/投诉率摊开给消费者看;T3 溯源二维码扫码验真;价格公示。**信息要"一屏看清、一步可查"**,不能藏在多级菜单里。
- **消费端体验必须轻量**:查询/扫码/投诉是主路径,**PC Web 优先**(先 Web 后套壳桌面,移动端后置),投诉操作要"傻瓜式"(选商户 → 选类别 → 传证据 → 看进度)。
- **强监管品类(农资/医美)对消费者的信息核验要显著提示**(只做核验公示,不能误导为官方认证)。
- **"不知道选哪个"要"问得出、比得清"**(对应痛点 #8):在 J3 透明推荐基础上补**澄清式导购**——用户说"帮我选/不知道买什么"时,助手反问用途/预算/给谁用等 → 收敛候选 → 按信用/溯源/价格/评价透明对比并给理由(详见 `27` §4.1);保持**非竞价、不杀熟、候选不足如实提示、脱敏不出域**等既有边界。

## 二、经营端(商户老板 / 供应商 / 从业人员)

### 痛点
1. **平台抽成高、获客贵、被平台绑架**:外卖平台抽成、家政中介抽成高、货运平台被约谈(满帮抽成、司机挣得少)——经营端对"流量平台"普遍不信任。
2. **被职业差评/职业索赔讹诈**:餐饮、住宿、美容、零售 4 行业共性;"知假买假""恶意索赔"已成官方关注点(两高+市监 2026 典型案例)。
3. **招工难、人员流动大、招到不靠谱的**:餐饮、家政最痛;无统一履历核验导致"用人靠赌"。
4. **合规成本高、流程繁琐**:办证、年检、录入台账;中小商户无技术团队、数字化能力弱。
5. **资金压力:货款拖欠、融资难**:供应商货款无保障(货车司机被欠9500元运费案例)、1688 低价骗局损失订金。
6. **供应商侧信任缺失**:有货卖不出、好货无人知,缺资质背书和信用证明。
7. **从业人员侧:欠薪、克扣、无社保、超时加班**(5 大行业共性);健康证/技能证自费、履历无法证明。
8. **不知道进什么货/选哪家供应商(选品采购决策难)**(用户新增痛点 2026-09,对等消费端 #8):商户/企业采购跨行业供给(农资/食材/医美材料等)时,怕选错供应商与商品——1688 类平台只有价格与交易、无信用背书,信任缺失与低价骗局普遍(`15` §4);供应商信用、质量口碑、履约与价格信息分散,小商户无专业采购能力(README 角色表:商户核心诉求含**选品采购**)。→ 平台能力落点:T1 选品广场 + **采购决策辅助(`20` §T1-补)** 收敛与对比、T2 供应商信用/「放心供应商」、T4 担保交易与验收兜底。

### 项目重点关注(经营端)
- **商户端"轻量 + 获得感"是入驻率的命门**:录入门槛 ≤1 分钟、**PC Web 优先**,扫码/拍照录入;录入成本极简,不做重型改造。
- **E2 优质小店推广免费、群众点评、信用加权**:用"信用分 → 流量"的正向循环替代竞价广告,让商户看到"上平台 = 免费获客",这是与流量平台差异化的关键。
- **公平机制必须配套**:D3 恶意差评申诉 + 证据留存 + 职业索赔识别,否则商户会因被讹诈而流失。
- **结算透明、资金有保障**:I3 工资代付留痕"先发工资后结货款"、T4 货款分账"到货验收后放款"、F4 运费结算;**费率公开**是商户信任底线;资金走**第三方持牌通道,平台不沉淀资金**。
- **支付通道开通是小商户信任前提**:需营业执照+对公账户申请微信/支付宝商户号,分账产品资质审核是 M0 最大不确定项(M0 即启动申请 + 聚合支付备选双轨)。
- **C2 防童工对商户是"保护而非负担"**:一键年龄核验,避免误招风险。
- **从业人员端**:一人一档(A2)让履历可证明、工资有保障,是"善待员工 → 善待顾客"闭环的技术底座。
- **"进什么货"要给采购方"筛选与对比"工具**(对应痛点 #8):T1 选品广场补**采购决策辅助**——按经营用途/预计用量/预算收敛候选,供应商横向对比(信用构成/价格/检测/溯源/履约),收藏询价后走 T4 担保下单(详见 `20` §T1-补);平台只做**撮合与信息辅助,不代下单、不替代采购方判断**;推荐排序非竞价、价格透明、强监管品类只核验不替代许可。

## 三、监管端(市监 / 农业 / 药监 / 劳动监察 / 政府)

### 痛点
1. **人手不足、靠抽查、事后监管**:辖区商户/摊贩海量(石家庄"三小"整治重点),监管力量无法全覆盖。
2. **取证难**:后厨看不到、台账造假、履历造假、农资假货难辨——"看不到、查不实、拿不到证据"。
3. **数据不互通、跨部门协调难**:预付卡监管涉及商务局/市监/公安,欠薪涉及劳动监察,医美涉及多部门,"各管一段、信息割裂"。
4. **处罚执行难、小摊小贩难覆盖**:流动性经营、取证后执行难。
5. **新业态监管滞后**:剧本杀、民宿、预制菜、网约货运等监管标准跟不上。
6. **强监管品类全链条打击缺数据支撑**:农资(两高案例:小麦冒充种子、高岭土当农药)、医美材料 11 部门全链条打击——单靠执法人力无法溯源。
7. **民生诉求响应难**:12345 工单量大、"打了电话没人管"、部门办结无法考核。

### 项目重点关注(监管端)
- **对接结论(2026-09-01 用户确认:均不可接)**:石监码(电子执照)、消费维权智慧中枢、食品安全智慧监管、12345、银行专户、公安实名、北斗/GPS——**全部无法对接**,平台**自建替代**(证照人工核验、自建工单线下流转、第三方支付通道代付分账、手机 GPS 定位),做"整合与预警"而非依赖外部体系。
- **A4 监管预警是监管端核心价值**:高频投诉、资质临期、异常经营、欠薪预警、溯源断链、餐厨去向不明——**自动推送 + 分级监管**(低分多查、高分少查),用数据换人力。
- **存证能力(时间戳+哈希)必须从设计期就做**:投诉证据、溯源记录、交易留痕都要"可出证、可调取",否则监管端不会把平台当执法依据。
- **全链条数据可视化**:溯源断链显式标注、抽检结果公示(B3)、餐厨垃圾闭环台账——让"看不见"变成"看得见"。
- **G1/G3 政民互动做"工单化、时限化、结果公示"**:部门限时办结,投诉进度对群众可见,倒逼响应效率;优秀建议进论坛公示采纳。
- **合规红线(监管端最敏感)**:政府牵头做交易撮合有合规边界 → **政府背书 + 国企/混合所有制运营**;农资/医美等强监管品类只做信息撮合+溯源核验,**不替代行政许可**。

## 四、项目整体必须注重的关键点(跨端)

| 关注点 | 为什么重要 | 依据 |
|---|---|---|
| **信任前置、分期落地** | 先做"溯源+信用"攒数据与信任,二期再上交易撮合,避免一步到位失败 | 15 号报告 §8、21 里程碑 |
| **轻资产原则** | 不建重仓配、只做撮合+担保交易,吸取美菜"断臂求生"教训 | 15 号报告 §4 |
| **金融合规** | 工资代付/货款分账走**第三方持牌通道**(微信/支付宝/聚合支付分账产品),平台不沉淀资金、不做二清,M0 即锁定支付通道方案 | 规格书 §6、`24`、21 里程碑风险5 |
| **支付通道是最大不确定项** | 微信/支付宝商户号/分账产品资质审核慢 → M0 即申请 + 聚合支付服务商备选双轨 | 21 里程碑风险1 |
| **商户冷启动** | MVP 需 200 家商户入驻 → 政府发文推荐 + 行业协会动员 + 存量商户数据人工导入 | 21 里程碑风险3 |
| **数据来源双轨** | 处罚/抽检先接公开数据+商户自主申报,逐步打通政务共享 | 21 里程碑风险4 |
| **试点聚焦** | 首期只做餐饮(溯源+工资代付)+零售(一店一档)+家政(履历核验+劳务信用)3 行业,验证后复制 | 21 里程碑 2.3 |
| **六方角色数据边界** | 个人履历本人授权可见、数据分级授权,防监管端"一刀切公开"引发反感 | 规格书 §6、11-P0 非功能 |
| **防刷单防作弊** | 信用分是平台生命线,异常交易自动拦截,否则红黑榜失去公信力 | 20-T 非功能要求 |

## 五、一句话总结

> 消费端要"看得见、投诉有回音";经营端要"低门槛、有获得感、不被讹、货款有保障";监管端要"看得见、管得动、取证易、有数据预警"。平台成败的关键不在功能多少,而在**信任前置的分期节奏、支付通道与金融合规的落地、以及商户端录入轻量化的冷启动**。
