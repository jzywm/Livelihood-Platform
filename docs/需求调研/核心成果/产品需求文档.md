## 2. 背景与目标

### 2.1 为什么做（问题与机会）

| # | 问题（含实证来源） | 影响 |
|---|---|---|
| 1 | 消费信任缺失：资质造假、假农资/假材料、图文不符、缺斤少两、隐形消费跨行业普遍（调研 10 行业，`15`/`25`） | 消费者决策成本高、维权无门 |
| 2 | 维权不畅：投诉「打了没人管」、12345 不可对接、监管取证难、职业索赔讹诈（`25` 监管端 #2/#5） | 信用环境恶化、好店被淹没 |
| 3 | 商户合规成本高：证照临期不自知、年检错过、被职业差评讹诈；平台抽成高且不透明（货拉拉等被约谈实证，`04`/`25` 经营端） | 经营负担重、平台信任透支 |
| 4 | 劳资与预付费风险：欠薪频发、预付卡跑路有本地案例（石家庄实证）、未成年进入娱乐场所（网吧最普遍） | 民生安全底线问题 |
| 5 | 监管数字化缺口：数据不互通、人手不足、事后监管为主；本地「石监码/消费维权智慧中枢/银行专户/12345」经确认**不可对接** | 需自建替代体系（`23`/`README` 决策） |
| 6 | 机会窗口：全国尚无「治理监督 + 透明交易 + 民生服务」一体化的政府背书平台；胖东来式全链透明值得普惠化（`15` §5） | 先发与信任背书优势 |

### 2.2 项目定位与理念（用户已确认）

- **一句话定位**：政府牵头、信用驱动、群众参与的民生综合服务平台——跨行业全产业链的选品与交易透明进行，用胖东来的透明理念贯穿全产业。
- **三位一体**：治理监督（档案/信用/投诉直达）＋ 透明交易（B2B 为主、延伸 B2C 的全产业选品采购）＋ 民生服务（热线/建议论坛/民生建设监督）。
- **理念五词（设计自检原则）**：**惠民 · 方便 · 安全 · 透明 · 直达**——任何功能须落在某词上，评审对照（`26` §2.5）。
- **核心主张**：信用可视化（好店好人的好要让所有人看见）；员工权益前置；价格/过程/结果三透明；全供应链结算（记账在平台、资金走持牌通道）；政府牵头、群众监督；全产业选品透明（每家小店拥有胖东来式供应链信用）。
- **品牌**：对外品牌「民生甄选」；主口号「从种子到餐桌，全程透明」；理念口号即五词。商标注册用户自行处理（不委托）。
- **信任背书承诺（P-05）**：对外统一交付「信用背书 + 政府监督 + 全链溯源 + 免费推广（信用加权）+ 投诉直达与结果公开（脱敏）」；行为边界：政府牵头运营、强监管品类只做信息撮合与溯源核验、AI 不代行执法。

### 2.3 预期收益（按角色）

| 角色 | 预期收益（定性目标；量化指标见 §7.1/§8） |
|---|---|
| 市民/消费者 | 一屏查清商户档案/信用/价格/溯源后决策；投诉 ≤3 步直达并可见进度；工资、预付、未成年人风险有平台防线 |
| 商户/经营者 | 合规成本降低（证照临期提醒、OCR 快审、录入 ≤1 分钟）；免费信用背书与推广；费率公开可预期；被讹有申诉通道 |
| 从业人员 | 履历有背书、工资代付有保障、劳务信用双向可见 |
| 供应商/采购方 | 供应商信用 + 溯源 + 担保交易，放心选品采购（M2） |
| 监管/政府 | 数据预警与分级监管、AI 辅助筛查降人工、取证出证、政民互动直达；实现从「事后抽查」到「数据驱动」 |
| 平台/运营 | 以信用与数据建立信任壁垒（先攒信任后上交易），为后续撮合/服务费（0.5%~1% 公开）奠定基础 |

### 2.4 试点范围与扩展机制

- **试点城市：石家庄市**（用户确认）；覆盖产业链：农资→种植养殖→初加工→深加工→冷链→流通→终端→消费→回收。
- **首期试点行业：餐饮 + 零售 + 家政**（M1 试点 ≥200 商户、≥3 行业，AC-M1.1/M1.2）；其余行业按 §10 附录行业映射分阶段纳入（P-03）。

### 3.3 明确不做与边界声明

1. **不做网约车/出租车**：F 模块只做货运物流（`README` 决策）。
2. **M1 明确不做**：F 物流货运、G2/G3、H 民生监督、E 社区生态、B1 农户端接入、T4 撮合/I4 购买/I5 零工结算、B2 后厨直播、D1 预付卡托管（需银行/硬件合作）、三小/摊贩流动经营者登记（**P3 预留扩展位，裁剪声明**）——引自 `32` R-12/规格书 v1.6 拍板。
3. **行业边界**：未冻结行业（第二批 7 行业）不进入正式范围（§2.4）。
4. **监管/行政边界（R-09）**：农资/医美等强监管品类**只做信息撮合 + 溯源核验，不替代行政许可**；平台不放贷、不设金融服务、不做买量/地推承诺（R-08 轻资产 + 市场分析结论）。
5. **资金边界（R-01）**：平台不沉淀资金、不做二清、不设资金池；工资/货款/运费全走第三方持牌通道（微信/支付宝/聚合），记账与支付分离。
6. **实名边界（R-02）**：全员实名仅微信/支付宝实名回传，不接受人工证件核验降级；第三方不可用时流程暂停。
7. **AI 边界（R-05，C8）**：AI 只做辅助筛查与标记，任何执法/处罚/公示动作必须人工确认；不开放自由工具调用。
8. **价格边界**：公示价目由商户自主维护、平台不代定价；推荐排序非竞价、无付费置顶；**价格不因画像差异化（不杀熟）**。
9. **骑手端后置**：本地配送本次只做消费端 + 运营端（平台运营管理端）+ 经营端（商家接单），**骑手端 App 本次不建**，骑手侧动作暂由运营端人工调度 + 运力档案承载。

## 5. 功能详述

### 5.0 阅读约定

- **组织**：按功能域分节（P 平台级 / A~L 模块），每功能点带 `32-功能列表` 编号（如 A-01、L-01），作为跟踪 ID；各功能点同时对应规格书模块能力（如 K-01 = 规格书 K2 证照 OCR）。
- **去重口径（沿用 `32` §1）**：同一能力跨模块只保留一个功能点并挂靠来源——C1 工资保障并入 I-03、C3 从业履历并入 A-06、T3 溯源 = B1 升级、B1 全链能力 = T-08/T-09 基础 + M3 农户端扩展；避免重复计点。
- **状态标记**：「【M1】/【P1】/【M2】」为分期；【待评审】/【建议初值】表示细节未冻结，引用勿当已确认口径。
- **贯穿红线**：各功能点同时受 §3.4 R-01~R-16 约束，不再逐条重复。
- **业务规则中出现的数值**：除标注「已确认」外，凡「建议初值/上线前评审」项均需在设计与测试阶段标定（对应 §8 验收证据）。

## 6. 业务流程

> 本层为**业务级端到端流程**（谁触发、走哪些环节、异常分支、结果去向），不表述系统内部实现（接口/队列/存储等见概要设计）。每条流程标注对应功能点与验收项；状态迁移描述为业务状态，非技术状态机。

### 6.1 实名与建档（I-01 / A-01 / A-06 / C-01）

```
用户发起（注册/入驻/入职） → 微信/支付宝实名回传（唯一通道）
  → 成功：生成实名账户（六方角色）→ 按场景继续建档
      · 商户：对公/法人实名 → 上传证照 → 核验（人工 + OCR 预审 K-01）→ 一店一档（A-01）
      · 从业人员：健康证/技能证核验 → 一人一档；入职扫码核验（雇主）→ 记录雇佣关系（A-06）
      · 用工入职：身份证+人脸核验 → 年龄 <16 自动拦截警示（C-01）
  → 失败/不可用：流程暂停并明示（红线：不接受人工证件核验降级）
异常分支：证照临期/异常 → 双向推送（A-03 → A-08）
```

### 6.2 工资保障代付（I-03）

```
老板绑定收款账户并核验 → 发起代付（附用工/考勤数据）→ 平台校验 → 第三方持牌通道代付
  → 成功：工作者到账确认 → 流水留痕 + 存证（可一键打包出证）→ 更新老板发薪履约率
  → 应发未发（超时）：欠薪预警 → 催办/仲裁（证据链完整）
  → 通道失败：重试/更换通道（幂等），平台不碰钱、只记账（I-01）
```

### 6.3 投诉直达与升级（D-02；G-01 复用同一工单内核）

```
消费者 ≤3 步提交（选商户→选类别【含「未成年人违规进入」】→附证据）
  → 平台分诊 → 商家限时处理（48h，品类可配）→ 未解决自动升级市监 → 办结
  → 全程进度可见（已提交/处理中/已解决/已升级/已办结）→ 结果公示（脱敏）→ 计入商户信用分
异常分支：商家申诉（D-03）/ 证据存证出证（P-02）；未成年人违规进入举报 → A-08 聚合预警（人工复核）
```

### 6.4 供应商入驻与溯源（T-01 / T-08 / T-09）

```
供应商实名 + 品类资质核验（农资/食材门槛表）→ 开通 → 建档（信用分 T-05）
创建批次 → 生成唯一溯源码（一批一码）→ 上报环节（批号→检测→温控→终端）
  → 扫码验真：时间轴展示全链；任一环节缺失 → 显式「缺失/断链」标注；扫码次数留痕
异常分支：资质过期/投诉激增 → 强制下架/断链预警；供应商扣分 → 申诉复核（T-07）
```

### 6.5 担保交易与分账（T-11/T-12/T-15，M2）

```
采购方在选品广场选品（T-03/T-04，可对比 T-21）→ 担保下单 → 货款托管于持牌机构
  → 发货 → 到货验收（48h，品类可配）
      · 验收通过 → 放款（卖方货款 + 平台服务费 0.5%~1% 公开）→ 互评（T-13）→ 信用联动
      · 拒收 → 退款 → 完成（退款）
      · 争议 → 仲裁（T-15）→ 仲裁完成（放款/退款，结果公示）
异常分支：超时未发货 → 催发/取消退款；验收超期 → 自动确认；刷单/价格异常 → 风控拦截（T-14）
```

### 6.6 预警双向推送（A-08 / A-03）

```
数据扫描（证照有效期/年检/投诉聚合/用工异常）
  → 触发预警：① 资质临期/过期 → 监管端预警 + 商户端提醒（双向）
              ② 违规入场高频举报场所（未成年人举报聚合）→ 监管端预警（人工复核后推送，不自动定责）
  → 处理：商户更新资质自动销警；监管处置留痕
边界：预警只推送线索、不自动执法（执法由监管人工执行）
```

### 6.7 画像生命周期（J-07/J-08）

```
数据采集（实名/履历/行为/主动完善）→ 授权校验（履历需本人授权；未授权字段不入画像）
  → 标签计算（脱敏、加密）→ 画像输出（供 J-09/J-10/J-11 使用）
  → 用户控制（查看/修改/关闭个性化/删除，操作审计）
  → 关闭/删除后：推荐回退通用规则（J-03）；删除后 30 天内清理画像衍生数据；不影响基本功能
红线：未成年人不建行为/购买画像；价格不因画像差异化
```

### 6.8 对话助手交互闭环（J-01~J-06/J-13）

```
用户输入 → 脱敏前置 → 意图识别
  → 白名单跳转（J-02，二次确认）/ 使用指导（J-01）/ 商品推荐（J-03/J-13，透明理由）
  → 无法识别 → FAQ → 人工入口（G-01）；输出过内容安全过滤并标注「以页面为准」
  → 会话 30 分钟超时清空、不留跨会话记忆；回答可评价（用于知识库迭代，脱敏）
```

### 6.9 价格公示与争议（A-04）

```
商户自助维护价目表（扫码/拍照录入，≤1 分钟）→ 提交更新（留痕 + 轻量审核）→ 档案「价格公示」区展示
  → 更新历史可查；消费者一屏可见
异常分支：投诉/抽检发现价目与实收不符 → 标记「价格争议」→ 关联 D-02 处理
边界：平台不代定价；价目表仅展示，不因画像差异化定价（不杀熟）
```

### 6.10 本地配送（L-01~L-06）

> 新增功能域：同城即时配送。**骑手端 App 后置**，骑手侧动作暂由运营端人工调度承载。位置/定位为下单与全程跟踪的必备能力。

**（a）端到端主流程**

```
消费者在店铺/商品页发起配送下单 → 选地址（GPS 定位 / 地图选点 / 常用地址）→ 校验配送范围
  → 超范围：显式提示不可达，引导改地址（阻断下单）
  → 范围内：生成配送订单（计算配送费/预计送达）→ 支付（复用 I-04 持牌通道，平台不沉淀）
      → 商户接单（超时未接自动拒单转运营调度并预警）→ 备货 → 出餐 → 请求取货
      → 运营调度派单（自动/人工）→ 骑手取货 → 配送中（轨迹存证）
      → 已送达 → 消费者确认收货 → 完成
异常分支：取消（支付前/商户拒单/超时）→ 退款；超时/偏航/异常停留 → 自动预警 → 运营人工处置
```

**（b）状态流转（配送订单状态机）**

```
待支付 → 待接单 → 商户备货 → 待取货 → 配送中 → 已送达 → 已完成
   ↘        ↘                              ↘
  已取消    已取消（商户拒单/超时）          异常（超时/偏航，运营介入后可恢复或取消）
```

**（c）角色与职责**

| 角色 | 职责 | 页面 |
|---|---|---|
| 消费者 | 下单（选地址）、跟踪、确认收货、催单/投诉 | S-29 / S-30 / S-31 |
| 商户 | 接单、备货、出餐、转调度 | M-40 |
| 平台运营 | 派单/改派/取消/催单、异常处置、运力管理 | O-01 / O-02 / O-03 / O-04 |
| 骑手（后置） | 取货、配送（本次不建 App，动作由运营端承载） | — |

**（d）位置/定位需求**

- **来源**：手机 GPS（同 F-02），**不做北斗硬件对接**。
- **用途**：① 下单选点与配送范围校验；② 配送全程轨迹存证（时间戳+哈希，P-02）；③ 超时/偏航/异常停留预警（A-08）。
- **合规**：位置属敏感个人信息，最小化收集、脱敏存储，按 R-03 分级授权（本人可见→授权可见→脱敏公示）；R-07 画像不因位置差异化定价（不杀熟）。

### 7.3 可用性与容灾

| 服务级别 | 月度可用性 | 允许月宕机 | 覆盖 |
|---|---|---|---|
| L1 核心链路 | ≥**99.95%** | ≤21.6 分钟 | 支付/代付/实名/投诉/交易 |
| L2 | ≥99.9% | ≤43.2 分钟 | 档案/溯源/看板 |
| L3 | ≥99.5% | ≤3.6 小时 | 内容/资讯/非关键 |

- **容灾**：同城双活 + 异地灾备（两地三中心：生产/同城热备/异地冷备）;**RPO ≤15min、RTO ≤30min（L1）**；L2 目标 RPO ≤1h、RTO ≤2h;灾备切换演练每半年 ≥1 次真实切换并留痕（专项 §4.2/AC-NFR-5）。
- **故障韧性**：限流/熔断/降级/舱壁——核心链路与非核心隔离，非核心故障不得拖垮核心；重试+幂等+超时控制；支付/代付/分账最终一致 + 对账补偿，无重复扣款/重复入账;第三方（支付/AI）异常时平台可降级运行并明确提示（专项 §4.3）。
- **备份恢复**：数据库每日全量 + 实时增量（WAL）；对象/存证多副本 + 跨机房复制；每月 ≥1 次恢复演练（AC-NFR-8）；备份加密 + 异地留存。
- **应急**：应急预案覆盖数据泄露/DDoS/支付故障/RPO 失守/账号批量被盗/AI 误判等；每年 ≥1 次全链路演练 + 每半年桌面推演（专项 §4.6/AC-NFR-10）。

| S-9 | 审计日志 | 关键操作（登录/实名/发薪/分账/申诉/执法/权限变更/数据导出）全量审计，防篡改（WORM/哈希链）;**留存 ≥6 个月**;日志脱敏（专项 §3.7/AC-NFR-9） |
| S-10 | SDL 与供应链 | 威胁建模、SAST + SCA + 密钥扫描门禁;依赖白名单/SBOM/镜像签名 |
| S-11 | 漏洞与渗透 | 上线前第三方渗透测试并整改闭环;此后每半年 ≥1 次;修复 SLA：严重 24h / 高危 72h / 中危 2 周 / 低危 1 月，高危未闭环不得发布 |
| S-12 | 安全运营 | 告警 5 分钟响应、30 分钟定位、重大事件 2 小时处置;SOC/SIEM 集中审计 |

### 7.5 可扩展性

- 应用无状态化，可**水平扩展**；有状态层（DB/缓存/队列）分片 + 读写分离；**自动弹性伸缩**策略（专项 §5.3）。
- 突发流量预案：提前容量评估 + 压测 + 临时扩容;大促/集中检查场景不劣化（§7.2 压测要求）。
- 扩展边界随里程碑：M1 双实例起步、M2 交易/结算按域独立部署扩展（范围口径，实现见概要设计）。

### 7.6 可观测性

- 统一**日志 / 指标（Metrics）/ 链路追踪（Tracing）**三件套 + 集中告警;单次业务请求全链路可追踪（专项 §4.5）。
- 关键指标：错误率、P95/P99 时延、QPS/TPS、可用性、队列积压、依赖健康度;助手业务指标：意图命中率/跳转成功率/推荐采纳率（脱敏）。
- 告警分级（P0~P3）与值班/on-call；告警收敛防轰炸（专项 §4.5）。
- 日志分通道留存：审计日志 ≥6 个月（WORM）;对话日志 ≤30 天脱敏自动清理（红线）;日志不得含明文密钥与敏感字段。

### 7.7 兼容性与发布

- **灰度发布**（按用户/区域/百分比）；金丝雀 + **自动回滚（错误率/时延超阈值自动切回，回滚 ≤10 分钟）**；数据库变更向后兼容（expand-migrate-contract）（专项 §4.4）。
- API 版本化与废弃策略（下线前通知，向后兼容优先）;PC Web 端浏览器兼容当前主流两个大版本;桌面套壳版本随 Web 同版演进。
- 对外公示类变更（费率/规则）调整前提前告知（§5.1 P-01）。

### 7.8 数据与隐私（《个保法》等）

- **分类分级**：个人敏感信息（实名/健康证/工资/履历/画像）→ 高敏感;经营数据 → 内部;公示数据 → 脱敏公开。
- **全生命周期**：采集（告知同意 + 最小化）→ 存储（加密）→ 使用（最小权限 + 授权）→ 共享（协议 + 脱敏 + 审计）→ 销毁（到期/注销后 30 天内）。
- **用户权利**：查询/更正/删除/撤回同意/注销/复制副本;**画像四权**（查看/修改/关闭/删除）。
- **数据不出境**（境内存储）;AI 云服务签合规协议、不用于训练（对话 R-06/图像 R-05）;对话日志 ≤30 天、审计日志 ≥6 个月;画像删除后 30 天清理衍生（专项 §6 + §8 AC-C6/C7）。

### 7.9 UX 与体验量化（验收挂 AC-M1.1/M1.5）

| 指标 | 目标 |
|---|---|
| 商户入驻/上架录入 | **≤1 分钟**（PC Web，扫码/拍照录入 + OCR） |
| 消费端核心信息（档案/信用/溯源/价格） | **一屏看清、一步可查**（不得藏多级菜单） |

| 费率/抽成 | 公示口径与调整规则透明、调整前提前告知（P-01） |
| 助手 | 跳转前二次确认;回答标注「以页面为准」;无法识别给人工入口（不卡死） |
| 弱网/低性能设备 | 关键信息优先、渐进呈现、可恢复错误提示（与 §7.2 弱网条目一致） |
