# 民生甄选 · 功能列表（需求说明 / 调研材料 / 市场分析 → 功能点）

> **用途**：以「功能点」为单位的功能全景清单，供设计、评审、排期直接引用。每个功能点明确两部分核心内容：
> **① 该功能围绕解决什么问题**（业务痛点 / 用户需求 / 市场差距，含文档实证）；**② 项目通过该功能能做什么**（项目侧能力与行为边界，不含实现细节）。
> **依据（仅限三个目录，未引入目录外事实）**：`需求调研/`（核心成果 22 份 + README + 调研素材）、`市场分析/民生甄选-市场分析报告.md`；`docs/` 下仅含 `design/概要设计说明书.md`（设计阶段产物）与 `sop/`（调研方法论），**均不参与取数**（见 §6 范围声明）。
> **基准口径**：《需求规格说明书》v1.8（2026-09-02 当前有效基线）；优先级 P0/P1/P2 与里程碑 M0~M3 均以规格书 §6 与 `21-里程碑规划.md` 为准。
> 版本 v1.0 · 编制于需求评审通过（2026-09-01）、市场分析完成（2026-09-03）之后，功能内容与 v1.8 基线一致。

## 1. 组织方式与字段说明

- **分组**：沿用规格书模块体系 A（信用与监管）→ B（透明与溯源）→ C（用工与保障）→ D（交易与维权）→ E（社区与生态）→ F（物流货运）→ G（政民互动）→ H（民生建设监督）→ T（全产业透明交易）→ I（平台账户系统）→ J（智能助手）→ K（AI 能力中心），另设 **P（平台级能力）** 组；合规红线等贯穿性约束单独列于 §3，不占功能点编号。
- **编号**：`字母-序号`（如 `A-01`、`T-09`），顺序即分组内建议实施次序。
- **状态标记**：正文中的「【M1 基础版】/【P1】」等为规格书既定分期；「【待评审】/【拟定】/【延伸·待确认】」表示文档内该细节未冻结，引用时勿当已确认口径。
- **优先级与里程碑**：P0=首期 MVP；P1=二期；P2=三期；M0~M3 为里程碑（M1=档案/信用/溯源/代付，M2=透明交易，M3=全链深化）。
- **来源代号**：见 §6（如「规格书§4-A1」=《需求规格说明书》v1.8 §4 模块 A1；「11-P0-1」= `核心成果/11-P0用户故事.md`「P0-1」）。
- **去重口径**：同一能力在多个文档出现的只保留一个功能点并挂靠所有来源（如工资保障 = C1/I3 同源、T3 溯源 = B1 升级、从业履历并入 A2）；C1 工资保障与 C3 从业履历的能力并入 I-03 / A-06（分组内注明），避免重复计点。
- **统计**：共 **79 个功能点**（P 组 6 + 模块组 73）+ §3 平台级红线约束 16 项 + §4 查缺提示与附录痛点映射。
