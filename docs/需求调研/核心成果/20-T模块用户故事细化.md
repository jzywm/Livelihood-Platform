## 总览：T 模块定位与边界

- **定位**：轻资产撮合 + 信用背书 + 全链溯源 + 政府监督的跨行业选品采购平台（B2B 为主，延伸 B2C）
- **不做**：自建仓储物流（吸取美菜教训）、重仓配、自行销售商品（只做信息撮合 + 担保交易）
- **不做**：替代行政许可（农资/医美等强监管品类的资质核验只做信息核验与留痕）
- **核心复用**：T2→A3 信用分、T3→B1 溯源、T4→I4/第三方分账（替代原 C1/F4 结算托管）、T5→D2 投诉直达
- **试点品类（首期）**：农资 + 食材（用户已确认）；后续扩展医美材料 / 美发产品 / 维修配件 / 家政人力

### 供应商入驻资质门槛（各品类核验项，T2/T3 共用）

| 品类 | 必核资质 | 强监管说明 |
|---|---|---|
| 农资（种子/化肥/农药/饲料） | 营业执照、农药经营许可证/种子生产经营许可证、产品登记证/批号 | 只能信息撮合+溯源核验，不能替代行政许可 |
| 食材（预包装/生鲜） | 营业执照、食品经营/生产许可证、检验报告 | 批次检测报告上架必备 |
| 医美材料（玻尿酸/肉毒素/器械） | 营业执照、医疗器械注册证/备案、药品批号 | 注册证/批号核验 + 来源追溯；机构选品必须走平台 |
| 美发产品（化妆品） | 营业执照、化妆品注册/备案凭证 | 注册备案核验 |
| 维修配件 | 营业执照、合格证/质保信息 | 配件溯源 + 质保 |
| 家政人力（服务型） | 营业执照、人员健康证/技能证（联动 A2） | 人力服务类暂不涉及货品溯源 |

## T1 全产业选品广场（跨行业分类选品）

### 用户故事
- 作为**商户（采购方）**，我想按行业分类浏览/搜索供应商商品（农资/食材/医美材料/美发产品/维修配件），看到来源、批次、检测报告、价格、供应商信用分，以便放心选品下单
- 作为**供应商**，我想上架商品并展示资质、批次、检测报告，获得平台背书，以便扩大销路
- 作为**监管人员**，我想查看各品类商品与供应商数据总览、异常标记（资质临期/投诉激增），以便精准监管
- 作为**消费者（B2C 延伸）**，我想在开放品类上选购并扫码验真，以便买到放心的东西

### 关键流程
1. 供应商入驻 → 实名 + 品类资质核验（见总览表）→ 通过后开通上架权限
2. 上架商品：填商品信息 + 关联资质/批号 + 上传检测报告 → 平台校验（批号格式、报告有效期）→ 审核发布
3. 采购方检索（行业 / 品类 / 价格 / 信用分 / 距离 / 溯源完整性）→ 查看商品详情（来源 + 批次 + 检测 + 信用 + 价格）
4. 下单 → 进入 T4 撮合交易流程
5. 交易完成后商品挂「已交易次数」「履约率」，供应商信用分联动更新（T2）

### 数据字段
商品ID、供应商ID、品类、名称、规格、单价/计价单位、库存批次、资质关联、检测报告（文件+有效期）、溯源码、上架状态、信用分、履约率、交易次数、最近交易价

### 商品状态机
`草稿 → 待审核 → 已上架 ⇄ 下架`；异常（资质临期/投诉激增）→ `强制下架`

### 页面清单（PC Web 优先）
- 选品广场首页（行业分类导航 + 搜索 + 信用/溯源排序）
- 商品详情页（来源、批次、检测、信用、价格、溯源入口、投诉入口）
- 供应商主页（资质、信用分构成、红黑榜标识、全部商品）
- 上架管理页（供应商端：新建/编辑/下架商品，批次与报告上传）

### T1-补 采购决策辅助（「不知道进什么货/选哪家供应商」，经营端场景）

> 痛点依据:`25` 经营端 #8(用户新增 2026-09,对等消费端 #8)——采购方怕选错供应商与商品;`15` §4 实证 1688 类平台信任缺失、低价骗局;README 角色表:商户核心诉求含选品采购。消费端对等场景(澄清式导购)见 `27` §4.1。

#### 用户故事
- 作为**采购方(商户/企业)**,我想在选品广场"拿不准进哪个货、选哪家"时,按经营用途/用量/预算得到收敛后的候选与对比,以便放心下单。
- 作为**供应商**,我想让优质商品在采购方筛选对比中被看见(信用背书而非竞价)。

#### 功能目标
1. **采购需求收敛**:采购方以用途(如"小饭店日常炒菜油")、预计用量/频次、预算区间(可空)描述需求 → 平台在品类内收敛候选(在售 + 信用分 ≥ 阈值 + 溯源完整,规则同 T1/T2);
2. **供应商横向对比**:对候选供应商做并排对比 —— 信用分构成(资质/履约/质量口碑/正向贡献)、价格与计价单位、检测报告、溯源链路完整度、履约率/交易次数、距地(可选);支持「只看放心供应商」过滤(T2);
3. **决策到下单衔接**:收藏/加入采购单 → 询价(可选)→ 走 T4 担保交易下单(48h 验收放款),全程可回溯。

#### 行为边界(平台级能力与红线口径不变)
- **只做撮合与信息辅助**:平台不代下单、不代定价、不替采购方做专业判断;不提供"包赚/包销"类承诺;
- **非竞价排序**:候选默认排序与推荐逻辑同 T1/J3(信用/溯源/价格/评价,建议初值待评审),**不做竞价排名、付费置顶**;价格透明展示,无隐藏费用(费率见 T4/P 平台承诺);
- **强监管品类**(农资/医美等)仅做资质核验展示与溯源核验,**不替代行政许可**;
- **数据边界**:采购行为数据仅用于本平台选品与信用评估(遵循数据分级授权),不向无关第三方共享;供应商信用相关数据脱敏公示口径同 T2;
- **分期(随 T1/T4)**:M1 期不做交易场景(T1/T4 属 M2 范围),采购辅助随 M2 上线;M1 仅提供基础筛选入口评估【待评审确认】;对话式澄清在消费端优先(J3 §4.1),经营端使用基础问答。

#### 页面与字段(草案,随 T1 页面清单扩充)
- 页面:选品向导页(需求描述/用途标签)、供应商对比页、采购单/询价页;
- 字段:复用 T1 数据字段,补「预计用量/频次」「预算区间」「采购单状态(草稿→已下单→已完成)」。

## T2 供应商信用体系（复用 A3 信用分内核）

### 用户故事
- 作为**采购方（商户）**，我想查看供应商信用分、履约率、红黑榜和「放心供应商」标识，以便选择可靠货源
- 作为**供应商**，我想了解自己信用分构成、申诉不合理扣分，以便提升信用获得更多订单
- 作为**监管人员**，我想按信用分级监管供应商（低分多查、高分少查），以便节约人力聚焦风险

### 信用分构成（建议权重，待评审确认）
- 资质合规 30%：资质齐全有效、批号/报告齐全
- 交易履约 30%：按时发货率、按约质量、退换率
- 质量口碑 30%：质量投诉率、检测合格率、纠纷处理及时率
- 正向贡献 10%：主动公示信息完整度、检举协查等

### 关键流程
1. 供应商入驻 → 生成信用档案（初始分，如 60）
2. 每笔交易完成后自动更新履约维度；投诉/抽检联动更新质量维度
3. 信用分阈值 → 红黑榜：≥85 挂「放心供应商」标识；≤40 进黑榜并限制接单/降权
4. 供应商申诉扣分项 → 平台复核 → 修正或驳回（留痕）
5. 信用分与 A3 全域信用分体系联动（同一主体信用档案贯通平台）

### 数据字段
供应商ID、信用分、各维度得分、红黑榜状态、标识（放心供应商/警告/黑榜）、扣分明细（原因/时间/证据）、申诉记录、评级历史

### 状态机（榜单状态）
`正常 ⇄ 警告（60~40）⇄ 黑榜（<40）`；黑榜期间：商品降权、禁止新订单、存量订单需预付全款担保

### 「放心供应商」标识授予门槛（已确认 2026-09-01）
- **条件**：信用分 ≥85 且无质量投诉，**并根据消费者评价与商品质量动态授予**（非一次性认定，随评价/质量变化可授予或撤销）
- 授予后显著展示在供应商主页与商品详情；撤销需公示理由

### 页面清单
- 供应商信用档案页（构成 + 明细 + 申诉入口）
- 红黑榜公示页（脱敏展示）
- 申诉处理页（供应商端 + 平台后台）

## T3 一物一码全程溯源（复用并升级 B1）

### 用户故事
- 作为**采购方/消费者**，我想扫商品溯源码看到全链条（农资批号→生产检测→流通温控→终端），以便验证真伪与来源
- 作为**供应商**，我想为每个批次生成溯源码并维护各环节记录，展示全链透明，获得信任
- 作为**监管人员**，我想抽查任意批次溯源的完整性与真实性，识别断链/造假，以便精准执法

### 关键流程
1. 供应商创建批次 → 平台生成**唯一溯源码**（一物一码/一批一码，编码含品类+供应商+批号+随机校验）
2. 各环节上报：生产（检测报告）→ 流通（温控/在途，联动 F2 物流位置）→ 终端（入店/上架扫码登记）
3. 采购方/消费者扫码 → 按时间轴展示全链条记录，断链环节显式标注「缺失」
4. 溯源记录不可篡改：时间戳 + 哈希存证（联动存证能力），异常（同一码重复流通/温度超限）自动预警
5. 假货/断链投诉 → 一键直达 T5 反向闭环（联动 D2）

### 数据字段
溯源码、品类、供应商ID、批次号、生产日期、检测报告、各环节记录（环节类型/时间/位置/温度/操作人/证明文件）、断链标记、存证哈希、扫码次数

### 状态机（溯源链路完整性）
`环节① 农资批号 → ② 生产检测 → ③ 流通温控 → ④ 终端登记`；任一环节缺失 = 断链；完整 = 可全链验证

### 页面清单
- 扫码结果页（时间轴 + 断链标注 + 验真结果）
- 批次管理页（供应商端：创建批次、上报环节记录）
- 溯源监控台（监管端：断链率、异常批次预警）

## T4 透明交易撮合（轻资产 + 担保交易）

### 用户故事
- 作为**采购方（商户）**，我想在平台下单采购，货款由**第三方持牌通道托管**、到货验收后再放款，避免假货与预付款损失
- 作为**供应商**，我想订单货款有保障、按时结算，避免货款拖欠
- 作为**监管人员**，我想看到交易全流程留痕与异常预警（货不对板/拖延放款），以便调处纠纷

### 关键流程
1. 采购方下单（选商品/数量/配送方式）→ 货款进入**第三方持牌通道托管**（替代原银行托管，见 `24-平台账户系统需求.md`）
2. 供应商发货 → 物流在途可见（联动 F2）
3. 采购方收货验收（**验收期 48h，已确认；生鲜/农资品类可差异化调整**：确认/部分拒收/全额拒收 + 证据）
4. 验收通过 → 托管货款经持牌机构**分账**给供应商（扣除平台服务费，**费率=成交额比例 0.5%~1% 分品类，已确认**）
5. 验收超期未确认 → 自动确认 + 提示；验收争议 → 平台存证仲裁 → 计入双方信用分
6. 交易完成 → 双方互评 → 更新 T2 供应商信用与 A3 商户信用

### 数据字段
订单ID、买卖双方ID、商品/批次、数量、单价、货款、托管流水、验收状态、验收期、争议状态、仲裁结论、双方评价、服务费率

### 订单状态机
`待付款 → 已付款(货款托管) → 已发货(在途) → 待验收(验收期内) → 已完成(放款+互评)`
分支：`验收拒收 → 退款中 → 已完成(退款)`；`争议 → 仲裁中 → 仲裁完成(放款/退款)`
异常：`超时未发货 → 自动催发/可取消退款`；`验收超期未确认 → 自动确认`

### 页面清单
- 下单确认页（货款托管提示 + 费用明细）
- 订单列表/详情页（状态机可视 + 验收操作 + 证据上传）
- 验收与评价页（确认/拒收 + 证据 + 互评）
- 争议仲裁页（双方提交证据 → 平台结论公示）
- 结算台账页（供应商端：托管流水、服务费、结算记录）

## T5 反向闭环（投诉直达 + 餐厨垃圾登记）

### 用户故事
- 作为**采购方/消费者**，我想对假农资/假材料一键投诉并看到处理进度（平台 + 市监联动），避免买到假货无处维权
- 作为**产废单位（餐饮商户/食堂/食品加工企业）**，我想登记餐厨垃圾去向（交运给合规收运企业），证明没有地沟油回流，展示诚信
- 作为**监管人员**，我想看到假货投诉热点与餐厨垃圾收运全链路数据，发现回流风险，以便执法

### 关键流程（投诉直达，复用 D2）
1. 扫码/订单页发起投诉（选品类、问题类别、证据照片/视频、关联溯源码）
2. 平台智能分诊 → 供应商先处理（限时，如 48h）→ 未解决升级市监（联动 D2；石监码/智慧中枢不可接 → 线下联动）
3. 全程进度可视化：处理中/已解决/已升级/已处罚
4. 处理结果计入供应商信用分（T2）与批次记录；同一溯源码多次投诉自动预警

### 关键流程（餐厨垃圾登记，防地沟油回流）—— 首期范围：餐饮商户 + 食堂 + 食品加工企业（已确认 2026-09-01）
1. 产废单位（餐饮商户/食堂/食品加工企业）登记产废（类型/量/频率）→ 选择合规收运企业（平台白名单）
2. 收运企业上门 → 双方扫码确认交接（时间/重量/去向：处理厂或资源化企业）
3. 处理厂接收确认 → 全链路留痕可查
4. 收运异常（超期未收运/去向不明）→ 预警 → 联动市监
5. 收运企业建信用档案（T2 体系延伸）：交接履约率、去向合规率

### 数据字段
投诉ID、关联溯源码/订单、品类、问题类别、证据、分诊结果、处理时限、处理状态、升级记录、处罚结果；餐厨登记ID、商户ID、产废类型/量、收运企业、交接时间/重量、处理去向、异常标记

### 状态机（投诉）
`已提交 → 供应商处理中 → 已解决 / 已升级(市监) → 已办结(公示)`
### 状态机（餐厨交接）
`已登记 → 待收运 → 已交接(在途) → 已接收(处理厂) → 闭环完成`；异常 → `预警`

### 页面清单
- 投诉提交页（关联溯源/订单 + 证据上传）
- 投诉进度页（状态机可视化 + 结果公示）
- 餐厨登记页（商户端：产废登记 + 收运交接确认）
- 收运台账页（监管端：全链路台账 + 异常预警）

## T 模块非功能要求

- **轻资产**：不建仓储物流，撮合 + 第三方持牌通道结算（平台不沉淀资金，见 `24-平台账户系统需求.md`）
- **强监管品类红线**：农资/医美等只做信息撮合 + 溯源核验，不替代行政许可（页面显著提示）；**首期仅农资+食材，医美等二期（已确认）**
- **存证**：溯源记录、交易、投诉证据时间戳 + 哈希存证，可出证供执法调取
- **实名与授权**：供应商实名核验（微信/支付宝实名回传，不接受人工降级）；数据分级授权（采购记录等敏感数据按角色可见）
- **PC Web 优先**：上架/下单/验收操作在 PC 端 ≤1 分钟完成（先 Web 后套壳桌面）
- **防刷单防作弊**：异常交易（同 IP/同设备高频、价格异常）自动拦截
- **公示透明**：服务费率（成交额 0.5%~1%）、抽检结果、红黑榜、投诉处理结果均脱敏公示
- **对接**：政务通道（石监码/12345/银行专户）不可接，全部自建替代 + 第三方支付通道
