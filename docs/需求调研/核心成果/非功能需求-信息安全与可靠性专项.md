# 非功能需求专项 · 信息安全与可靠性

> 版本：v1.0 · 2026-09-02 · 依据：《需求规格说明书》v1.8 §8（非功能需求核心基线）
> 定位：本专项是规格书 §8 的**详细展开**，覆盖「规模容量 / 信息安全 / 平台应用安全 / 健壮性高可用 / 性能容量 / 数据隐私 / 合规对照 / 验收度量 / 里程碑 / 风险成本」十部分；规格书 §8 只保留核心基线并链接本专项，设计/测试/安全团队以本专项为执行输入。
> 适用标准：GB/T 22239-2019（等保 2.0 三级）、GB/T 35273（个人信息安全规范）、《网络安全法》《数据安全法》《个人信息保护法》《密码法》、OWASP ASVS L2 / Top10。

## 1. 规模与容量定位（用户目标 2026-09-02）

> **平台定位：覆盖石家庄市全体市民及常住人口的 75%。**

| 指标 | 目标值 | 说明 |
|---|---|---|
| 常住人口基数 | ≈ 1120 万 | 石家庄 2024 年统计公报口径，[来源](http://news.sjzdaily.com.cn/2025/04/18/99965312.html) |
| **覆盖人口** | **≥ 840 万（75%）** | 全体市民 + 常住人口；以最新统计口径为准 |
| 注册用户 | ≥ 600 万（覆盖人口的 70% 转化假设） | 设计容量按 840 万规划，用户数取安全上界 |
| 月活跃用户 MAU | ≥ 200 万（注册的 33%） | 容量规划基线 |
| 商户 / 机构 | ≥ 10 万 | 餐饮/零售/家政/培训等全行业商户 + 供应商 + 托育/养老机构 |
| 日活峰值 DAU | ≈ 120 万（MAU 60%） | 用于并发估算 |
| 峰值在线 / 并发 | 见 §5 容量估算 | 按 1%~5% 在线、TPS 分场景 |

> ⚠️ 从「试点级（商户 200+ / 用户 1~10 万）」升级为「市级生产级」后，下述安全与可靠性要求**必须整体达到市级政务/民生平台水准**，不得再以试点基线降级。

## 2. 信息安全（等保 2.0 三级，GB/T 22239-2019）

### 2.1 安全等级定级
- **定级对象**：民生综合服务平台（含 Web/桌面三端 + 数据底座 + AI 服务）。
- **定级建议**：**等级保护三级（S3A3G3）**。理由：① 涉及大量公民个人信息（实名、履历、健康证、工资流水）；② 涉及政务数据与政府监督业务；③ 遭破坏将危害公民权益、公共利益，甚至影响社会秩序。
- **动作**：M0 完成定级备案 + 专家评审；M1 上线前完成等保三级**测评**（备案测评机构），取得测评报告并整改闭环。

### 2.2 安全物理环境
- 托管于国内持牌/合规机房（或政务云），物理访问控制、门禁/监控/双路供电/消防；异地容灾机房见 §4.2。

### 2.3 安全通信网络
- 全链路 **HTTPS/TLS 1.2+**（禁用 SSL/TLS 1.0/1.1）；管理面独立安全通道（VPN/专线）。
- 网络分区分域：DMZ / 应用区 / 数据区 / 管理区隔离，东西向流量微隔离。

### 2.4 安全区域边界
- **WAF**（防 SQL 注入/XSS/CC 攻击）、**抗 DDoS**（清洗 + 黑洞，市级平台必备）、防火墙/IPS。
- API 网关统一收敛入口：认证、鉴权、限流、签名、防重放（见 §3.4）。

### 2.5 安全计算环境
- 主机安全：最小化安装、补丁管理、HIDS（主机入侵检测）、防病毒、容器/镜像安全扫描。
- 数据库安全：最小权限账号、透明加密（TDE）、审计、备份加密。
- 密钥与证书：**HSM/KMS 统一密钥管理**，密钥与数据分离存储、轮换策略（见 §3.6）。

### 2.6 安全管理中心（SOC）
- 集中日志审计（SIEM）+ 统一身份认证 + 统一授权 + 集中安全策略下发。
- **安全事件响应 SLA**：告警 5 分钟响应、30 分钟定位、重大事件 2 小时处置（见 §4.6）。

### 2.7 安全管理制度与机构
- 设立**信息安全负责人 + 安全运营团队**；制度覆盖：安全策略、人员安全、资产/变更/事件/应急/外包管理。
- 人员安全：背景审查、保密协议、最小授权、离职权限回收；安全培训每年 ≥1 次。

### 2.8 数据安全（《数据安全法》+《个保法》）
- 数据**分类分级**：核心数据 / 重要数据 / 一般数据 + 个人信息（敏感/一般），分级授权与脱敏（详见 §6）。
- 重要/敏感数据**加密存储、脱敏输出、操作审计**；数据全生命周期留痕。

## 3. 平台应用安全（OWASP ASVS L2）

### 3.1 身份认证与账号安全（ASVS V2/V3）
- **实名 + 多因素认证（MFA）**：敏感操作（发薪、分账、申诉、监管执法）强制 MFA（短信/OTP/生物特征）。
- 强口令策略 + 防暴力破解（限速、锁定、验证码、风控）；会话安全（短令牌、超时、防固定、退出即失效）。
- 实名通道：仅微信/支付宝实名回传，不接受人工降级（沿用规格书红线）。

### 3.2 访问控制（ASVS V4）
- **RBAC + ABAC 最小权限**：按角色（消费者/商户/供应商/工作者/监管/政府/运营）+ 数据域（本人/授权/脱敏公示）双重控制。
- 水平/垂直越权防护（IDOR 校验）；关键对象操作二次确认 + 审计。

### 3.3 输入验证与注入防护（ASVS V5）
- 防 **SQL 注入、XSS、CSRF、SSRF、命令注入、路径穿越、XML/反序列化攻击**。
- 输出编码、参数化查询、文件上传白名单+杀毒+存储隔离；上传文件病毒/木马扫描。

### 3.4 API 安全（ASVS V12/V13）
- API 全量鉴权 + 限流 + 幂等 + 请求签名（防重放/防篡改）；**OpenAPI 安全评审**。
- 敏感 API 强制 HTTPS + MFA + 审计；API 版本与废弃策略（下线前通知）。

### 3.5 前端与客户端安全
- 内容安全策略（CSP）、防点击劫持（X-Frame-Options/frame-ancestors）、Cookie 属性（HttpOnly/Secure/SameSite）。
- 桌面套壳应用：签名、自动更新通道校验、防逆向/防调试基础加固。

### 3.6 密钥与证书管理
- 统一 KMS/HSM；密钥分级（支付密钥最高级）；密钥轮换（对称 ≤1 年、非对称 ≤2 年、证书到期前 30 天告警）。
- 支付/工资场景密钥强制硬件或等效隔离存储；日志与审计禁止记录明文密钥。

### 3.7 安全日志与审计
- 关键操作（登录、实名、发薪、分账、申诉、执法、权限变更、数据导出）**全量审计**，日志防篡改（WORM/哈希链）。
- **日志留存 ≥ 6 个月**（关键/涉诉日志按法规延长）；日志脱敏，不记录明文敏感字段。

### 3.8 安全开发生命周期（SDL）与供应链
- 设计阶段：威胁建模（复用 `agent-sdlc-standard` 威胁建模模板）；代码：SAST + 依赖漏洞扫描（SCA）+ 密钥扫描（gitleaks）。
- 发布：CI 门禁（单元/安全/依赖）强制通过；**供应链安全**：依赖白名单、SBOM、镜像签名。
- 上线后：众测/渗透、漏洞悬赏可选。

### 3.9 漏洞管理与渗透测试
- **上线前**：第三方**渗透测试**（含 API、移动/桌面端）并整改闭环；**上线后**：每半年 ≥1 次渗透 + 重大变更后复测。
- 漏洞修复 SLA：严重 24h / 高危 72h / 中危 2 周 / 低危 1 月；高危未闭环不得发布。

## 4. 健壮性与高可用

### 4.1 可用性目标（分级 SLO）
| 服务级别 | 可用性（月度） | 允许月宕机 |
|---|---|---|
| 核心交易/支付/实名/投诉（L1） | ≥ **99.95%** | ≤ 21.6 分钟 |
| 档案/溯源/论坛/看板（L2） | ≥ 99.9% | ≤ 43.2 分钟 |
| 内容/资讯/非关键（L3） | ≥ 99.5% | ≤ 3.6 小时 |

- 支付/代付/分账链路**最终一致 + 对账补偿**；失败自动重试（幂等），无重复扣款/重复入账。

### 4.2 容灾与业务连续性（BCP/DR）
- **同城双活 + 异地灾备**（两地三中心）：生产、同城热备、异地冷备。
- **RPO ≤ 15 分钟、RTO ≤ 30 分钟**（L1 核心链路）；L2 目标 RPO ≤ 1h、RTO ≤ 2h。
- 灾备**切换演练**：每半年 ≥1 次真实切换演练并留痕；核心数据每日全量 + 实时增量备份。

### 4.3 故障隔离与弹性韧性
- **限流 / 熔断 / 降级 / 舱壁**：核心链路与非核心链路物理/逻辑隔离，非核心故障不得拖垮核心（如论坛宕机不影响支付）。
- 重试 + 幂等 + 超时控制 + 队列削峰；**故障自动切换**（主从/多副本）。
- **防雪崩**：依赖服务超时/降级策略；第三方支付/AI 服务异常时平台可降级运行并明确提示。

### 4.4 灰度发布与回滚
- 灰度发布（按用户/区域/百分比）；金丝雀 + 自动回滚（错误率/时延超阈值自动切回）。
- 发布可回滚：**回滚 ≤ 10 分钟**；数据库变更向后兼容（expand-migrate-contract）。

### 4.5 可观测性
- 统一**日志 / 指标（Metrics）/ 链路追踪（Tracing）**三件套 + 集中告警。
- 关键指标：错误率、P95/P99 时延、QPS/TPS、可用性、队列积压、依赖健康度。
- 告警分级（P0~P3）与值班/on-call；告警收敛防轰炸。

### 4.6 应急响应与演练
- 应急预案：数据泄露、DDoS、支付故障、RPO 失守、账号批量被盗、AI 误判等场景。
- **应急演练**：每年 ≥1 次全链路演练 + 每半年 1 次桌面推演；演练后复盘更新预案。

### 4.7 数据备份与恢复
- 备份策略：数据库每日全量 + 实时增量（WAL）；文件/存证对象多副本 + 跨机房复制。
- **备份可恢复性验证**：每月 ≥1 次恢复演练；备份加密 + 异地留存（防勒索）。

## 5. 性能与容量

### 5.1 容量估算（按 840 万覆盖 / 600 万注册设计）
| 场景 | 估算基线 | 规划峰值（1.5~3x 冗余） |
|---|---|---|
| 并发在线 | 峰值 DAU 120 万 × 3% 在线 ≈ 3.6 万 | 支撑 ≥ 10 万并发在线 |
| 核心读 QPS（档案/信用/溯源） | 3.6 万在线 × 1~2 req/人 ≈ 5 万 QPS | 支撑 ≥ 15 万 QPS |
| 核心写 TPS（投诉/发薪/交易/评价） | 峰值 ≈ 2 万 TPS | 支撑 ≥ 5 万 TPS |
| 存储（流水/档案/存证/日志） | 首年 ≈ 50 TB | 规划 ≥ 150 TB（3 年） |

> 具体以设计阶段压测与容量模型为准；本表为架构选型的**量级输入**。

### 5.2 响应时间 SLO
- 核心读页面（档案/信用/溯源/价格）**首屏 P95 ≤ 2s**；核心写（投诉提交/下单/发薪确认）**P95 ≤ 3s**。
- API 核心链路 **P95 ≤ 500ms**、**P99 ≤ 1s**；AI 类（助手/视觉审核）按异步任务设计，同步 P95 ≤ 3s。
- 弱网/高峰降级策略：关键信息优先渲染，非关键延迟加载。

### 5.3 弹性扩容
- 无状态应用**水平扩容**；有状态（DB/缓存/队列）分片 + 读写分离；**自动弹性伸缩**（HPA/Serverless 策略）。
- 大促/监管集中检查等突发流量：提前容量评估 + 压测 + 临时扩容。

### 5.4 压测要求
- 上线前**全链路压测**（含第三方支付/实名/AI 依赖），达到规划峰值 1.5~3x 不劣化；每季度回归压测 + 重大变更后压测。
- 压测报告留存作为验收证据（AC-NFR 系列）。

## 6. 数据安全与隐私（个保法）

- **分类分级**：个人敏感信息（实名/健康证/工资/履历/画像）→ 高敏感；经营数据 → 内部；公示数据 → 脱敏公开。
- **全生命周期**：采集（告知+同意+最小化）→ 存储（加密）→ 使用（最小权限+授权）→ 共享（协议+脱敏+审计）→ 销毁（到期/注销后 30 天内）。
- **用户权利**：查询/更正/删除/撤回同意/注销/复制个人信息副本；画像四权（查看/修改/关闭/删除）沿用规格书 C7。
- **数据出域**：**境内存储、不出境**；AI 云服务签数据合规协议、不用于训练（沿用规格书 C6/C8）。
- **留存期限**：业务流水按法规/业务需要；对话日志 ≤30 天脱敏；审计日志 ≥6 个月；画像注销后 30 天内清理衍生数据。

## 9. 里程碑与实施（M0~M3 安全/可靠性工程）

| 里程碑 | 安全/可靠性关键动作 |
|---|---|
| **M0 立项合规** | 等保定级备案 + 专家评审；安全架构设计（威胁建模）；机房/政务云选型（同城双活预留）；KMS/密钥体系设计；第三方支付/实名/AI 服务的合规与数据协议评审 |
| **M1 MVP 上线** | 等保三级测评 + 整改闭环；上线前渗透测试 + 修复；WAF/抗DDoS/SOC/SIEM 上线；日志审计、备份恢复、灰度回滚、可观测三件套就绪；压测达到规划峰值 |
| **M2 透明交易** | 同城双活 + 异地灾备（RPO≤15min/RTO≤30min）落地 + 切换演练；应急响应体系 + 首次全链路演练；支付/交易链路可用性 99.95% 验证 |
| **M3 全链深化** | 全量安全运营成熟化；覆盖规模滚动达 75%；年度等保复测 + 渗透；韧性工程（混沌演练）常态化 |

## 10. 风险与成本

| 风险 | 影响 | 缓解 / 成本提示 |
|---|---|---|
| 等保三级测评周期（备案→测评→整改 2~4 月） | 可能拉长 M1 上线 | M0 即启动定级备案，测评与开发并行 |
| 灾备两地三中心投入高 | M2 成本显著增加 | 政务云/托管分级：L1 核心双活、L2/L3 降级容灾；先同城热备、异地冷备起步 |
| 安全团队/运营人力不足 | SOC/应急形同虚设 | 自建最小安全团队 + 托管 SOC（MSSP）组合 |
| 840 万级容量设计过度/不足 | 成本或性能风险 | 用 §5 量级输入 + 压测迭代，避免一次性超配 |
| 第三方（支付/实名/AI）依赖故障 | 核心链路中断 | 多通道备选 + 降级运行 + 对账补偿（§4.3） |
