# 阶段 0:想法澄清

> 目标:把一句话模糊想法,变成一张"想法卡",定义清楚**谁、在什么场景、要解决什么**。
> 预计耗时:15~30 分钟 · 负责人:人类回答,Agent 提问并整理

---

## 0.1 输入

你只需要有一句话想法,例如:
- "我想做个宠物相关的 App"
- "给考研党做个效率工具"
- "帮小餐馆老板管账"

**模糊完全没关系**,本阶段就是把它问清楚。

---

## 0.2 5W1H 提问清单(Agent 逐个提问,人类回答)

| # | 问题 | 目的 |
| --- | --- | --- |
| 1 | **Who** 你最想服务谁?(年龄/身份/职业,先别求精确) | 锁定目标用户 |
| 2 | **What** 你希望帮他们解决什么问题?(用"现在的做法 + 哪里不爽"描述) | 找到切入点 |
| 3 | **Where** 这个问题主要发生在什么场景?(家里/公司/通勤路上/线下门店…) | 明确场景边界 |
| 4 | **When** 多久发生一次?频率高不高? | 判断痛点频次(高频 > 低频) |
| 5 | **Why** 为什么是你/现在做?(你自己是否有这个痛点?是否有资源?) | 判断动机与优势 |
| 6 | **How** 你初步设想的产品形态?(App/小程序/网页/SaaS/硬件配套…) | 记录初步形态 |

> 💡 Agent 追问技巧:回答出现"大概""可能""也许"时,追问"你见过/经历过具体例子吗?"——把模糊描述逼成具体故事。

---

## 0.3 想法卡模板(产出物)

```markdown
# 想法卡(Idea Card)

- 日期:________
- 一句话想法:____________________________________

## 目标用户(Target)
- 谁:________(身份/年龄段)
- 用户画像一句话:________

## 场景与痛点(Pain)
- 场景:________
- 用户现在怎么做:________
- 哪里不爽(痛点描述):________
- 发生频率:□ 每天 □ 每周 □ 每月 □ 偶尔

## 价值主张(Value Proposition)
- 我们要提供:________(产品形态)
- 帮用户获得:________(结果/感受)
- 一句话卖点:________

## 待验证假设(Hypotheses)
- H1(人群假设):________
- H2(痛点假设):________
- H3(方案假设):________
- H4(付费假设):________

## 直觉判断
- 为什么现在做/为什么是我:________
- 最大风险:________
```

**假设(H1~H4)是本阶段最重要的产物** —— 后续所有搜索和调研,都是在验证这 4 条假设。

---

## 0.4 决策门 G0

| 问题 | 通过标准 |
| --- | --- |
| 目标用户是否可描述? | 能说出"谁 + 场景"即可(哪怕粗略) |
| 是否有至少一个明确的"不爽"? | 有具体场景下的具体抱怨 |
| 是否值得花 1~2 天搜索验证? | 回答"是"即可(成本很低,大胆进 G1) |

- ✅ 通过 → 进入 [阶段1-市场扫描](阶段1-市场扫描.md)
- ❌ 不通过(完全说不清用户和场景)→ **建议终止**,回去想清楚再启动

> ⚠️ G0 否决是正常且光荣的。它只花你 30 分钟,却可能帮你省下三个月。
