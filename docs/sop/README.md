# 软件早期 Agent 需求收集 SOP

> 版本:v1.0 · 适用场景:软件立项初期(0→1),尚未写代码之前
> 执行主体:AI Agent(具备联网搜索能力)+ 产品负责人(人类决策者)
> 核心思想:**用"联网搜索市场 → 验证痛点 → 触达用户 → 收敛需求"的流水线,把"拍脑袋做产品"变成"有证据做产品"**

---

## 一、这套 SOP 解决什么问题

| 传统做法的问题 | 本 SOP 的解法 |
| --- | --- |
| 需求靠老板/自己拍脑袋 | 阶段 1~2 用联网搜索找**外部证据**(市场数据、用户吐槽、竞品差评) |
| 分不清"真需求"和"伪需求" | 阶段 2 有**反伪需求检查表**,每条痛点必须过 3 关 |
| 访谈问不到点上 | 阶段 3 有**访谈提纲模板 + 追问技巧** |
| 需求清单又大又散,无法排期 | 阶段 4 用 **MoSCoW 优先级 + 验收标准** 收敛成可开发范围 |

**Agent 的职责边界(重要):**
- ✅ Agent 负责:搜索、整理证据、生成模板、起草需求清单、标注不确定项
- ❌ Agent 不负责:拍板做什么(那是产品负责人/用户的事)
- 每个阶段末尾都有 **决策门(Gate)**,必须由人类确认后才能进入下一阶段

## 二、总流程总览

```
┌─────────────────────────────────────────────────────────────┐
│ 输入:一句话想法(哪怕很模糊,如"我想做个宠物相关App")           │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 阶段 0:想法澄清 ────────────────────────────────────────────┐
│ 用 5W1H 把模糊想法问清楚,定义"目标用户 + 场景 + 初步价值主张"   │
│ 产出:想法卡(Idea Card)                                       │
│ 决策门 G0:想法是否值得继续?否 → 直接终止,省下所有后续成本       │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 阶段 1:市场扫描(Agent 主战场 · 联网搜索)────────────────────┐
│ 搜索市场规模、趋势、竞品格局、监管/政策,建立宏观认知           │
│ 产出:市场扫描报告(1~2 页)                                     │
│ 决策门 G1:市场是否有空间且自己能进场?                         │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 阶段 2:痛点挖掘与验证(Agent 主战场 · 联网搜索)──────────────┐
│ 搜用户吐槽、差评、社区讨论、知乎/小红书/贴吧内容,收集候选痛点    │
│ 每条痛点过"反伪需求检查表"3 关                                 │
│ 产出:痛点清单(带证据链接 + 置信度)                            │
│ 决策门 G2:是否存在 1 个"足够痛 + 有支付意愿"的核心痛点?        │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 阶段 3:用户调研(Agent 辅助 · 真实用户介入)──────────────────┐
│ 设计访谈提纲/问卷,招募 5~10 名目标用户访谈或投放问卷            │
│ Agent 负责:整理访谈记录、聚类、标注引用                         │
│ 产出:用户洞察报告(引用原话 + 需求聚类)                        │
│ 决策门 G3:核心痛点是否被真实用户确认?                         │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 阶段 4:需求输出(Agent 起草 · 人类拍板)─────────────────────┐
│ 将验证过的痛点转化为功能需求,MoSCoW 分级,写验收标准             │
│ 产出:PRD 前置版 —— 需求清单(带优先级 + 验收标准)              │
│ 决策门 G4:范围是否可开发?进入原型/排期                         │
└─────────────────────────────────────────────────────────────┘
```

**三个"能砍就砍"的原则:**
1. G0 就能否决的想法,不要在 G3 才否决 —— 越早否决成本越低
2. 单次 SOP 全程建议 2~5 个工作日,禁止超过 2 周(否则市场已变)
3. 任何阶段发现"证据不足",回到上一阶段补证据,而不是硬闯决策门

## 三、目录结构与使用方式

```
docs/sop/
├── README.md                  ← 本文件(总流程 + 决策门)
├── 阶段0-想法澄清.md            ← 想法卡模板 + 5W1H 提问清单
├── 阶段1-市场扫描.md            ← 联网搜索提示词模板 + query 范例
├── 阶段2-痛点验证.md            ← 反伪需求检查表 + 信源分级
├── 阶段3-用户调研.md            ← 访谈提纲模板 + 问卷框架
├── 阶段4-需求输出.md            ← MoSCoW + 验收标准模板
└── examples/
    └── 示例-<领域>-痛点与需求.md ← 实战样例(证明流程可用)
```

**使用方法(两种):**

> 方式一(手动):对照各阶段文档,把模板提示词复制给任意联网 AI 执行。
>
> 方式二(技能化):把本目录声明为 Agent 技能,在会话说一句:
> "按需求收集 SOP 执行,我的想法是:______"
> Agent 会自动按阶段推进,每到决策门停下来向你汇报。
