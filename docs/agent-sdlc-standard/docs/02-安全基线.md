# 02 · 安全基线

> 目的:定义所有代码必须满足的安全底线,作为评审、门禁与威胁建模的判定依据。
> 对齐:OWASP ASVS L2、OWASP Top 10 (2021)、NIST SSDF。所有条目为**强制项**,除非经安全负责人书面豁免。

## 1. 安全设计原则

1. **最小权限**:代码、账号、密钥、网络权限只给完成任务所需的最小集合。
2. **纵深防御**:单一防护不信任,认证、授权、校验、加密分层叠加。
3. **默认安全**:默认拒绝、默认加密、默认不泄露,开关默认关闭。
4. **永不信任输入**:所有外部输入(请求、文件、环境变量、第三方回调)默认不可信。
5. **失败安全(Fail-safe)**:出错时倾向拒绝服务而非放开权限;错误信息不泄露内部细节。

## 2. 密钥与凭证管理(红线)

| 规则 | 说明 |
|---|---|
| **零密钥进仓库** | 任何环境变量、密钥、token 不得写入源码/配置文件;G0 Gitleaks 拦截,违反即门禁红 |
| 密钥只经注入 | 运行时从密钥管理系统读取:云 KMS / HashiCorp Vault / GitHub Secrets |
| 轮换周期 | 静态密钥 ≤ 90 天轮换;泄露立即轮换并审计影响面 |
| 禁止硬编码 | 默认密码、测试账号不得出现在生产代码路径 |
| 最小权限密钥 | 每个服务使用独立凭证,按环境隔离(dev/staging/prod 分离) |
| 审计 | 密钥访问留痕,异常访问(非常规时间/来源)告警 |

## 3. 输入输出安全(ASVS 对齐)

| 类别 | 强制要求 |
|---|---|
| 输入校验 | 所有外部输入做白名单校验(类型、长度、范围、格式);服务端校验,不信任前端 |
| 注入防护 | 使用参数化查询/预编译语句;禁止字符串拼接 SQL;命令执行用参数数组;模板渲染默认转义 |
| XSS | 输出编码按上下文(HTML/JS/CSS/URL);CSP 头启用;不信任富文本,白名单清洗 |
| SSRF | 出站请求校验目标地址,禁止直接请求内网/元数据地址(169.254.169.254 等) |
| 反序列化 | 仅反序列化可信来源;不接收用户可控的反序列化流 |
| 文件上传 | 白名单扩展名 + 内容嗅探校验;存储与执行目录分离;限制大小 |

## 4. 认证、授权与会话

- 认证:统一身份接入(SSO/OIDC);禁止自研密码存储,密码哈希用 bcrypt/argon2。
- 会话:HttpOnly + Secure + SameSite Cookie;会话超时与空闲回收;登录失败限速与锁定。
- 授权:服务端强制鉴权(不依赖前端隐藏按钮);每个接口做资源级授权(IDOR 防护)。
- 越权防护:横向/纵向越权测试纳入安全评审 checklist。
- 多因素:管理后台、生产操作强制 MFA。

## 5. 数据保护

| 数据类别 | 要求 |
|---|---|
| 传输 | 全链路 TLS ≥ 1.2(生产强制 1.3 优先) |
| 静态 | 敏感数据落盘加密(KMS 托管密钥) |
| 敏感字段 | 数据库层加密或脱敏存储;日志/链路追踪中脱敏(身份证、手机号、token) |
| 个人数据(PII) | 遵循最小收集原则;按地区合规(如个保法/GDPR)保留与删除策略 |
| 密钥材料 | 私钥不出加密边界;内存中短暂存活,用时释放 |

## 6. 日志与审计

- 关键事件必须记录:认证成功/失败、授权变更、数据导出、删除操作、配置变更、密钥访问。
- 日志禁止记录:密码、token、密钥、完整 PII。
- 日志带请求 ID 便于链路追踪;时间统一 UTC;保留期 ≥ 90 天(生产关键日志 ≥ 180 天)。
- Agent 操作日志接入同一审计体系(见 `docs/06`)。

## 7. 依赖与供应链安全

- 依赖锁定文件提交进仓库;CI 执行 SCA 扫描(G2 `sca` job)。
- **已知漏洞处理 SLA**:

| 严重度 | 修复时限 | 说明 |
|---|---|---|
| CRITICAL | ≤ 24h | 立即升级或临时缓解,门禁阻断 |
| HIGH | ≤ 7 天 | 排入本周迭代 |
| MEDIUM | ≤ 30 天 | 排入下个迭代 |
| LOW | 评估后处理 | 记录理由 |

- 新增依赖的替代评估 + 维护活跃度检查;锁定供应链攻击面(如 npm `--ignore-scripts` 评估、可复现构建)。

## 8. 错误处理与异常

- 用户可见错误:统一错误码 + 通用提示,不暴露堆栈、SQL、框架路径。
- 全局异常兜底,未捕获异常落入日志并告警。
- 禁止在生产输出 debug 信息;环境差异(dev/prod)行为一致化。

## 9. 安全配置基线

- 禁用默认凭证、默认管理员账号强制改密。
- 服务监听:生产仅暴露必要端口;管理端口不公网可达。
- 容器:非 root 运行、只读根文件系统(如可行)、资源限制、无特权模式。
- 响应头基线:`Strict-Transport-Security`、`X-Content-Type-Options`、`Content-Security-Policy`、`X-Frame-Options`。
- 依赖版本与运行时版本纳入版本管理,安全补丁及时跟进。

## 10. 漏洞响应流程

1. **发现**:扫描告警 / 渗透测试 / 外部上报(安全邮箱 + 公开渠道)。
2. **分级**:按 CVSS + 可利用性 + 影响面定级(上表 SLA)。
3. **处置**:CRITICAL/HIGH 创建热修分支,24h 内出修复方案;修复走完整门禁但允许加急评审。
4. **复盘**:root cause 分析,写入安全基线或威胁建模模板,防止同类复发。
5. **公告**:对外影响需披露时,按披露政策(协调披露 ≥ 90 天窗口)。
