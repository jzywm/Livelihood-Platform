# 04 · 威胁建模模板

> 用途:高风险变更(见 `docs/03` 第 3 节)在评审前必须完成的威胁分析,结论附在 PR 中。
> 方法:STRIDE(微软威胁分类)。目标不是"产出文档",而是**找出会被攻击者利用的缺口并落到验证项**。

## 1. 触发条件(满足任一做一次)

- [ ] 认证 / 授权 / 会话 / 密钥管理相关改动
- [ ] 支付、计费、资金相关改动
- [ ] PII 数据的新增采集、存储、传输、导出
- [ ] 新增外部依赖 / 网络通信 / 反序列化 / 文件处理
- [ ] CI/CD、部署脚本、生产配置改动
- [ ] 数据库结构变更或数据迁移

## 2. STRIDE 速查表

| 字母 | 威胁 | 攻击者目标 | 典型缓解 |
|---|---|---|---|
| S | Spoofing 假冒 | 冒充他人/系统 | 强认证、签名、会话绑定 |
| T | Tampering 篡改 | 修改数据/代码 | 完整性校验、签名、只读存储 |
| R | Repudiation 抵赖 | 否认做过的事 | 审计日志、不可否认记录 |
| I | Information Disclosure 泄露 | 窃取敏感信息 | 加密、脱敏、最小权限、访问控制 |
| D | Denial of Service 拒绝服务 | 让服务不可用 | 限流、资源上限、超时、配额 |
| E | Elevation of Privilege 提权 | 获得更高权限 | 服务端鉴权、最小权限、输入校验 |

## 3. 威胁建模模板(复制到 PR 中填写)

### 3.1 变更概述

```markdown
**变更**:<一句话>
**涉及组件/数据流**:<组件名 → 数据流向,可贴简化图>
**受影响资产**:<用户数据 / 密钥 / 资金 / 可用性 / 声誉>
**信任边界**:<如:公网入口、内部服务边界、第三方回调>
```

### 3.2 威胁清单

| # | STRIDE | 威胁描述(攻击者怎么做) | 可能性(H/M/L) | 影响(H/M/L) | 缓解措施(已实现或待实现) | 验证方式 |
|---|---|---|---|---|---|---|
| T1 | S | 攻击者伪造 JWT 访问管理接口 | H | H | 校验签名算法+iss+aud;密钥经 KMS 轮换 | 单元测试:伪造 token 被拒 |
| T2 | E | 越权访问他人资源(IDOR) | H | H | 服务端资源级鉴权,对象 ID 与归属绑定 | 集成测试:跨用户访问返回 403 |
| T3 | I | 日志记录完整手机号 | M | H | 日志脱敏组件,统一日志工具类 | 代码评审 + 脱敏单测 |
| T4 | D | 未限流的公开接口被打爆 | M | M | 网关限流 + 超时 + 并发上限 | 压测报告 |
| ... | | | | | | |

> 规则:任何 H×H 或 H×M 威胁,**没有缓解措施不得进入评审**;缓解措施必须给出验证方式。

### 3.3 结论

```markdown
**总体结论**:☐ 可接受,无剩余高风险威胁 | ☐ 有条件通过(需修复以下项后合入)
**待修复项**:<威胁编号 + 措施 + 负责人 + 期限>
**剩余低风险项**(记录理由,接受):<编号 + 理由>
**安全负责人签字**:<姓名/日期>
```

## 4. 示例:OIDC 登录模块

**数据流**:浏览器 → 反向代理 → auth-service(校验 OIDC 回调)→ 签发会话 → 业务服务(校验会话)→ DB

| # | STRIDE | 威胁 | 可能 | 影响 | 缓解 | 验证 |
|---|---|---|---|---|---|---|
| T1 | S | 攻击者用篡改的 state 参数做登录 CSRF | H | H | state 随机 + 一次性 + 绑定会话;PKCE | 单测:state 不匹配拒绝 |
| T2 | S | JWT 算法混淆(alg=none / HS256) | H | H | 显式校验 `alg` 白名单 + 公钥固定 | 单测:伪造 alg 被拒 |
| T3 | E | 通过回调参数切换身份 | M | H | 只信任 IdP 签发的 claims,不信任回调参数 | 集成测试 |
| T4 | I | token 落在前端日志 | M | M | 日志脱敏;token 仅存 HttpOnly Cookie | 评审 + 日志扫描 |
| T5 | D | 回调接口无限次打 | M | M | 限流 + 幂等 | 压测 |

## 5. 安全需求追踪矩阵(可选,大型功能必填)

| 需求 ID | 安全需求(来自威胁) | 设计落地 | 验证(测试/扫描) | 状态 |
|---|---|---|---|---|
| SR-001 | JWT 必须白名单算法 | auth/jwt.py 固定 RS256 | `test_jwt_alg_confusion` 通过 | ☐ |
| SR-002 | 会话 Cookie 加 HttpOnly+Secure+SameSite | 全局中间件 | 响应头测试通过 | ☐ |

## 6. 常见误区

- 威胁建模 ≠ 代码 review:先画数据流,再找攻击路径,最后才是查代码。
- 不要只列威胁不写缓解:每个威胁必须有缓解或明确接受理由。
- 缓解必须可验证:写"加密"不够,写"用 X 库 AES-GCM,密钥来自 KMS,测试用例 xxx"。
