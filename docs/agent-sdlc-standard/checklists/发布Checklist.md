# 发布 Checklist

> 每次发版(打 tag / 部署生产)由发布负责人逐项勾选,完成后归档到审计记录。
> 流程详见 `docs/05-发布与供应链安全.md`。

## 1. 发布前准备

- [ ] 待发布内容已合入 main,main 分支 CI(merge-gate)全绿
- [ ] 版本号与变更一致(SemVer);release notes 可由 conventional commits 生成
- [ ] 变更涉及数据库迁移 → 迁移脚本与回滚脚本已评审通过
- [ ] 涉及配置变更 → 配置已评审、密钥已就位(KMS/Secrets)
- [ ] 高风险变更已完成安全评审(`安全评审Checklist.md`)并签字
- [ ] 依赖:SCA 扫描通过,无未处理的高危漏洞

## 2. 发布执行(G4 发布门)

- [ ] 打 tag 触发 release.yml,流水线通过:
  - [ ] 版本一致性校验通过
  - [ ] 可复现构建成功
  - [ ] Trivy 镜像扫描:CRITICAL/HIGH 为 0(或有记录理由的豁免)
  - [ ] SBOM(CycloneDX)已生成
  - [ ] cosign 签名完成(镜像 + SBOM)
- [ ] Release 产物(二进制/SBOM/签名)已归档

## 3. 金丝雀与验证

- [ ] 金丝雀(5% 流量)健康检查通过:错误率、P99 延迟、内存指标正常,观察 ≥ 15 分钟
- [ ] smoke test 通过(登录、核心业务流、关键 API)
- [ ] 监控告警已就位,无新增异常

## 4. 全量发布

- [ ] 全量发布完成
- [ ] 发布后 30 分钟监控:无错误率/延迟异常
- [ ] 若异常:已确认回滚预案(上一版本镜像可立即切换)

## 5. 发布后归档

- [ ] 审计记录已写入:版本、变更摘要、审批人、时间、环境
- [ ] 回滚预案已记录(当前版本号 + 上一版本号)
- [ ] 通知相关方(团队/客户支持/运维)
- [ ] 如涉及漏洞修复:漏洞状态已更新(修复时间 ≤ SLA)
