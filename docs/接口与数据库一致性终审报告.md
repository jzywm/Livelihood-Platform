> **用途**：以基线文档（PDD v1.0（基线）/ PRD v2.3 / 32-功能列表 v1.5 / 微服务边界与职责基准 v1.6 / 高并发 v1.0 / 页面清单 IA v1.6 / 各线框图）为准，对 14 个业务微服务的 `openapi.yaml`、`er.md`、`README.md` 与 `openapi.apifox.json` 做**最后一次一致性检查与完善**的终审记录。GATEWAY 无业务接口/业务库（SSOT C14），不在本轮审计对象内。

## 1. 执行方法与验证

- **审计**：14 个只读审计子代理并行逐服务核对（功能点→接口覆盖、表/字段→基线口径、枚举/状态机/定值、红线合规、版本引用），产出结构化差异报告；主控汇总裁决并逐项修正。
- **Apifox 产物**：`openapi.apifox.json` 为自动生成物（禁止手改）——编写回放脚本 `.dsh/regen-apifox.cjs`（openapi.yaml + `_common` 全量解引用 → JSON），先用未变更的 ticket 回放验证**字节级一致**，再对全部 14 份重打包。
- **验证结果**：
  - 15 份 YAML（14 服务 + `_common`）js-yaml 解析 **ALL PASS**；
  - 14 份 `openapi.apifox.json` 与 `openapi.yaml` 重生成比对 **全部 MATCH**（DELIVERY 由旧 v1.0.0 产物升级为 v1.1.0 全量，含骑手 7 接口与 VehicleType/CargoSpec/NavTarget）；
  - 残留口径扫描：`智能派单/自动派单` services 内 **0 残留**（TICKET G-01「智能分派至部门」为政务工单路由，保留）；`7 天可配`、`高德/百度候选`、`归本域但`、`上线前评审`（已定档项）**0 残留**。
