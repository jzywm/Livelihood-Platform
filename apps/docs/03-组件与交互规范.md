# 03 · 组件与交互规范

> 本章约束「组件怎么封装、交互怎么做」。三端统一用 Ant Design 5(PC/Electron)封装进 `packages/ui`,移动端(uni-app)复用同一套交互语义与令牌,只做平台适配(见 `04`)。

## 1. 组件库策略(MUST)

- **统一封装**:所有业务组件在 `packages/ui` 二次封装 AntD,业务页面**禁止直接深用 AntD 内部 API / 魔法 className**;升级 AntD 时只改 `packages/ui`。
- 必封装的公共组件(至少):档案卡(一店一档/一人一档)、信用分、红黑榜、表格(带空态/分页/筛选)、表单(统一校验)、上传(证照/证据)、看板卡片、状态徽章、时间轴(进度/溯源)、公示对照表。
- **禁止**页面各自写同功能组件的第二个版本;发现重复即收敛回 `packages/ui`。

## 2. 通用组件规范

### 2.1 按钮

- 主操作一个页面(或一个弹窗)**只有一个**主色按钮(primary),其余用默认/文本按钮,避免主次不分。
- 危险操作(删除、拒绝、放款、投诉升级)用 `danger`,并配二次确认。
- 按钮文案:动词开头、语义明确(如「发起代付」「提交投诉」),禁止「确定」代替真实动作词(除非上下文极清晰)。
- 异步按钮:请求期间 `loading` + 禁用,防重复提交(MUST)。

### 2.2 表单

- 必填/选填标注统一;校验即时反馈(失焦校验 + 提交校验),错误信息具体(「请输入 11 位手机号」而非「格式错误」)。
- **方便原则**:可自动带出(实名信息、档案字段)、给默认值、减少必填;录入类任务目标 ≤1 分钟(如价目表维护)。
- 敏感/资金字段(金额、收款账号、手机号)按 `06` 做脱敏展示 + 提交前二次确认。
- 长表单分段(步骤条/分栏),禁止一屏堆 20+ 字段。

### 2.3 表格(经营/监管端重)

- 必须有:加载态、空态(含「去创建」引导)、分页、列排序/筛选;数据量大时列固定、表头吸顶。
- 金额右对齐 + `tabular-nums`;状态列用**状态徽章**(见 §3),不用裸文字。
- 行操作控制在 3 个以内,更多收进「更多」;批量操作提供全选 + 动作条。

### 2.4 反馈组件

- 轻提示 `Toast/Message`:用于操作结果,自动消失,不含需用户记忆的信息。
- 弹窗 `Modal`:用于需要确认或输入的重要操作;标题=动作,内容=影响说明(尤其资金/信用/不可逆)。
- 确认 `Popconfirm`:用于列表内危险小操作。
- 全局进度(工单进度、溯源时间轴、发薪流水):用**时间轴 + 状态徽章**表达「过程透明」,而非纯文字。

## 3. 状态规范(MUST,统一语义色)

| 状态 | 语义色 | 通用含义 |
|---|---|---|
| 成功/通过/已办结 | `success` | 已完成、已通过、已到账、已上线 |
| 进行中 | `primary` | 处理中、审核中、运输中 |
| 待处理/预警 | `warning` | 待审核、临期、待办、欠薪预警 |
| 失败/拒绝/违规 | `error` | 失败、拒绝、超期、违规 |
| 已取消/已关闭 | 中性灰 | 取消、关闭、失效 |
| 草稿 | 中性灰 | 未提交 |

- 状态徽章统一组件,文案 + 颜色一一对应;同一业务状态在三端颜色**必须一致**。
- 涉及资金/信用/工单的状态名从规格书状态机取值,禁止前端自造状态词。

## 4. 通用页面状态(四态,MUST)

每个数据区域/页面必须覆盖四态,缺一不可:

1. **加载中**:骨架屏(优先于转圈)或 `Spin`,不闪白屏。
2. **空态**:说明「为什么空」+ 引导动作(如「暂无投诉记录,去提交」)。
3. **错误态**:说「原因 + 怎么办」+ 重试按钮;网络/权限错误区分提示。
4. **无权限态**:角色无权访问时显示明确「无权限」而非空白或报错(配合 `06` RBAC)。

## 5. 导航与信息架构

- 层级 ≤3 层(MUST);关键诉求(投诉/热线/扫码溯源)在**首页首屏直达**。
- 三端合一靠「角色 + 权限路由」:同一 URL 按角色渲染对应视图,未授权重定向到权限页(见 `06`)。
- 面包屑(经营/监管端)+ 侧边栏(管理型页面);消费端用轻量导航,减少层级。
- 全局搜索/智能助手(民生小助手)为共享入口,三端复用 `packages/assistant`。

## 6. 无障碍与可用性(SHOULD,逐步达标)

- 语义化标签(`<button>`/`<label>`/`<table>` 语义),不用 `div` 堆交互。
- 键盘可达:可聚焦、可 Tab 导航、弹窗可 Esc 关闭、焦点不丢失。
- 对比度达标(见 `02` §2.4);图标 + 文字并存,不只靠颜色传达状态。
- 触达目标:移动端 ≥44px;PC 按钮高度 ≥32px。
- 表单控件关联 `label`/`aria-label`;错误提示用 `aria-describedby` 关联。

## 7. 交互细节红线(MUST)

- 资金/信用/不可逆操作:必须二次确认 + 展示影响;禁止一键直接执行。
- 长耗时操作(OCR 审核、证照核验)必须有明确进度与结果反馈,禁止「点了没反应」。
- 表单/提交类操作:请求中禁用 + loading,防止重复提交(幂等配合后端)。
- 输入即时校验不阻塞用户;提交前统一校验 + 定位第一个错误项。
