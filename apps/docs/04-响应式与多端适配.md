# 04 · 响应式与多端适配

> 端形态:PC Web(三端合一,当前主线)→ Electron 桌面套壳(复用同一 Web 包)→ 移动 H5 / 微信小程序(uni-app,后置)。
> 原则:**一套设计、一套令牌、一套交互语义**,差异只做「布局/栅格/平台能力」适配,不做第二套风格。

## 1. 端形态总览(MUST)

| 端 | 技术 | 主设备 | 设计宽度 | 说明 |
|---|---|---|---|---|
| PC Web | React 18 + Vite + AntD 5 | 桌面浏览器 | ≥1024px(主流 1440/1280) | 三端合一,角色+权限路由 |
| Electron 桌面 | Electron 33 套同一 Web 包 | Windows 桌面 | 窗口可缩放 | 复用 Web,仅加桌面壳能力 |
| 移动 H5 | uni-app Vue3 | 手机浏览器 | 375~428px | 消费端优先 |
| 微信小程序 | uni-app mp-weixin | 微信内 | 375px(rpx) | 消费端优先 |

## 2. 断点与栅格(PC,初版基线)

| 断点 | 宽度 | 栅格列 | 布局策略 |
|---|---|---|---|
| `--breakpoint-lg` | ≥1440px | 24 列 | 内容区最大宽 1200~1280px 居中 |
| `--breakpoint-md` | 1024~1439px | 24 列 | 侧边栏可收起,表格列可隐藏次要列 |
| `--breakpoint-sm` | <1024px | 12 列 | 折叠导航;复杂表格转卡片/横向滚动 |

- 栅格 gutter 取 16/24px(令牌 `--space-4/6`);内容区最大宽度不无限拉伸,保证「白底干净 + 信息不散」。
- 管理型页面(经营/监管)以 1440 为基准设计,1280 不横向溢出、1024 可用。

## 3. 多端一致性(MUST)

- **同一令牌**:颜色/字体/间距/圆角/状态色在所有端一致(`02` 令牌落地到 `uni.scss` 同名变量)。
- **同一状态语义**:某工单「待处理」在 PC/移动/小程序都是 `warning` 黄 + 同文案(见 `03` §3)。
- **同一交互语义**:资金/不可逆操作在所有端都二次确认;加载/空/错/无权限四态所有端都覆盖。
- 允许差异仅限:导航形态(侧边栏 vs TabBar)、信息密度(桌面表格 vs 移动卡片)、平台手势。

## 4. Electron 桌面适配

- 复用同一 Web 构建产物,不另写 UI;桌面差异在 `electron/` 主进程(窗口、菜单、更新、托盘)。
- 窗口最小宽度建议 ≥1024px;窄窗口时侧边栏自动收起、表格降级(同 §2)。
- 桌面端需处理:离线/断网提示、窗口缩放重排、文件上传走系统对话框(主进程能力)。
- 禁止在 Web 包内写 Electron 专属逻辑污染;用能力探测或独立入口隔离。

## 5. 移动 H5(uni-app)适配

- 布局单位:用 `rpx`(750 设计稿)或百分比 + 弹性布局;字体/间距尽量复用令牌换算,避免散落 px。
- 导航用 `pages.json` 原生导航栏 + TabBar;消费端首屏保留「一键投诉 / 热线 / 扫码溯源」直达入口。
- 表单/列表:移动端表格转卡片列表;输入控件触达 ≥44px;键盘弹出与吸底按钮避让。
- 图片:按需压缩/懒加载,不阻塞首屏;大图用占位 + 渐进加载。

## 6. 微信小程序适配

- 用 uni-app **条件编译**(`#ifdef MP-WEIXIN`)处理平台差异,业务逻辑与 H5 共用,只隔离平台 API。
- 单位 `rpx`;遵守微信小程序基础库 API 能力边界(不用的 API 不调用,做能力判断)。
- 隐私合规:获取用户信息/位置/手机号须按微信「用户隐私保护指引」申报;授权最小化(配合 `06`)。
- 包体积控制(主包 ≤ 合理阈值),图片/大资源走 CDN + 分包加载。

## 7. 兼容性(MUST)

- 浏览器:近两个大版本的 Chrome / Edge(桌面主流);H5 覆盖主流手机浏览器内核;小程序覆盖当前微信版本。
- 特性降级:不支持的 CSS/API 用渐进增强,不影响核心功能可用。
- 字号/缩放:支持浏览器 125% 缩放不破版;移动端尊重系统字体缩放(SHOULD)。
- 环境差异:开发/测试/生产域名、接口网关统一走环境变量,禁止写死(见 `05` §9、`06` §3)。
