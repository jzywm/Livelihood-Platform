# 01 · 设计原则与品牌视觉

> 本章回答「为什么这么设计」:把平台定位与「五词设计原则」转译为前端可直接执行的设计准则,并固化品牌视觉基调。
> 事实来源:`docs/需求调研/核心成果/26-平台命名与品牌定位.md`、`docs/design/产品设计文档.md` §1.1。

## 1. 平台定位(设计的总输入)

- **一句话定位**:政府牵头、信用驱动的全产业链透明交易与民生综合服务平台「民生甄选」。
- **本质**:To G + To C 的**民生平台**;把胖东来「一家店的全链条可控」普惠给石家庄每一家小店。
- **主口号**:从种子到餐桌,全程透明。
- **三端**:消费端 / 经营端 / 监管端(三端合一单 React App,按「角色 + 权限路由」区分)。
- **品牌调性**:可信 · 透明 · 温暖 · 现代 · 接地气(政府亲民 + 品质生活,不说教、不冰冷)。

## 2. 五词设计原则 → 前端可执行准则

> 五词(惠民 · 方便 · 安全 · 透明 · 直达)既是品牌理念,也是**每个页面/组件评审时的自检标准**。下表把抽象理念转成前端能直接检查的准则。

| 理念 | 前端设计准则 | 正例 / 反例 |
|---|---|---|
| **惠民** | 核心功能免费可达、不设付费墙;费率为用户「可见且可理解」;推荐不竞价、理由透明 | ✅ 费率公开页免费可查;❌ 核心查询页面插会员墙 |
| **方便** | 关键任务少步数:投诉 ≤3 步、录入 ≤1 分钟、下单 ≤1 分钟;扫一物一码即验;减少填写(自动带出/默认值) | ✅ 一键实名、扫码即验;❌ 投诉要填 8 个必填项 |
| **安全** | 资金/实名/敏感数据**永远在可信路径**:不直连敏感接口、不前端做资金计算、敏感信息脱敏展示;操作有二次确认与留痕提示 | ✅ 代付走服务端、仅展示留痕;❌ 前端拼金额字符串直接提交 |
| **透明** | 价格 / 过程 / 结果三透明:进度可见、理由可查、结果可溯源;公示信息用「时间轴 / 对照表」而非一句话结论 | ✅ 投诉进度时间轴 + 处理结果公示;❌ 只显示「处理中」无详情 |
| **直达** | 诉求一键直达政府/商家,进度实时可见;关键入口在首屏可达、层级浅(≤3 层) | ✅ 首页直达「我要投诉 / 群众热线」;❌ 热线藏在 4 层菜单下 |

**使用方式**:每个 feature / 页面评审时对照上表逐词自检,并在 PR 描述注明「落在哪几个词」。无法回答「落在哪词」的设计,默认打回。

## 3. 设计目标(优先级排序)

1. **信任前置** > 好看:优先让用户「看得懂、信得过」(信用分、溯源、公示),视觉服务于信息可信度。
2. **效率优先** > 炫技:管理类页面(经营/监管端)信息密度高、操作轻量,拒绝无意义的动效与装饰。
3. **一致性** > 个性:三端、三角色共享同一套令牌与组件,视觉差异只在「角色信息架构」层面,不在「风格」层面。

## 4. 品牌视觉基调

### 4.1 色彩方向(MUST,数值见 `02-设计令牌.md`)

- **主色「民生蓝」**:政务信任、可靠、透明;用于品牌标识、主按钮、链接、选中态。
- **辅色「暖橙」**:民生温度、热忱、行动号召(CTA);用于强调、惠民标签、关键提醒、收藏/关注态。
- **白底(透明感)**:页面以浅灰底 + 白卡片承载内容,留白充足,传递「透明、干净」。
- **语义色**:成功/警告/错误/信息,仅用于状态反馈,不用于品牌装饰。

### 4.2 图形与图标

- Logo 意象:「选」字对勾 / 环链 + 对勾(甄选 + 全链);图标统一**线性风格**,描边 2px,24px 网格(见 `02`)。
- 业务图标(溯源/信用/结算/工单)风格一致,禁止混用实心/线性/拟物三套。

### 4.3 语气与文案

- 语气:政府亲民 + 品质生活,**不说教、不冰冷、不卖惨**。
- 文案规则(MUST):按钮/提示用「动词 + 对象」;错误信息说「原因 + 怎么办」,不说只报错误码;涉及资金/信用/法务的表述用词谨慎、留出证据感。

## 5. 三端设计基调(差异化在信息架构,不在风格)

| 端 | 用户 | 页面特征 | 设计侧重 |
|---|---|---|---|
| 消费端 | 群众(宝妈/银发/白领等) | 查档案、扫码溯源、投诉、看红黑榜/推荐 | 大字、浅层级、一键直达、银发友好 |
| 经营端 | 商户/供应商/从业者/司机 | 维护档案证照、价目表、代付发薪、选品采购 | 表单/表格重、批量操作、状态清晰 |
| 监管端 | 政府/监管人员 | 看板、预警、工单分派、公示核验 | 高信息密度、数据可视化、分级与审计 |

**MUST**:三端共用同一套令牌与组件库(`packages/ui`),禁止为某端单独造风格;差异只通过「布局密度 / 导航层级 / 权限路由」体现。

## 6. 冲突裁决

当「效率」与「好看」、「一致」与「定制」冲突时,按以下顺序裁决:

1. 合规红线(见 `06`)> 一切;
2. 五词原则(尤其「安全」「透明」) > 视觉;
3. 一致性 > 个性化;
4. 效率 > 装饰性动效。
