## 1. 为什么需要四态说明

| **正常态** | 数据就绪，页面完整呈现业务内容 | 列表接口 200；筛选/排序/刷新返回数据；重试成功 | 商户卡片列表按信用分排序，卡片直览在售商品（品名/价格/溯源/检测） | 一屏可查（R-11）；信用分脱敏排序；语义色 ≥85 绿 / 60~84 橙（§2.5）；金额等宽数字；单页单主按钮 | IA §3.2 · 线框 S-01 · UI §2.5/§4.2 |

## 4. S-01 落地明细

### 4.1 正常态

- **呈现**：商户卡网格（≥1024 双列、≥1280 三列自适应）。卡片 = 商户头像/名称/「✓ 已核验」标 + 信用分（语义色）+ 品类/距离/评分/服务单数 + **在售商品直览**（品名 · 价格 · 溯源✓ / 检测✓ 标签）+ 主行动「进店看一店一档」。
- **信用分语义色**（UI 设计规范 §2.5）：≥85 绿（放心/红榜方向）、60~84 橙、≤40 红（本原型列表样本取 92 / 88 / 84 / 79 / 71 展示前两档）。
- **交互**：搜索（商户名/在售商品）、品类/位置筛选、信用优先排序、分页；点卡片/「进店」→ `/shops/:id`（S-02 一店一档，⭐白名单可跳）；点商品 → `/market/products/:id`（S-18 商品透明详情，M2 设计先行）。
- **示例文案**：列表页头「共 5 家商户 · 已按信用分排序」；卡片「信用分由平台信用档案计算（脱敏公示）」——不出现“竞价排名”等诱导表述。

### 4.2 加载态

- **呈现**：数据区整区替换为骨架屏（商品卡外形一致，避免切换时跳版）；仅当骨架不可行时用 Spin；顶部工具栏/筛选保持可用外观但请求期间禁用（防重复）。
- **时长策略**：瞬时命中（<300ms）可直出数据不闪骨架；骨架 >10s 或重试超限转入错误态并提示（前端统一超时，见 05 §错误码映射）。
- **无障碍**：骨架区 `aria-busy="true"` + 读屏播报；系统开启「减弱动态效果」时关闭 shimmer（本原型已内置 `prefers-reduced-motion` 处理）。
- **演示方式**：原型中点「刷新」或错误态「重试」，可看到 骨架屏 1.2s → 正常态 的完整过渡。

### 4.3 空状态

- **三类成因与对策**（决定文案主语）：
  1. 筛选条件过窄 / 无搜索结果 → 主操作「清除筛选条件」；
  2. 位置范围未覆盖（超出服务半径）→ 引导放宽位置（附近 3km → 全市）；
  3. 品类暂无商户入驻（供给侧为空）→ 引导「让问一问帮我找」或看红黑榜。
- **插画**：线性插画 + 暖灰（UI 规范 §5），建议随图标集统一建设空态插画库（见 §8）。
- **文案**：标题给结论、副文案给原因和出路，动作给「动词 + 对象」。

### 4.4 错误态

| 错误类别 | 提示文案（示例） | 动作 |
|---|---|---|
| 网络错误（ERR_NETWORK / 弱网） | 「网络开小差了，请检查网络连接后重试」 | 重试 + 反馈入口 |
| 服务错误（5xx / 网关超时） | 「服务开小差了（503），请稍后再试」 | 重试（带退避）+ 反馈 |
| 客户端超时（>10s） | 「响应超时了，网络较慢或服务繁忙，请重试」 | 重试 |
| 限流 / 风控 | 「请求太频繁，请稍后再试」 | 冷却后重试 |
| 无权限（R-03 / RBAC） | 「当前账号无权查看该内容」 | 返回上一页 / 联系平台（**不归入本态**） |

- 重试策略：手动重试即时可点、可重入；自动重试 ≤3 次指数退避，避免放大故障。
- 详情折叠：错误码 / 重试次数 / 耗时折叠展示，用户默认只看人话（透明但不打扰）。

## 6. 复用到全站 98 页的方法

通用骨架（每个数据区域 / 页面照此实现）：

1. **数据区独立组件**：列表/表格/卡片区单独封装，四态由该组件统一承载（loading / empty / error / data 四分支），页面其余部分不受影响。
2. **空态必带引导**：按“为什么空 → 自助动作 → 智能兜底（问一问）→ 关联内容”逐级给出口，禁止只写「暂无数据」。
3. **错误态分类文案**：网络 / 服务 / 超时 / 限流四类（§4.4 表）由统一错误码映射产出文案，页面不自行拼接错误文案。
4. **无权限态独立**：路由守卫层（06 安全）负责，页面内不模拟。

典型页差异速查：

| 页面 | 空态要点 | 错误态要点 |
|---|---|---|
| S-10 我的投诉（M1） | 「还没有提交过投诉」→ [去提交投诉]（≤3 步，D-02） | 进度拉取失败 → 重试 + 提示「进度不会丢，已为您保存」 |
| S-06 扫码验真 / 溯源结果（M1） | 码无效：「未找到该溯源码」→ [扫码重试] [举报可疑商品] | 网络失败 → 重试；结果页保持上一次成功结果 + 顶部「数据可能不是最新」降级提示 |
| M-01 经营工作台（M1） | 今日无待办：「今天没有待办，安心经营」 | 看板数据失败 → 重试 + 保留昨日缓存并标注时间 |
| R-20 存证调取出证（M1） | 无存证记录 → [去生成存证] | 出证服务异常 → 提示重试，**资金/证据类不可静默失败** |

## 8. 落地到前端工程的建议（对齐 05 前端工程约束）

- AntD 映射：骨架屏 `Skeleton`（avatar/title/paragraph 组合）、空态 `Empty`（定制插画 + 动作插槽）、错误态 `Result`（status=warning/error + extra 动作）二次封装进 `packages/ui`，业务页禁用直接深用（03 §1）。
- 文案收敛：四态标题/说明/按钮统一存 i18n/常量表（§5 为 v0.1 基线），状态与颜色由 `packages/ui` 状态徽章统一（03 §3）。
- 错误码映射：前端统一拦截器将后端/网关错误映射为 §4.4 四类 + 页面错误码（对接 PDD §6.2 统一响应），超时/重试在请求层统一处理。
- 测试：每个列表/数据区补「四态渲染」用例（组件测试建议，05 §测试），验收清单可引用本表状态与文案。
- 空态插画库：随图标集一期建设（无结果/无覆盖/无记录/无权限 ≥4 张基础插画），风格 = 线性 + 暖灰 + 蓝橙点缀。

## 9. 自检与待办

- 五词自检（本页）：**方便**（信用/位置一键筛选 + 商品直览）、**安全**（信用分脱敏排序）✅；加载/空/错误态均已给出「用户可理解、可行动」的表达，不背离「惠民/透明/直达」。
- 无障碍走查项：四态键盘可达、焦点管理、`aria-busy`/读屏播报、对比度 ≥4.5:1、`prefers-reduced-motion`。
- 待评审问题（✅ 2026-09-11 已裁决）：
  1. 信用分语义色落到「分数数字」还是「分数 + 分档标签」→ **✅ 已裁决：色 + 分档标签（红榜 ≥85 / 良好 60~84 / 待提升 <60，标签词银发友好）**。
