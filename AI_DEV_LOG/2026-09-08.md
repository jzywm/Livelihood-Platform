### 关键决策与理由
- 原型放 `apps/docs/原型/`(与线框图同级):上游规范与原型同目录便于评审对照;自包含单 HTML(无 CDN/无构建)保证 file:// 直接可开、可随评审分发
- 「四态」口径:仓库 03 §4 的四态 = 加载/空/错误/无权限;按用户表格聚焦前三态+正常态,S-01 全员可见无无权限态 → 说明文档显式注明无权限态口径(03 §4-4 + 06 RBAC)待评审是否纳入样板
- 信用分展示:分数数字按 UI设计规范 §2.5 语义色(≥85 绿/60~84 橙),不另造「红榜/良好」分档词(待评审问题 1);卡片在售商品直览保留「溯源✓/检测✓」徽章还原线框 S-01 的透明表达
- 交互可演示优先:重试/刷新/清除筛选均真实走「骨架屏→正常」过渡,评审可现场验证状态机而非看图说话

### 经验与教训
- **无视觉模型下做 UI 交付物自检 = 无头浏览器 DOM dump + 标记断言**(四态互斥用 `class="view on"`/hidden 判断,不能只看 dump 文本 Contains——display:none 的节仍序列化在 DOM 里,首轮误报「四态内容泄漏」)
- 沙箱限制:受限模式 Chrome 无法建 mojo 命名管道(退出码 -36863)→ headless 截图/dump 需一次 `danger-full-access` 升级;PowerShell 读 UTF-8 文件必须 `-Encoding UTF8`(默认 ANSI 会把中文读成乱码再写出,node --check 误报)
- 高保真原型「演示层与产品层分离」写法可复用:演示工具条独立 CSS 类+注释「交付时移除」,产品页面本体可整段评审
