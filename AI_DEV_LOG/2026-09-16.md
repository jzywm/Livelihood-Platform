- **场景标题写 `#### Scenario: 中文名` 而非 `#### 场景:`**:实验显示后者当前能过,但属**宽松实现而非承诺**;若 OpenSpec 升级收紧即集体失效,故不赌实现细节。

- **不采信子代理自证,也不采信其状态快照**:两个子代理都准确完成了自己的文件,但都基于**过期快照**报告「还有文件未翻译」——**并发写入场景下,复核必须以磁盘当前状态为准**,并自写脚本独立验证。

**关键决策与理由**

- **走 architectural 而非 bounded 路径**:bounded 的判据是"要改的流程已经在仓库里能读到",而 AICORE **零代码**,不存在可读的现成流程;`brainstorming` 技能明示"拿不准时走更重的那条,且棘轮是单向的"。
- **设计文档与 OpenSpec 分工而不合并**:决策与理由的唯一事实源保持 `openspec/.../design.md`,superpowers 设计文档只承载"怎么做、顺序、判据"——避免出现两个都可手改的口径源(这与本仓库既有的"接口唯一可手改源 = openapi.yaml、库表唯一可手改源 = er.md"同一纪律)。
- **成功码取 `0`、限流码取 `2004`**:用户裁决"按接口文档写";`_common/openapi.yaml` L122 已写死 `code === 0` 为前端判断依据,而 `429` 不在码表内——**业务码与 HTTP 状态码必须分开对待**。
- **`X-Internal-Token` 写进接口文档而非只写在代码里**:它是 PROFILE 侧也要遵循的**跨服务契约**,不写进 `openapi.yaml` 的 securityScheme,两个服务的实现必然对不上。
- **三源交叉校验而非两方比对**(第 3 组 3.6):tasks 原文只要求「DDL ↔ `er.md`」,但那样**模型层写错了照样漏检**,而模型才是业务代码真正使用的东西;加模型这一源后可同时抓住"文档改了代码没改""代码改了文档没改""模型与 DDL 走偏"三类。
- **第 1 组写完整步骤级细节、第 2/3 组只写接口+验收**:第 1 组会以真实运行结果校准若干实现细节(`Settings` 实际字段类型、异常处理器与 FastAPI 校验错误的对接方式、structlog 处理链配置),提前写死具体代码会与刚验证过的实现冲突;**该取舍已在计划中显式声明,不以占位符伪装完成**。
- **不引入 `httpx2`**:FastAPI 0.141 / starlette 1.6 的 `TestClient` 会打弃用警告但**实测可用**(非致命)——不为他人的迁移买单,登记为偏差 V2。
- **MySQL 用"直启进程 + 最小权限专用账号"而非继续绕认证**:服务壳提权也打不开,`--skip-grant-tables` 会让 mysqld 崩溃;试 3 个常见开发口令即停并改建专用账号,避免暴力尝试与长期占用 root。

**经验与教训**

- **"装得上"不等于"跑得起来"**:依赖全绿只是前置条件;**真正决定方案可行性的是"这套机制能否检出它该检出的问题"**——所以冒烟测试专门验证了 import-linter 的"故意违规必须变红",而不只是"能导入"。
- **环境类障碍要用对照实验定位,不要靠猜**:本次用 `mode 700` vs `mode 755` 两组写入对照,把"pip 装不上"精确定位到"沙箱禁止写 `0700` 目录 + pip 强制用 `0700` 临时目录",而不是停留在"权限不足"的笼统判断;同时暴露了"`0700` 目录连删都删不掉"的连带影响。
- **文档缺陷多数出在"少写"而非"写错"**:F2(通篇没有成功码)比 F1(写错码值)更危险——**照着一个没写的文档实现,每个人都会按自己的默认值补**,而默认值恰好是错的。审文档时要专门找"本该有却没有"的地方。
- **改文档前必须全量定位,不能只改记得的那几处**:我预估 `429` 有 2 处,实读发现 **7 处**;漏改的部分会留在工件里继续误导后续实现。
- **子模块例外是分层契约最容易写错的地方**:`forbidden_modules` 写父包会**连带禁掉子模块**,而这恰恰与"service 只依赖 Protocol"的设计意图冲突;必须精确列具体实现模块 + `ignore_imports` 放行例外,并**两个方向都验证**(只依赖例外时放行、依赖具体实现时变红)。
- **配置文件的中文契约名会被编码坑**:Windows PowerShell 的 `Set-Content` 按 GBK 落盘,而 `lint-imports` 按 UTF-8 读 ⇒ **中文契约名必须用能指定编码的方式写文件**(Python `write_text(encoding='utf-8')`)。
- **误判也要先读文件核实再动手**:我一度以为编辑把段落写重复了,读完文件才确认是正确的;若按误判回改,会把正确内容改坏。
- **环境探测要适可而止**:试 root 口令到第 3 个命中即停并转建专用账号——**探测的目的是拿到可用条件,不是穷尽可能性**。
