- 环境:DSH 检出位于 `D:\soft\deepseekharness\deepseek-harness`(在工作区 `D:\progrom` 之外,写操作需 `danger-full-access` 升级批准)

### 过程记录

#### 1. 需求/问题 → 2. 方案/动作 → 3. 产出物 → 4. 验证

- **需求**:用户「帮我想一个方案,在大型项目中实现更好管理 deepseek harness 的上下文,让工具更准找到目标文件和目录,并尽量修改文件内容而不是新建文件」
- **调研现状**(读 `packages/core/system-prompt`、`packages/fs/*`、`packages/context/agent-instructions`、`packages/compaction/*`、`packages/workspace`、`packages/lsp`):三个痛点对应缺口 = 上下文只「压缩」不「挑相关性」;文件发现只有运行时 `glob`/`grep`、`listDir` 存在但不对模型暴露;`fs-observation-policy` 只拦「没读就 edit」、无「已存在却 write 覆盖」拦截、提示词无「优先 edit」显式要求
- **方案**:按 memory 规则给 4 方案(A 轻量指令+政策 / B 标准 项目地图+目录列表+edit 指导 ⭐ / C 进阶 符号索引 / D 重量 上下文编排)→ 用户选 **方案 B + A 的 edit 指导**;再给详细实施步骤 → 按 **D1 → D2 → D3** 实现
- **产出物**(均在 DSH 检出内):
  - **D1** `packages/fs/tool-fs/src/write.ts`(write 指导文案强化)、`read.ts`(read 指导加「先 glob/grep/list_dir 定位再 read」)
  - **D2** `packages/fs/tool-fs/src/list-dir.ts`(新增 `list_dir` 工具)+ `index.ts`(注册 + 配置 `listDirMaxDepth`/`listDirMaxEntries`)
  - **D3** `packages/context/project-map/`(新包:`src/config.ts`、`src/map.ts`、`src/index.ts`、`package.json`、`tsconfig.json`、`README.md`/`.zh.md`)
  - 集成:`tsconfig.host.json` 注册 `project-map` 到构建图;`tool-fs` 双语 README 整份重写(D1+D2 文档)
- **验证**:`pnpm exec tsc -b packages/context/project-map/tsconfig.json packages/fs/tool-fs/tsconfig.json` → 首跑报 1 错(`Agent` 导入未使用),移除后复跑 **exit 0 通过**

### 关键决策与理由

- **选方案 B**:性价比最高,直接命中「找文件/目录」最痛点;「优先 edit 而非 write」指导正交且近乎免费,一并做掉。方案 C/D 作为后续迭代按仓库规模再加
- **`list_dir` 落 `tool-fs` 而非 `tool-fs-search`**:`tool-fs` 注入 `ctx.fs`,`listDir` 就在该 seam 上;`tool-fs-search` 故意不注入 fs、只走 ripgrep 二进制
- **`project-map` 用 `snapshot` 形式(而非自定义 source kind)**:`MessageSourceMap` 是 merge-extensible,但通用 `{ kind: 'plugin', plugin, form: 'snapshot', sections }` 已内置「后出取代先出」语义,避免声明合并复杂度
- **新包注册**:`tsconfig.base.json` 通配符 `@deepseek-ai/dsh-*` → `packages/context/*/src` 自动解析(注释明确「同组加包无需改此文件」),但 `tsconfig.host.json` 的 project references 需手动加一行

### 经验与教训

- **fs 契约无 mtime**:`FsInfo`/`FsDirEntry` 只有 `version`/`size`,无修改时间 → 地图的「最近改动热点」不可用 mtime,改为省略或本会话 touch 顺序;「最近」类问题仍归 `glob`(`--sort=modified`)
- **`exactOptionalPropertyTypes: true`**:可选 `signal` 参数传给 `fs.resolve` 要条件展开 `{ ...signal !== undefined ? { signal } : {} }`,否则显式 `undefined` 报类型错
- **DSH 检出在沙箱外**:每处 `D:\soft` 写都要 `danger-full-access` 升级弹窗;改用「整文件重写」合并多处小改,减少批准次数

### 下一步

1. 补测试门禁:`test:snapshot`(新增 `list_dir` 工具 schema/结果 与 `project-map` 注入的快照)、包内单测(100% coverage gate)、非平凡变更补 Agent Note
2. 可选后续:方案 C(基于 `lsp` 的符号索引)/ 方案 D(上下文相关性编排)按大仓库规模再加
3. 挂载验证:在真实 cordis.yml 里加载 `project-map` + `list_dir`,确认地图注入与触碰刷新行为
